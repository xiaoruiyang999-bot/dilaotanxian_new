# v0.5.4.1 正式计划：怪物多招式攻击系统

> **版本说明**：v0.5.4（完整楼层循环）的前置子版本。本版本聚焦于让敌人战斗有**招式多样性**——同一个敌人可以根据距离/概率使用不同招式，而非只会走上来平A。
> **前置版本**：v0.5.3（房间类型系统，代码完成，待人工验收）
> **状态**：📋 计划阶段

## 版本信息
- **版本号**：v0.5.4.1
- **版本名称**：怪物多招式攻击系统（AttackData 数组 + 招式选择策略）
- **前置版本**：v0.5.3（房间类型系统）
- **依据**：《v0.5 Dungeon 系统开发计划书》+ 用户需求（怪物战斗逻辑差异化）
- **目标**：让敌人支持配置多份 AttackData，按策略选择不同招式，实现战斗行为差异化
- **约束**：
  1. 不碰 Player/PlayerCombat/WeaponHitbox/IDamageable 任何现有逻辑
  2. 攻击3阶段状态机（Windup→Active→Recovery）**结构不变**
  3. 改内容（配多份 AttackData + 调策略参数）只改 SO/Inspector，不改代码
  4. 现有敌人行为零回归——默认配单份 AttackData 时与现在完全一致
  5. 程序员美术：新招式 = 换 AttackData 数值 + 换预警指示器颜色/大小，无需新美术资产

## 一、现状分析

### 1.1 当前 `EnemyCombat` 的招式限制

```csharp
// EnemyCombat.cs 当前：只支持单份 AttackData
[SerializeField] private AttackData attackData;  // 只有 1 个
```

**后果**：所有普通敌人 = 同一套参数（0.25s 前摇 / 1.5 范围 / 120° 扇形 / 伤 1），精英/Boss 只是换了数值的单份 AttackData。战斗体验是"走到脸上丢骰子"，没有招式感。

### 1.2 可复用资产（本版本不动的部分）

| 资产 | 复用方式 |
|------|----------|
| `AttackData` SO 结构 | 不改字段，只新增 minDistance/maxDistance |
| 攻击3阶段状态机 | `EnterWindup → EnterActive → EnterRecovery → EndAttack` 流程完全不动 |
| `WeaponHitbox` | 伤害检测层零改动，`SetAttackData()` 运行时切换即生效 |
| `WeaponController` | 武器视觉 `RefreshWeaponVisual()` 已有，加 `SetAttackData()` 运行时切换 |
| `WeaponAnimator` | 动画层零改动，参数全由 AttackData 驱动 |
| `AttackIndicator` | 预警指示器零改动，参数全由 AttackData 驱动 |
| `EnemyAI` 4状态 FSM | 攻击决策零改动——"进范围→开打"逻辑不变，招式选择在 `EnemyCombat` 内部 |

### 1.3 关键工程事实

| 事实 | 影响 |
|------|------|
| `WeaponController.OnValidate()` 在编辑器期按 `attackData.attackRange` 同步武器视觉长度 | 多招切换必须在**运行时**调用 `SetAttackData()` + `RefreshWeaponVisual()`，不能依赖 OnValidate |
| `WeaponHitbox.attackData` 引用决定了伤害结算的 damage/targetLayer | 必须在 `EnterActive → BeginSwing()` 之前完成 AttackData 切换 |
| 攻击3阶段的每个阶段（Windup/Active/Recovery）都**直接读 `attackData` 字段** | 用中间变量 `currentAttackData` 指向已选中的那份 SO，各处改读 `currentAttackData.XXX` |
| `Enemy.prefab` 中 `attackData` 被 **5 个组件引用** | `EnemyCombat`（决策+执行）/ `EnemyAI`（读 attackData）/ `WeaponController`（视觉同步+角度计算）/ `WeaponHitbox`（伤害结算）——多招切换后 `WeaponController` 和 `WeaponHitbox` 都需要同步切换 |
| AttackData 的 `targetLayer` 每份不同（如 Boss 横扫=129 Default+Obstacle） | 多招共享同一 targetLayer？不一定——可能远程招打 Enemy+Default、近战招打 Default+Obstacle。需保留差异 |

## 二、目标架构

### 2.1 招式选择流程

```
EnemyCombat.TryStartAttack(target)
  │
  ├─ 1. 按策略从 attackDataSet[] 中选一份 AttackData
  │     策略枚举：
  │     · Random       – 完全随机（默认）
  │     · Distance     – 按目标距离选（minDistance~maxDistance 区间匹配）
  │     · Sequence     – 按数组顺序轮换
  │     · Weighted     – 每份有 weight，按权重随机
  │
  ├─ 2. currentAttackData = 选中的那份
  │
  ├─ 3. 同步到 WeaponController.SetAttackData(currentAttackData)
  │     → 自动 RefreshWeaponVisual（武器长度/宽度匹配新招）
  │
  ├─ 4. 同步到 WeaponHitbox.SetAttackData(currentAttackData)
  │     → BeginSwing 时使用正确的 damage/targetLayer
  │
  └─ 5. 走现有 3 阶段流程（所有阶段内读 currentAttackData 而非 attackData）
        Windup  → 设置指示器形状/预警色（currentAttackData 驱动）
        Active  → 武器动画/检测（currentAttackData 驱动）
        Recovery
```

### 2.2 数据模型变更

```
AttackData（ScriptableObject）新增字段：
  · minDistance / maxDistance — Distance 策略用（0~0 = 无距离限制，适用于所有策略）
  · weight — Weighted 策略用（0 = 不会被权重随机选中）
```

### 2.3 EnemyCombat 变更

```
旧：private AttackData attackData;             // 单份
新：private AttackData[] attackDataSet;        // 多招数组
    + public AttackSelectionMode selectionMode; // 选择策略枚举
    + private AttackData currentAttackData;     // 本轮选中的那份
    + private int sequenceIndex;                // Sequence 策略的轮换指针

所有阶段方法改读 currentAttackData 而非 attackData。
```

## 三、修改文件清单

### 3.1 `Assets/Scripts/now_use/AttackData.cs`（+3 字段）

```csharp
[Header("招式选择（v0.5.4.1）")]
[Tooltip("Distance 策略：目标在此距离范围内可选用此招（0~0 = 不限距离）")]
[SerializeField] private Vector2 distanceRange = Vector2.zero;  // x=min, y=max

[Tooltip("Weighted 策略：此招式的权重（0 = 不会被权重随机选中）")]
[SerializeField] private int weight = 1;
```

### 3.2 `Assets/Scripts/now_use/EnemyCombat.cs`（核心改造）

- `AttackData attackData` → `AttackData[] attackDataSet` + `currentAttackData`
- 新增 `AttackSelectionMode` 枚举：Random / Distance / Sequence / Weighted
- 新增 `PickAttack(Transform target)` 策略选择方法
- 所有阶段方法（`EnterWindup/UpdateWindup/EnterActive/UpdateActive/EnterRecovery/UpdateRecovery/EndAttack`）从读 `attackData` 改为读 `currentAttackData`
- `IsInAttackRange` 改为取所有招式中最远的那份范围

### 3.3 `Assets/Scripts/now_use/WeaponController.cs`（+1 方法）

```csharp
/// <summary>运行时切换攻击配置。多招系统在 EnterWindup 后调用。</summary>
public void SetAttackData(AttackData data)
{
    attackData = data;
    RefreshWeaponVisual();
}
```

### 3.4 `Assets/Scripts/now_use/WeaponHitbox.cs`（已存在 `SetAttackData`，无需改）

当前 `SetAttackData(AttackData data)` 已存在，直接复用。

## 七、风险与注意事项

| 风险 | 影响 | 应对 |
|------|------|------|
| AttackData 数组为空或全 null | TryStartAttack 失败无提示 | PickAttack 加空守卫，返回 null 时 TryStartAttack 静默拒绝 + LogWarning 一次 |
| IsInAttackRange 按最远招式判定 | 敌人用短招时可能"够不着" | 接受为合理行为——AI 进范围才开打，具体用哪招再判定，短招失败则本回合不攻击（实际短招 minDistance=0 不会失败） |
| 招式选择使用房间子 seed 还是 Unity 随机 | 与布局可复现性关系 | 招式选择用**战斗专用子 seed**或直接 `System.Random` 派生，确保同 seed 战斗可复现 |
| 多招切换后 WeaponHitbox.targetLayer 不匹配 | 伤害误判 | 每份 AttackData 独立 targetLayer；BeginSwing 前 `SetAttackData` 已同步到 WeaponHitbox → 天然正确 |
| 旧 prefab 的序列化 `attackData` 字段改名 | 丢失引用 | 保留 `attackData` 字段名不变（向前兼容），新增 `attackDataSet` 数组并行；当数组非空时用数组，数组空时回退用 `attackData` |
