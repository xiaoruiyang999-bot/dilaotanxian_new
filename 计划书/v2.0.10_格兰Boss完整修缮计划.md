# v2.0.10 失落守门人·格兰 Boss 完整修缮计划

> 状态：待实施  
> 适用基线：Unity 6、URP 2D、Input System、DOTween、当前 V2 横向房间制 Roguelite  
> 玩法真源：《无名之地_完整游戏开发文档_V2.md》与《v2.0.10_失落守门人格兰_地形联动Boss招式计划.md》  
> 目标：将当前“可编译的模块骨架”修缮为可完整游玩、可反复重开、可测试、可接正式美术的双阶段 Vertical Slice Boss。

## 一、结论与范围

当前格兰综合完成度约 40%。一阶段具备基本循环，二阶段已有脚本骨架，但正式 Prefab、Layer、Boss 房场地、石柱、预警、动作选择和生命周期尚未形成可靠闭环。

本计划完成后，格兰必须达到以下结果：

1. 第一阶段通过双爪连击、三重跃击、落空眩晕教授绕侧、锁点躲避与输出窗口。
2. 55% 生命附近只触发一次临界狼嚎，并进入四段压迫节奏。
3. 50% 生命时安全切换为四足形态，不残留一阶段动作和判定。
4. 第二阶段只交替使用裂柱奔袭与残月围猎，不再调用一阶段爪击或跃击。
5. 四根石柱具有 Intact、Cracked、Collapsed 三态，并真实改变奔袭、月痕和安全区。
6. Boss 死亡、房间卸载、重开、玩家死亡重生时，不残留协程、Hitbox、预警、月痕、Tween 或场地状态。
7. 没有正式动画和 VFX 时也能用灰盒完整打通；接入正式美术时不修改伤害与判定规则。

### 1.1 本轮包含

- 格兰唯一行为状态机修正。
- 一阶段招式补全。
- 临界狼嚎与阶段转换补全。
- 四足追猎移动。
- 裂柱奔袭与残月围猎完整实现。
- 正式 Boss 房、四柱和 BossArenaState 接线。
- 预警、月痕、震荡波的世界空间池化。
- Prefab、Layer、AttackData/配置资产正式化。
- EditMode、PlayMode、性能与人工手感验收。
- Animator、VFX、SFX 接入合同与缺失素材清单。

### 1.2 本轮不包含

- 新增第三阶段或更多招式。
- 为格兰建立通用到所有 Boss 的大型框架。
- 继续扩建 FrameAnimator、WeaponPivot 或旧随机攻击池。
- 在机制闭环前制作大量最终动画或先做数值平衡。
- 将 Boss 攻击逻辑写进动画 Clip 或 Animation Event。

## 二、当前已确认的问题

### P0：会让战斗流程失效的问题

1. `GrandBossBrain` 在进入 `ChargeAttack` 时先覆盖 `lastAttackState`，导致二阶段选择器持续偏向 `MoonHunt`，裂柱奔袭无法正常交替执行。
2. `LayerMask.GetMask("Player")` 当前返回 0；工程没有 Player Layer。墙体又使用 Default，而正式墙体/障碍使用 Obstacle，二阶段命中链不可信。
3. 正式 `Enemy_Boss.prefab` 尚未包含 `GrandChargeAttack` 与 `GrandMoonHunt`；运行时 AddComponent 不能替代正式 Prefab 接线。
4. 正式仪式厅只生成柱视觉和 RoomPlan 障碍，没有向 `BossArenaState` 注册四根柱。
5. `EnsureOn` 找不到 Arena 时会创建一个脱离房间的空 `BossArenaState`，使石柱联动静默失效。
6. 撞击开裂石柱时虽然进入 `Stunned`，但立即被 `FinishAction` 重置；`crackedPillarStun` 没有实际等待。
7. 圆形预警、直线预警和月痕被挂在 Boss Transform 下，会随格兰移动，违反锁点后固定规则。
8. Brain 中断时没有显式取消 `GrandChargeAttack` 与 `GrandMoonHunt`，死亡或切阶段可能残留月痕和模块状态。

### P1：机制与设计不一致的问题

1. 三重跃击的外围震荡波只是瞬时大圆判定，没有扩散过程，也没有完整石柱遮挡。
2. 第三跳没有更明显的终结预警；升空月影、空中受击规则尚未确定并实现。
3. 临界四连只重复右爪/左爪两个 AttackData，没有独立的上挑和双爪下砸判定。
4. 临界狼嚎没有抗控制窗口、月环亮起和安全动作切入点。
5. 二阶段移动仍是直线加速接近，没有限速转向、侧跳、绕侧、拉距和合法起跑点选择。
6. 残月围猎从固定角点开始，可能横穿场地；扑击由逐帧随机决定，不能保证发生。
7. 月痕只在柱附近少生成一个点，并非真正的“柱后安全缺口”。
8. 所有柱倒塌后没有强制保留入口侧或中央安全路线。
9. 正式 Boss 房仍保留旧南入口合同，与当前 V2 默认左入右出不一致。

### P2：质量与维护问题

1. 预警频繁创建/销毁 GameObject、Mesh 和协程；围猎每次创建临时 List 并排序，不符合热区零 GC 目标。
2. 高速奔袭只在当前位置做 OverlapCircle，存在高速穿透风险。
3. `FindAnyObjectByType<Room>()`、隐式父级查找和运行时补组件造成隐藏初始化顺序。
4. 场地 Reset 没有恢复开裂后的颜色/材质，也没有完整事件通知。
5. 二阶段没有专项自动测试，现有测试只覆盖枚举、阈值、基础资产和一阶段部分分支。
6. ArtAdapter 仍以变色为主，正式动画、VFX、SFX、镜头与命中反馈均未接入。

## 三、目标架构

### 3.1 项目等级

格兰属于 Vertical Slice 的长期维护内容，不按一次性原型处理；但只建立格兰所需的最小架构，不创建万能 Boss 框架。

### 3.2 推荐模块

| 模块 | 唯一职责 |
|---|---|
| `GrandBossEncounterContext` | Boss 房组合根；持有 Room、RoomBounds、WorldHazardRoot、BossArenaState 与配置引用 |
| `GrandBossBrain` | 唯一决策者；阶段、状态、动作排序、中断、恢复和死亡 |
| `GrandBasicCombo` / `GrandTripleLeap` | 一阶段动作执行器，只执行命令并返回结果 |
| `GrandChargeAttack` / `GrandMoonHunt` | 二阶段动作执行器，只执行命令并返回结果 |
| `BossArenaState` | 四柱三态、碎石区、安全走廊和重开复位的唯一运行真值 |
| `BossTelegraphController` | 从房间级对象池获取并控制圆、线、环和月痕预警 |
| `GrandBossPresentation` | Animator、Sprite、VFX、SFX、镜头和反馈；不拥有伤害真值 |

`BossPhaseController` 继续监听生命变化，但只能向 Brain 发送 `RequestPhaseWarning` 和 `RequestPhaseTwo`，不得自行切攻击池或启动攻击。

### 3.3 场景与初始化

采用显式组合顺序，禁止依赖 Awake 偶然顺序：

```text
BossRitualRoom 构建完成
→ 创建 GrandBossEncounterContext
→ 创建 BossArenaState 和 WorldHazardRoot
→ 生成并注册四根 PillarRuntime
→ EnemySpawner 实例化 Enemy_Boss
→ GrandBossEncounterInstaller.Initialize(boss, context, config)
→ 所有模块 Init
→ Brain 最后 Enable/StartEncounter
```

规则：

- `EnsureOn` 只保留旧入口兼容，不再创建脱离房间的 Arena。
- 正式流程缺少 EncounterContext 时必须明确报错并禁用 Boss Brain，禁止静默创建空场地继续运行。
- Boss 本地模块正式写入 `Enemy_Boss.prefab`；房间级对象写入房间运行根。
- 只有一个 Brain 可以启动动作；其他模块不得自行 StartCoroutine 发起新招式。

### 3.4 数据归属

| 数据 | 归属 |
|---|---|
| 单次攻击前摇、有效、收招、几何、伤害、位移、反馈键 | `AttackData`，作为当前 AttackDefinition 同源实现 |
| 连击顺序、跃击次数、间隔、眩晕、奔袭次数、月痕数量 | `GrandBossConfig` ScriptableObject |
| 55%/50% 阈值、阶段移速、转向速度、抗控时长 | `GrandBossConfig` |
| 当前阶段、当前动作、冷却、已命中、柱状态 | 运行时对象，不写回 ScriptableObject |
| 动作选择、交替、阶段请求优先级 | 纯 C# `GrandBossDecisionPolicy` |
| 围猎路径和安全走廊计算 | 纯 C# `GrandArenaPathPlanner` |

短期不强行重命名整个项目的 `AttackData`。格兰修缮中必须遵守“预警、动画窗口、Hitbox、伤害、位移与反馈消费同一攻击定义”，不得在执行器里复制另一套伤害真值。

### 3.5 通信规则

- Brain → 动作模块：直接引用和明确的 `Execute(context)` 命令。
- 动作模块 → Brain：返回 `GrandActionResult`，不直接选择下一状态。
- Arena → 表现：状态变化事件，如 `OnPillarStateChanged`。
- 逻辑 → Presentation：只发状态和表现事件，不把伤害计算交给动画。
- 房间 → Boss：通过 `GrandBossEncounterContext` 显式注入，不使用全局 Find。

建议结果类型：

```csharp
public enum GrandActionEndReason
{
    Completed,
    HitPlayer,
    HitIntactPillar,
    HitCrackedPillar,
    HitWall,
    AllMissed,
    Interrupted,
    Dead
}
```

## 四、关键技术方案

### 4.1 状态机与动作所有权

- Brain 始终只持有一个 `activeRoutine` 和一个 `activeAction`。
- `EnterState` 不得在写入 lastAction 前查询“下一招”；先决策，再记录已执行动作。
- 二阶段使用显式交替序列 `Charge → MoonHunt → Charge`，不依赖易错的状态反推。
- 阶段命令使用待处理请求：`None / Warning / PhaseTwo / Death`。
- 死亡优先级最高；PhaseTwo 高于 Warning；阶段请求只在动作安全点消费。
- 三重跃击原则上完成本整套后再响应 Warning；若死亡或房间卸载则立即中断。
- 所有 Wait 使用可取消循环或统一动作时钟，避免不可中断的长 `WaitForSeconds`。

### 4.2 物理与 Layer

计划新增并统一：

- `PlayerHurtbox`：玩家受击区域。
- `Enemy`：格兰身体。
- `Obstacle`：实体墙与不可穿越障碍。
- `BossPillar`：站立石柱实体。
- `BossRubble`：倒塌碎石 Trigger，只参与减速查询。

注意事项：

- Layer 名必须在 ProjectSettings 中真实存在后再生成 Mask；不得依赖不存在名称返回 0。
- 玩家 Hurtbox、Movement Collider、攻击 Hitbox 分离；格兰身体冲撞不能通过武器 Sprite 大小推断。
- Trigger 只参与受击/碎石等逻辑；墙体检测必须跳过 Trigger。
- 高频查询使用 NonAlloc API 和复用缓冲。
- 奔袭使用 `Rigidbody2D.Cast` 或等价的扫掠检测，覆盖本 FixedUpdate 的完整位移，避免高速穿透。
- 位移和物理判定在 FixedUpdate 节奏执行；表现插值可以在 Update/LateUpdate 完成。

### 4.3 世界空间预警与对象池

建立房间级 `WorldHazardRoot`，预警和月痕均挂在此节点，不挂在 Boss 下。

对象池至少包含：

- CircleTelegraph
- LineTelegraph
- ShockwaveRing
- MoonMark
- RubbleVisual

规则：

- 预警实例获取后写入世界坐标；锁定后不再跟随玩家或 Boss。
- `HideAll(ownerToken)` 只回收当前动作拥有的预警，避免一个动作误删另一个系统的表现。
- 池在房间卸载时整体回收；预热数量按最大并发确定。
- 禁止每次跃击创建新 Mesh、Material、Sprite 或临时 List。
- 预警和实际判定共享相同的位置、方向、半径和长度快照。

### 4.4 三重跃击

单跳流程：

```text
前摇压低身体
→ 记录玩家位置
→ 生成固定圆形预警与地面月影
→ 进入 Airborne
→ 移动至锁定点
→ 中心坠落判定
→ 启动扩散震荡环
→ 固定间隔
```

技术细节：

- 中心判定和震荡波分别结算，并在单次落地内去重。
- 震荡波采用扩张环：查询外圆后按距离过滤内圆，形成 annulus，而不是瞬时大圆。
- 对候选玩家从落点做 NonAlloc 线段遮挡；先命中站立 `BossPillar` 时，震荡伤害被截断。
- 第三跳使用不同预警颜色/脉冲频率，但判定仍读取同一落点快照。
- 明确 Airborne 规则：建议可受伤、免疫地面位移控制、关闭普通移动，不完全无敌。
- 任意一次中心命中只记录一次追击标记；仍完成三跳。
- 全部中心落空后进入 6～7 秒真实 Stunned；状态期间禁移动、转向与攻击。

### 4.5 双爪与临界四连

正式攻击资产：

1. `GrandRightClaw`
2. `GrandLeftClaw`
3. `GrandRightUppercut`
4. `GrandDoubleClawSlam`

每个资产独立配置前摇、判定形状、有效时间、收招、最大转向与反馈键。四连不得复用左右横扫伪装后两击。

普通循环：右爪 → 约 1 秒节奏 → 左爪有限转向 → 收招 → 后退。

临界循环：右横扫 → 左横扫 → 右上挑 → 双爪下砸 → 明显收招 → 继续靠近，不后退。

### 4.6 临界狼嚎与阶段转换

- 55% 窗口只请求一次 Warning。
- 狼嚎在安全动作点开始；停止移动和普通攻击。
- 狼嚎期间短时免疫新硬控或缩短硬控，不使用完全无敌。
- 月环逐段亮起属于 Presentation；逻辑只维护 Warning 状态和抗控窗口。
- 50% 时请求 PhaseTwo；清理一阶段 Hitbox、预警、冷却和连击序号。
- 切换四足移动参数与 Animator 状态。
- 若需改 Collider 尺寸，先检测目标 Collider 空间是否与玩家/墙重叠；不允许在玩家体内直接扩大。
- 阶段动画结束后才启用二阶段动作决策。

### 4.7 四足移动

四足移动不是一阶段速度乘法，包含四个低伤害/无伤害行为：

- Chase：有限转向追踪。
- Orbit：围绕玩家侧向移动。
- Reposition：寻找合法起跑点。
- SideHop：短侧跳调整角度。

纯 C# 决策输入：玩家位置、Boss 位置、朝向、RoomBounds、柱状态、最近实体墙距离、上一招。

输出：期望方向、目标点、移动模式或可释放招式。MonoBehaviour 只负责用 Rigidbody2D 执行结果。

禁止：瞬间反向、穿墙选点、进入玩家身体、在距离不足时强行奔袭。

### 4.8 裂柱奔袭

流程：

```text
蓄力并跟随朝向
→ 直线预警实时更新
→ 咆哮锁定方向和终点
→ 固定方向扫掠移动
→ 返回明确撞击结果
→ Brain 决定恢复、继续冲锋或眩晕
```

结果合同：

| 结果 | 行为 |
|---|---|
| HitPlayer | 造成一次身体伤害与受控推开，结束连冲，短恢复 |
| HitIntactPillar | Intact→Cracked，短失衡，结束连冲 |
| HitCrackedPillar | Cracked→Collapsed，真实长眩晕，结束连冲 |
| HitWall | 快速翻身恢复，可结束本轮或按配置继续 |
| Missed | 未满三次则侧跳、重新显示预警并锁定；第三次后中等喘息 |
| Interrupted | 关闭身体攻击判定并回收预警 |

注意：每段奔袭只能对玩家造成一次伤害；扫掠检测必须区分 PlayerHurtbox、BossPillar、Obstacle 和 Trigger。

### 4.9 石柱与碎石

`BossArenaState` 是柱状态唯一真值，`PillarRuntime` 只负责场景引用：

- Id
- Center
- State
- SolidCollider
- Intact/Cracked/Collapsed Visual
- RubbleTrigger

状态变化：

```text
Intact --BossImpact--> Cracked --BossImpact--> Collapsed
```

- 玩家普通攻击不能改变柱状态。
- Intact/Cracked 保持实体碰撞；Collapsed 关闭高柱 Collider 并开启碎石 Trigger。
- `ResetAll` 必须恢复 Collider、Visual、Tint、Rubble 和事件状态。
- 正式 Boss 房构建时从 RoomPlan 的四个 PillarCenters 一次性注册。
- 房间卸载时清理所有动态碎石表现，不把状态泄漏到下一场战斗。

### 4.10 残月围猎

路径算法必须可重复验证：

1. 从 RoomBounds 内缩得到外围合法矩形或折线路径。
2. 选择离 Boss 最近的外围入口点，禁止从固定角点开始横穿场地。
3. 顺/逆时针选择在动作开始时确定。
4. 按累计世界距离生成月痕，不按帧概率生成。
5. 在固定进度区间锁定一次扑击，例如路径完成 55%～70%，禁止逐帧随机导致不扑击。
6. 扑击锁定后方向不再追踪玩家。
7. 月痕按 Sequence 依次预警和爆发，结束后全部回池。

石柱规则：

- Intact/Cracked 柱沿路径产生固定长度的“月痕阴影缺口”。
- Collapsed 柱不阻断月痕，但其碎石降低格兰速度并延长扑击可读时间。
- 所有柱倒塌时，由 PathPlanner 强制保留法阵中心或入口侧安全走廊；月痕不得覆盖该保底走廊。
- 月痕与扑击使用不同颜色、轮廓和音效。

## 五、正式房间与 V2 方向合同

当前固定仪式厅仍带旧南入口合同。格兰最终验收前必须完成 V2 横向版本：

- 实际房间左入右出，不创建上门/下门。
- 房间位置可以由 DAG 随机，房内布局不随机。
- 四柱、法阵、祭坛、Boss 出生点和奖励点保持手工确定性布局。
- RoomPlan 先验证入口到出口按玩家碰撞体口径可达，再一次绘制。
- 四柱可倒塌后仍必须保留至少一条合法移动通道。
- Camera Bounds 覆盖完整奔袭与围猎空间，震屏不能露出地图外。

旧南入口模板保留为兼容实现，不继续扩建；新格兰机制只以 V2 横向 Boss 房为正式验收入口。

## 六、Animator、VFX、音频与反馈

### 6.1 Animator 技术

- 新表现统一使用 Unity Animation/Animator。
- 使用一个格兰 Animator Controller，按双足/四足建立两个子状态组；不继续使用 FrameAnimator。
- Animation Event 或 StateMachineBehaviour 只能通知 AttackStart、HitboxOpen、HitboxClose、AttackEnd 等窗口，不能直接算伤害。
- 逻辑状态与 Animator 参数映射集中在 `GrandBossPresentation`。
- 动画缺失时使用灰盒 Clip 或占位姿态，保证逻辑仍可运行。

建议最小动画清单：

- 双足 Idle、Walk、右爪、左爪、上挑、双爪砸地。
- LeapWindup、LeapAir、LeapLand、Howl、CriticalRecover。
- PhaseTransition。
- 四足 Idle、Run、Orbit/SideHop。
- ChargeWindup、ChargeLoop、HitWall、HitPillar、Stunned。
- MoonHuntRun、Pounce、Recover、Death。

### 6.2 VFX/SFX

- 起跳尘土、落地中心冲击、扩张震荡环。
- 第三跳强化月环。
- 狼嚎月环逐段点亮。
- 奔袭抓痕、速度拖影、撞墙尘土、撞柱碎裂。
- 月痕预警、依序爆发、柱后安全缺口表现。
- 眩晕月环熄灭、恢复重新点亮。
- 爪击、重击、撞柱和扑击使用不同音色。
- 同帧多命中音效限流；停帧、震屏和闪白互斥并绑定生命周期。

表现不能改变判定范围；可见像素和伤害 Hitbox 必须通过调试 Gizmo 对照验证。

## 七、分批实施顺序

每批都必须保持项目可编译、可进入现有入口，并拥有独立退出条件。

### 批次 0：冻结基线与测试护栏

任务：

- 保存用户场景后运行当前全量 EditMode 测试。
- 为 P0 缺陷添加失败测试：二阶段交替、Layer 校验、裂柱眩晕时长、模块清理。
- 为 `GrandBossConfig`、DecisionPolicy 和 PathPlanner 建立测试目录。
- 记录 Enemy_Boss Prefab 当前组件和正式 Boss 房当前层级。

退出条件：测试能够稳定复现当前二阶段错误；不修改玩法结果。

### 批次 1：修通唯一行为链与生命周期

任务：

- 修复二阶段动作交替和 lastAction 写入顺序。
- 引入统一 `GrandActionResult`。
- Brain 显式取消 Combo、Leap、Charge、MoonHunt、Combat 和 Telegraph。
- 补齐 Death、Disable、RoomUnload、Respawn、PhaseTransition 清理。
- 去除空 Arena 静默创建；缺上下文时 fail-fast。
- Prefab 正式加入所有 Boss 本地模块。

退出条件：同一时刻只有一个动作；死亡/中断后所有模块与预警归零。

### 批次 2：正式房间、Layer 与四柱闭环

任务：

- 建立/确认 PlayerHurtbox、BossPillar、BossRubble Layer。
- 创建 `GrandBossEncounterContext` 和房间级 WorldHazardRoot。
- BossRitualRoomDecorator 创建 PillarRuntime 并注册四柱。
- 完成三态视觉、Collider 和 RubbleTrigger 切换。
- ResetAll 与 Boss 重开/房间卸载对接。
- 开始迁移 V2 左入右出固定 Boss 房。

退出条件：四柱可连续撞击、倒塌、减速并在重开后完整复位。

### 批次 3：一阶段完整化

任务：

- 新增上挑和双爪下砸 AttackData。
- 完成三重跃击扩张震荡波、柱后遮挡、第三跳强化预警。
- 实现 Airborne 规则、中心/外围判定去重。
- 狼嚎安全切入、抗控窗口和临界四连。
- 补齐一阶段 PlayMode 测试。

退出条件：普通循环、命中追击、全空眩晕、临界狂躁四条路径均可稳定复现。

### 批次 4：二阶段完整化

任务：

- 实现四足 Chase、Orbit、Reposition、SideHop 与转向限制。
- 奔袭改为 FixedUpdate 扫掠检测并完成所有结果分支。
- 围猎路径改为最近外围入口和确定性扑击时点。
- 月痕对象池、顺序爆发、柱后缺口和全倒塌安全走廊。
- 保证 Charge/MoonHunt 严格交替。

退出条件：二阶段不调用一阶段招式；两招均可被玩家读懂并利用场地反制。

### 批次 5：表现接入

任务：

- 建立 Animator Controller、参数与灰盒 Clip。
- 接入正式 Sprite/Clip 时使用同一状态合同。
- 接入落地、狼嚎、奔袭、撞柱、月痕、眩晕 VFX/SFX。
- 增加有限的 HitStop、Camera Shake 和命中闪白。
- 使用 Gizmo 对齐动画与 Hitbox。

退出条件：关闭调试图形后，玩家仍能仅凭动画、地面预警和声音判断攻击阶段与安全方向。

### 批次 6：数值、性能与 Vertical Slice 验收

任务：

- Profiler 检查攻击热区 GC、物理耗时和对象数量。
- 调整前摇、有效、收招、伤害、眩晕和安全窗口。
- 用至少三种狼人 Build 验证伤害闭环，不为某一 Build 单独硬改 Boss。
- 验证死亡 30%、撤离 60%、击败 Boss 100% 星蓝币结算链。
- 完成重开、房间卸载、连续三局和低帧率测试。
- 形成 v2.0.10 实施记录并更新路线图摘要。

退出条件：满足本文第十一节 Definition of Done。

## 八、测试计划

### 8.1 应抽离为纯 C# 的逻辑

- 阶段阈值和阶段请求优先级。

- Animator、SpriteRenderer、Particle、Audio、Camera。
- Prefab/房间实例化与对象池 GameObject 生命周期。

### 8.3 EditMode 测试

- 状态枚举与合法转换表。
- 55% Warning、50% PhaseTwo 只触发一次。
- PhaseTwo 永不选择 P1 动作。
- Charge 与 MoonHunt 严格交替且中断后可恢复。
- 四种 Charge 结果对应正确恢复/眩晕。
- Intact→Cracked→Collapsed→ResetAll。
- 围猎路径不穿越房间内部障碍并从最近外围点开始。
- 所有柱倒塌时仍生成安全走廊。
- GrandBossConfig 数值范围和必需 AttackData 不为空。
- Enemy_Boss Prefab 包含全部正式组件且没有 Missing Script。

### 8.4 PlayMode 测试

- 正式横向 Boss 房生成后恰好注册四根柱。
- Boss 只有一个行为 Brain，旧 EnemyAI 被禁用。
- 圆/线/月痕预警锁定后不随 Boss 移动。
- 三跳任意中心命中后接双爪；全空后眩晕 6～7 秒。
- 震荡波被站立石柱阻断，倒塌柱不阻断。
- 奔袭不会穿过墙、柱或玩家 Hurtbox。
- 撞裂柱后长眩晕真实持续配置时长。
- 围猎必定发生一次扑击，月痕依序爆发并回池。
- 阶段转换、死亡、RoomUnload 后无活动 Hitbox、预警和月痕。
- Respawn/重开后柱状态、阶段、冷却和对象池全部复位。

### 8.5 人工手感清单

- 不看调试面板也能判断右爪、左爪、上挑和下砸。
- 三跳锁点不会偷追踪；第三跳明显但不刺眼。
- 玩家能主动利用柱子创造安全区和输出窗口。
- 冲锋转向不瞬移，横向闪避有效。
- 围猎不会封死全场，安全路线可观察而非靠记忆。
- 失败原因能被玩家复述，不是“突然掉血”。
- 一阶段和二阶段移动姿态、节奏、音色有明显差异。

## 九、性能预算与诊断

- 热身后格兰每帧托管分配目标：0 B；允许阶段首次加载产生可控分配。
- 所有物理查询使用固定缓冲；缓冲溢出必须记录一次诊断而不是静默漏判。

- 不在 Update/FixedUpdate 使用 LINQ、字符串拼接、`FindAnyObjectByType` 或新建 List。
- 同一房间只有一个活动 WorldHazardRoot 和一个 BossArenaState。
- 用 Profiler 分别采集：P1 三跳、P2 三连冲锋、14 月痕顺序爆发、死亡清理。

## 十一、Definition of Done

只有同时满足下列条件，格兰才算“完整修缮完成”：

- [ ] 格兰只有一个行为在运行，旧 EnemyAI 不参与决策。
- [ ] P1 双爪、三重跃击、命中追击、全空眩晕形成稳定循环。
- [ ] 狼嚎和 PhaseTwo 各触发一次，阶段转换无残留。
- [ ] P2 只使用四足移动、裂柱奔袭和残月围猎。
- [ ] Charge/MoonHunt 不连续重复，且两者真实可达。
- [ ] 四柱三态、碎石减速、震荡遮挡和月痕缺口均生效。
- [ ] 所有柱倒塌后仍有可读且可达的安全路线。
- [ ] 所有攻击都有前摇、有效、收招和可辨别预警。
- [ ] 预警锁定后不追踪，且判定与预警消费同一快照。
- [ ] Boss 死亡、重开、Respawn、RoomUnload 后无残留状态。
- [ ] 正式组件写入 Prefab，本地引用和房间上下文可在 Inspector/验证器中核查。
- [ ] 编译无错误，Missing Script 为 0，EditMode/PlayMode 格兰测试全部通过。
- [ ] Profiler 热区无持续 GC，三跳/冲锋/月痕没有明显尖峰。
- [ ] 完成至少三轮人工战斗，并记录伤害、命中率、受击原因和阶段时长。
- [ ] 正式横向 Boss 房满足左入右出和玩家碰撞体可达性。

## 十二、实施注意事项与禁止项

1. 先修接线和生命周期，再调伤害与冷却；错误链路上的数值没有参考价值。
2. 不通过瞬移玩家、移动相机或关闭碰撞伪造测试结果。
3. 不在用户场景 Dirty 时保存、重载或切场景；先由用户处理未保存修改。
4. Prefab 修改通过 Unity Prefab API Apply，并 Reload/验证；不优先手改 YAML。
5. 新 Layer 修改后必须核查 Collision Matrix，避免 Enemy 与自身预警/Trigger 相撞。
6. Boss 房外部修改后重新加载 Unity 场景，再核查唯一 Player、Camera target 和 Debug_ 对象。
7. 对象池回收必须幂等；重复 Cancel、OnDisable、OnDestroy 不得报错。
8. 事件订阅和退订必须配对；房间卸载后不得持有 Room、Player 或 Arena 引用。
9. Tween、协程、VFX 和 Audio 必须绑定对象/房间生命周期。
10. 不把运行时柱状态、冷却或动作结果写回 ScriptableObject。
11. 不继续扩建旧随机攻击池作为二阶段核心；它只能在迁移期间保留兼容数据。
12. 每批完成后新增实施记录，记录实际改动、测试结果和遗留项；新工程教训同步《开发必读_核心信息整合.md》和 project-dev-rules。
