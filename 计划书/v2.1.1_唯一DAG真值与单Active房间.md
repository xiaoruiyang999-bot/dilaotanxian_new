# 《无名之地》v2.1.1 小版本计划书：唯一 DAG 真值与单 Active 房间

> 编写日期：2026-09-18
> 上位依据：《无名之地_完整游戏开发文档_V2.md》《v2.1_三流派肉鸽核心与单向DAG总计划.md》及 v2.1.0 数据合同
> 用户确认：旧 ActiveRun 保留资源并从新 DAG 起点进入；现有格兰仪式厅改为左入右出；贤者/物资房暂用现有三选一，实际领取后才能放行。
> 执行状态：代码与自动走查完成；UI 点击和手动 Boss 战体验待人工验收。完成情况以根目录同名实施记录为准。

## 1. 目标与边界

本版让一份 `DungeonGraphData` 同时驱动路线图、节点进入、房间类型、Seed、完成状态和存档。开局生成 10～12 层图数据，仅实例化 Start 房；之后每次只保留当前节点的一间运行房间。玩家在当前节点目标与奖励均结算后，从图上的直接后继中选一个，卸载旧房再进入新房。任何已走节点不可重进。

贤者房、物资房在本版共用现有 `RewardChoiceUI` 与 `NodeRewardService` 作为临时奖励。它们仍须先战斗、后领奖、再放行；临时奖池不被当成正式刻印或物资池。v2.1.4、v2.1.5 分别替换奖励提供者，不再改节点推进合同。商店房安全无战斗，本版沿用现有商品原型；逐阶解铭与付费揭印由 v2.1.6 接管。

本版不实装十三刻印的战斗效果、正式石碑、正式物资背包、统一暂停服务或付费揭印。这些属于 v2.1.2～v2.1.6。现有可玩入口、职业角色、Boss 结算保留。

## 2. 图生成与验证

1. `DungeonGraphGenerator` 只投放 Start、Supply、Sage、Shop、Boss；旧枚举整数保持不变，Elite 待其奖励职责确定后再投放。Start/Boss 唯一；Start 固定展开 3 条主分支，中间层始终保留三条主干。
2. 非端点节点记录 `MainBranchId`。每条主分支生成 1～2 个持续 1～3 层的局部分叉，支路只汇回原主干；三条主分支除 Start/Boss 外互不连通。所有节点从 Start 可达且能到 Boss；对每条 Start→Boss 路径验证至少 3 个 Sage、至少 1 个中段或之后 Shop。
3. 图 Seed、节点 Room/Encounter/Reward/Shop Seed 和节点类型由同一 Run 固定。地图只读这些数据；它的 UI 节点不另存当前节点真值。
4. `DungeonGraphData.Validate` 扩充层数、出度、前后继、可达性、路径机会与非法回边检查。失败图不能进入运行时。

## 3. 唯一 Run 状态与存档

1. `SaveService.ActiveRunData` 是持久化真值：完整图、`currentNodeId`、节点状态、当前资源。新 Run 先建图，再选择并进入 Start。`routeInitializationPending` 在图及当前节点均建立后清零并保存。
2. v1 迁移档和 v2 待路线初始化档不根据旧实体房间推断位置。读取时保留职业资源、随身星蓝币、职业角色、遗物、击杀等已有字段，按本档 `mainSeed` 建新图，从 Start 进入。有效资源快照照常恢复；缺少 `resourcesInitialized` 的旧档若已有真实生命、护甲或法力也继续保留，只有 5 生命、0 护甲、0 法力的旧 Prefab 坏快照会改用职业满状态。
3. 读到已有合法图时恢复当前节点及其原 Room Seed，不重掷图。当前节点目标已完成而奖励未结算时，恢复待领奖状态；已领奖时恢复可选路线状态。
4. 节点选定、目标完成、奖励确定与领取、进入下一节点、Boss 结算后保存。领取与推进必须有幂等门禁，关闭 UI 或重复触发不能重抽和重领奖。

## 4. 单房间运行合同

1. `DungeonBuilder` 增加单节点构建入口：把 `DungeonGraphNode` 映射到现有房间内容 Profile，按 `RoomSeed` 建最终 `RoomPlan`，用左入口与右出口锚点验证玩家碰撞口径可达，再绘制瓦片和仅此一间 `Room`。`ActiveRoomContext` 只持当前实例、出口和订阅，不回写图的已发现/已完成状态。
2. Start、Shop 为安全房；Supply、Sage 为战斗房；Boss 使用现有格兰仪式厅、Boss 内容和结算。格兰厅的模板坐标、门锚点与装饰统一转为左入右出；旧南入口布局仅留旧生成器兼容，不进入新 Run。
   新 DAG 商店房使用完整高度；房间含墙边界需覆盖右/上墙整格，镜头像素对齐、震动后对四边再次钳制。视口允许越过围墙约 1 个世界单位，以完整显示墙体并露出少量黑色背景。
3. 玩家从房间左侧安全位置出现，出口位于右侧。进入前核对唯一 Player、RoomBounds 和相机 Bounds。离开时取消奖励/清房/Boss 订阅与延迟协程，销毁旧房内容及门、敌人、Tween，清 Tilemap；新房建成后再释放转场门禁。任意时刻运行房间数至多 1。
4. 清房只推进 `ObjectiveCompleted`；临时三选一真正应用后才推进 `RewardResolved` 与 `Completed`。安全房在进入后完成客观目标并可主动离开。出口只提交路线选择意图，纯规则层验证候选必须属于当前节点 `NextNodeIds`，不能回退、跳层或绕领奖。
5. 对新 Run，停止调用旧 `DungeonGenerator` 的全层实体布局。旧 `DungeonLayout`、旧 Boss 南入口与旧多门连接只保留兼容代码；新链验收前不删除历史资产。

## 5. 路线图与表现

- 路线图显示完整连接、当前/已完成/直接可选后继，以及已揭示类型；Boss 始终可辨。未揭示类型只显示问号。
- 路线图固定分为 3 个纵向区域，对应三个 `MainBranchId`。普通节点单后继，只有短支路起点显示两个候选；支路结束后汇回本主干。10,000 Seed 验收须证明移除 Start/Boss 后恰好有三个连通分量，且选择任一主分支后直到 Boss 都无法到达其他主分支。
- 当前节点完成且奖励已领取时，直接后继才可点击；不可选节点不给推进回调。选择时先写入图与 Run、保存，再开始房间切换。与右出口交互打开路线选择；Tab 保留查看功能。
- v2.1.2 才统一暂停与模态焦点；本版路线选择临时屏蔽世界交互并避免双击推进，后续替换为统一服务。

## 6. 实施顺序与验证

1. 先实现纯数据图约束、路线推进状态机和覆盖至少 10,000 Seed 的 EditMode 测试。
2. 接入单房 `RoomPlan`/Builder、左入右出 Boss 模板与可达验证；验证重复生成不会遗留上一房间。
3. 将 `DungeonManager`、`RunManager`、地图选择、临时奖励、Boss 结算和 ActiveRun 存档接成一条链；在迁移期保持准备场景入口可运行。
4. Unity 编译、EditMode、PlayMode/人工完整走查：准备房开局、Start→分叉→汇聚→Boss、存读档、旧档迁移、死亡重开、唯一 Player、相机 Bounds、控制台错误和 Missing Script。
5. 新增根目录 `v2.1.1_唯一DAG真值与单Active房间.md` 实施记录；实际玩法决策同步 V2 主文档和长期路线图。工程红线若改变，同步 `AGENTS.md`、开发必读和 `project-dev-rules`。

## 7. 完成门禁

- 10,000 Seed 全部满足 10～12 层、1～3 节点/层、1～3 后继、唯一 Start/Boss、无环/死路/重复边、每路径 3 Sage 与中后段 1 Shop；同 Seed 全部节点字段稳定。
- 地图与房间读同一个 `ActiveRun.dungeonGraph`；开局和每次推进只存在当前节点一间房，右出口不能越过未领奖状态。
- 旧档资源保留并从新 DAG 起点进入，已有新图读档不重掷，节点状态与资源往返一致。
- 格兰 Boss 房左入右出，模板、敌人位置、奖励位置与相机范围没有南入口残留；清 Boss 后仍能正常结算。
- 代码编译无错误，EditMode 与至少一条完整人工 Run 通过，Console 无新增红错；不修改玩家真实测试存档或 PlayerPrefs。
