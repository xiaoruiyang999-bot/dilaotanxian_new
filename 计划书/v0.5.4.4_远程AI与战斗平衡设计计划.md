# v0.5.4.4 远程 AI 与战斗平衡：设计计划

> 人工体验发现的 Projectile 近战工具模板耦合已在 [`v0.5.4.4.1_远程攻击执行链解耦计划.md`](./v0.5.4.4.1_远程攻击执行链解耦计划.md) 完成自动修订验证；现在恢复远程手感人工验收。

## 1. 版本定位

v0.5.4.3 已完成五类敌人的运行闭环、预算遭遇和基础词缀。v0.5.4.4 不继续横向增加敌人种类，而是解决“能运行但战斗体验尚未被证明”的问题。

本版本主目标：

1. 让 Ranged 的攻击可观察、可躲避、不会隔墙命中。
2. 让远程敌人的保持距离、后撤和走位不会频繁卡墙或抖动。
3. 让遭遇强度随房间进度平滑变化，同时阻止明显不公平的高压组合。
4. 建立可重复的数值基线和人工体验验收流程。
5. 保持 v0.5.4.3 已通过的死亡、清房、开门、召唤上限和固定 seed 行为。

## 2. 完成定义

只有同时满足以下条件，v0.5.4.4 才能标记完成：

- Ranged 射击前有明确预警，预警方向与实际弹道一致。
- 发射时视线被墙阻挡则不生成投射物，也不进入无意义完整冷却。
- 玩家贴近时 Ranged 能后撤；后方受阻时停止或选择侧向空间，不持续顶墙。
- Ranged 不在最小/最大距离边界附近每帧来回切换状态。
- Start 附近房间不会出现 Summoner 或高压词缀组合。
- 同一固定 seed 下，地图、遭遇组合和词缀选择保持可复现。
- 完整地牢自动回归为 0 Error / 0 Warning，清房后门全部打开。
- 完成人工战斗记录，并根据记录完成至少一轮参数调整。

## 3. 范围与非目标

### 本版本范围

- Ranged 视线检测（Line of Sight，LOS）。
- 方向性射击预警。
- 带滞回区间的距离控制。
- 墙体感知与后撤失败处理。
- 可选的低频侧向选位，不实现完整寻路。
- 根据房间距起点距离计算遭遇预算。
- 高压组合限制和起始保护规则。
- 数值基线、自动测试与人工体验表。
- 清房反馈的最小表现增强。

### 本版本不做

- 新敌人类型。
- A*、NavMesh 或行为树重构。
- Projectile 对象池，除非 Profiler 达到文档阈值。
- Boss 多阶段与弹幕系统。
- 战后奖励、商店和下一层循环。
- 玩家武器成长与装备系统。

## 4. 架构增量

```text
感知层（新增职责）
├─ EnemyPerception：目标距离、LOS、前/后/侧向空间查询
└─ PerceptionResult：本帧只读感知快照
          ↓
决策层
├─ EnemyAI：根据配置和感知快照选择接近/保持/后撤/侧移/攻击
└─ EnemyBehaviorConfig：距离区间、滞回、选位间隔、视线参数
          ↓
执行层
├─ EnemyController：执行速度和朝向，不做战术选择
├─ EnemyCombat：预警、攻击状态机、发射前最终 LOS 校验
└─ Projectile：飞行、命中、撞墙、超时销毁
          ↓
遭遇层
├─ EncounterDifficulty：根据房间距离计算预算和限制
├─ SpawnTable：敌人成本、职责、上限、词缀池
└─ EnemySpawner：只消费最终规则，不感知玩家
```

### 依赖约束

- `EnemyPerception` 不修改速度、状态和动画，只提供查询结果。
- `EnemyAI` 不直接执行 Physics2D 位移。
- `EnemyCombat` 在 Windup 开始时锁定预警方向，在发射瞬间进行最终 LOS 校验。
- `Projectile` 不负责判断敌人是否应该开火。
- 遭遇难度只依赖房间元数据和 seed，不读取玩家实时生命值，避免不可复现的动态难度。
- 不把 Ranged 专用逻辑写入 `Room`、`Door` 或 `DungeonBuilder`。

## 5. 预使用技术

| 技术 | 用途 | 约束 |
|---|---|---|
| `Physics2D.Raycast` | 目标 LOS、后撤方向和侧向空间检测 | 使用明确 LayerMask；避免无过滤的全场查询 |
| 感知采样间隔 | 降低每个敌人每帧多次物理查询 | LOS 默认 0.10 秒，侧向选位默认 0.25 秒 |
| 距离滞回（Hysteresis） | 防止边界抖动 | 进入和退出阈值必须分开，不使用单一距离线 |
| AttackData | 继续保存攻击时序、弹速和伤害 | 不把 AI 选位参数塞入 AttackData |
| EnemyBehaviorConfig | 保存 Ranged 感知和距离控制参数 | 配置驱动，不在 EnemyAI 中散落魔法数字 |
| ScriptableObject 难度曲线 | 房间距离到预算/词缀概率的映射 | 第一版可用离散分段，不强制 AnimationCurve |
| 固定 seed 子随机源 | 侧向选择与遭遇组合 | 禁止改用全局 `UnityEngine.Random` |
| Unity MCP Play Mode 测试 | LOS、弹道、混合组合、门回归 | 隔离测试后才运行完整地牢 |

## 6. Ranged 行为规格

### 6.1 距离状态

建议初始值：

| 参数 | 初值 | 含义 |
|---|---:|---|
| preferredMin | 4.0 | 低于该距离开始后撤 |
| preferredMax | 7.0 | 高于该距离开始接近 |
| retreatExitDistance | 4.8 | 后撤达到此距离才退出，形成滞回 |
| approachExitDistance | 6.2 | 接近达到此距离才退出，形成滞回 |
| retreatSpeedMultiplier | 1.0 | 后撤速度倍率 |
| strafeSpeedMultiplier | 0.75 | 侧向速度倍率 |
| repositionInterval | 0.25s | 重新选择侧向方向的最短间隔 |

状态优先级：

```text
无目标 → Patrol
目标不可见且超过短暂宽限 → Chase/最后已知方向
目标过近 → Retreat
后撤方向受阻 → Strafe 或 Stop
目标过远 → Approach
距离合适且 LOS 有效 → Attack
```

### 6.2 LOS 规则

- LOS 从敌人发射点指向玩家伤害中心，不直接使用 Sprite 边缘。
- 首个有效命中为障碍物时视为遮挡。
- 玩家自身 Collider 命中视为 LOS 成功。
- Windup 可以因 LOS 丢失而取消；Active 发射瞬间必须再次校验。
- 取消攻击必须清理预警、武器锁定和状态机，不生成 Projectile。
- 短于 0.15 秒的瞬时遮挡可通过宽限处理，避免贴墙边缘频繁取消。

### 6.3 预警规则

- Windup 开始显示细长方向预警，长度不超过有效射程或首个墙体交点。
- 预警方向在 Windup 开始时锁定，实际 Projectile 使用同一方向。
- 预警颜色沿用 Warning → Danger 两阶段语义。
- Enemy 死亡、失活、攻击取消或离开 Active 时必须隐藏预警。
- 预警仅是表现，不参与伤害判定。

### 6.4 后撤与侧移

- 后撤前检测一个“本帧位移 + 安全余量”的空间。
- 后方受阻时分别检测左右两个候选方向。
- 两侧均可用时使用敌人子 seed 选择，保持可复现。
- 两侧都不可用时停止移动并面向玩家，不允许持续写入朝墙速度。
- 侧向选位存在最短保持时间，防止左右抖动。

## 7. 遭遇难度规格

### 7.1 距离分段

以 `RoomNode.distanceFromStart` 为输入：

| 距离 | 预算建议 | 词缀概率 | 规则 |
|---:|---:|---:|---|
| 0 | 0 | 0% | Start，无战斗 |
| 1 | 4–6 | 0% | 教学保护：禁用 Summoner，最多 1 个特殊职责 |
| 2–3 | 5–8 | 10% | 标准组合 |
| 4–5 | 7–10 | 20% | 允许一个 Support 或强化前排 |
| 6+ | 9–12 | 30% | 高压组合，但仍服从同类上限 |

最终数值必须结合当前地图实际最大距离调整，不直接假设每层都有 6+ 距离房间。

### 7.2 高压组合限制

第一版禁止：

- 房间距离 ≤1 时出现 Summoner。
- 同房间超过 1 个 Summoner。
- 同房间超过 2 个 Ranged。
- 同房间同时出现 Tough Charger、Summoner 和 2 个 Ranged。
- 没有 Frontline 的纯后排组合。

第一版推荐组合：

- Melee + Ranged。
- Melee + Skirmisher。
- Charger + Ranged。
- 2×Melee + Summoner。
- Melee + Ranged + Skirmisher。

## 8. 数值基线

本表是首轮测试起点，不是最终平衡结论：

| 对象 | 关键数值 | 初始目标 |
|---|---|---|
| Ranged | windup | 0.45–0.65 秒，玩家能看见并反应 |
| Ranged | projectileSpeed | 7–9，房间中距离可躲避 |
| Ranged | cooldown | 1.4–1.8 秒 |
| Projectile | damage | 1，不允许单发造成不可恢复的高压 |
| Summoner | cooldown | 8 秒 |
| Summoner | alive cap | 4 |
| Charger | windup | ≥0.5 秒 |
| Swift | speed multiplier | 1.25–1.35 |
| Tough | health multiplier | 1.5–1.75 |

调整顺序固定为：预警清晰度 → 攻击频率 → 弹速 → 敌人数量 → 伤害。不要先通过降低伤害掩盖不可读的攻击。

## 9. 分阶段实施计划

### 阶段 A：感知与 LOS（已完成）

- 明确 Player、Wall、Obstacle LayerMask。
- 增加可复用的感知查询或等价低耦合实现。
- 攻击开始和发射瞬间执行 LOS 校验。
- 建立无遮挡、墙体遮挡、墙边瞬时遮挡测试。

退出条件：隔墙不生成 Projectile；无墙时行为不回退；Console 0 Error。

验证结果（2026-08-14）：

- 新增只读 `EnemyPerception`，基础 Enemy Prefab 与全部 Variant 统一继承。
- 兼容 Walls 与 Player 同处 Default Layer 的现状：跳过自身 Collider，以首个外部 Collider 是否属于目标判断 LOS。
- 无遮挡时 LOS=True 且攻击可进入 Windup；墙体遮挡时 LOS=False 且攻击不启动。
- Windup 后新增墙体时，发射瞬间强制刷新 LOS，攻击取消且 Projectile 数量不增加。
- Unity 编译与 Console：0 Error。

### 阶段 B：预警与攻击取消（已完成）

- 为 Projectile 攻击增加方向预警。
- 保证预警与弹道方向一致。
- 完整处理死亡、失活、LOS 丢失和攻击取消。

退出条件：所有中断路径无残留指示器、武器锁定或攻击状态。

验证结果（2026-08-14）：

- `AttackIndicator` 新增 Line Mesh，Ranged Windup 显示方向预警。
- 锁定的预警方向与 Projectile 发射方向一致。
- 发射前 LOS 丢失会取消攻击、隐藏预警，并允许立即重试而不进入完整冷却。
- Windup 中敌人死亡会停用对象、清除 Combat 状态并隐藏预警。
- Unity 编译与 Console：0 Error。

### 阶段 C：后撤、滞回与侧移（已完成）

- 引入进入/退出阈值。
- 后撤检测墙体。
- 后撤失败时选择侧向或停止。
- 固定 seed 下侧向选择可复现。

退出条件：边界运行 10 秒无每帧状态抖动；墙边运行 10 秒无持续顶墙。

验证结果（2026-08-14）：

- Ranged 使用 Hold/Approach/Retreat/Strafe 有状态距离控制。
- 3.0 距离进入后撤，4.2 仍保持后撤，达到 4.9 后退出，滞回有效。
- 后方受阻时选择可用侧向；后方与两侧均受阻时速度归零，不持续顶墙。
- 相同 seed 的两次隔离测试得到相同侧移方向。
- 修复 `EnemyController.MoveTowards` 归一化导致速度倍率失效的问题。
- Unity 编译与 Console：0 Error。

### 阶段 D：动态遭遇规则（已完成）

- 将房间距离传入遭遇预算计算。
- 实现起始保护和高压组合限制。
- 保持旧表和固定 seed 兼容。

退出条件：各距离段至少 500 次抽样满足预算、职责和禁配规则。

验证结果（2026-08-14）：

- Room 保存 `DistanceFromStart`，EnemySpawner 按距离消费数据化难度 Band。
- 距离 1/2/4/6 各抽样 500 次，共 2000 次，职责、Support 上限和禁配失败数为 0。
- 距离 1 的 Summoner 出现数为 0，500 次词缀抽样出现数为 0。
- 平均遭遇成本随距离为 4.61 → 6.01 → 7.98 → 10.05，保持非递减。
- 200 个 seed 重复组合，确定性失败数为 0。

### 阶段 E：完整地牢与人工体验（自动回归已完成，人工手感待执行）

- 自动验证五类敌人、词缀、清房和门。
- 人工完成三轮不同 seed 的完整战斗。
- 每轮记录命中来源、受伤次数、卡墙、不可读攻击和房间耗时。
- 根据记录只调整一组变量，再复测。

退出条件：自动回归通过，人工验收没有阻断级问题。

自动验证结果（2026-08-14）：

- 随机 seed：9 个战斗类房间、23 个敌人，空房/Combat 无前排为 0，距离 1 的 Summoner 为 0。
- 随机 seed 全灭：9 个房间 Cleared 失败数 0，15 扇门仍关闭数 0。
- 固定 seed 42：实际生成 Melee、Ranged、Skirmisher、Charger、Summoner 五类敌人。
- 固定 seed 42 全灭：8 个战斗类房间 Cleared 失败数 0，12 扇门仍关闭数 0。
- Unity Console：0 Error / 0 Warning。

尚待人工执行：使用下方模板完成三个 seed 的 WASD 实战，记录弹道可读性、卡墙、受伤来源和房间耗时。该项不能由自动击杀替代。

## 10. 测试矩阵

| 类别 | 场景 | 通过标准 |
|---|---|---|
| LOS | 玩家与 Ranged 之间无墙 | 能进入 Windup 并发射 |
| LOS | 中间有 Wall | 不生成 Projectile |
| LOS | Windup 中玩家躲到墙后 | 攻击取消且预警清理 |
| 方向 | 玩家在 Windup 中移动 | Projectile 与锁定预警方向一致 |
| 后撤 | 玩家贴近、后方空旷 | 距离增加到退出阈值 |
| 后撤 | 玩家贴近、后方有墙 | 不持续顶墙，选择侧移或停止 |
| 滞回 | 玩家停在边界附近 | 10 秒内不发生高频往返切换 |
| 遭遇 | 距离 1 房间 | 无 Summoner、无词缀 |
| 遭遇 | 中后段房间 | 预算随距离非递减 |
| 禁配 | 500 次抽样 | 不出现文档禁止组合 |
| 确定性 | 相同 seed 重复生成 | 地图、组合、词缀一致 |
| 回归 | 清除所有敌人和 Minion | Room Cleared，所有门打开 |
| 生命周期 | Ranged 在 Windup/Active 死亡 | 无预警、弹道或状态机残留 |

## 12. 文档与变更纪律

1. 实现严格按 A → B → C → D → E 推进。
2. 每阶段先记录测试结果，再修改下一层。
3. LOS、预警和移动修改不得破坏 v0.5.4.3 的清房生命周期。
4. 新参数必须进入 `EnemyBehaviorConfig` 或专用配置，不在代码中散落常量。
5. 人工体验调整一次只修改一个变量组，并记录前后差异。
6. 对象池、Boss 和奖励系统继续冻结，除非另立版本文档。
