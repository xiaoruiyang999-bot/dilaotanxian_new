# v0.4.6 正式计划：武器实体碰撞判定 + 玩家世界空间状态条

## 版本信息
- **版本号**：v0.4.6
- **版本名称**：武器实体碰撞判定 + 玩家世界空间状态条
- **前置版本**：v0.4.5.2（攻击动画框架统一重构）
- **目标**：
  1. Player 与 Enemy 的伤害结算从「动画时刻触发的瞬时扇形判定」改为「挥动过程中武器矩形与角色碰撞体真实接触才结算」，动画回归纯视觉。
  2. Player 头顶增加世界空间状态条（红血条 + 蓝护甲条）。
- **约束**：不对现有框架做大幅度修改；Windup / Active / Recovery 状态机、AttackData 配置源、WeaponAnimator / WeaponController 分工全部保留。

## 一、现有框架分析（判定现状）

### 1.1 当前攻击数据流

```
AttackData（唯一配置源：形状/时长/范围/角度/伤害/冷却/目标层/动画/命中时刻比例）
    │
    ├─► WeaponController   武器朝向、WeaponSprite 视觉（长=AttackRange，宽=weaponWidth）
    ├─► WeaponAnimator     DOTween 旋转 WeaponPivot（纯视觉）
    ├─► AttackIndicator    扇形预警 Mesh（纯视觉）
    └─► AttackQuery        伤害判定：Active 阶段 activeMomentRatio 时刻（默认 0.5）
                           执行一次 OverlapCircleAll + 角度过滤 → TakeDamage
```

### 1.2 当前判定的三个问题

| 问题 | 说明 |
|------|------|
| 动画与判定脱节 | 武器还没挥到 / 已经挥过，伤害都在 0.5 时刻点一次性结算，动画只是"看起来像在打" |
| 无法走位规避 | 敌人在 Windup 后即使跑出武器轨迹，只要 0.5 时刻还在扇形内就会掉血；反之贴脸也可能因为角度缓存过早而空挥 |
| 判定形状与武器形状不符 | 判定是"以角色为圆心的扇形"，而不是"武器本身这个矩形"，长武器尖端与柄部判定无区别 |

### 1.3 可复用资产（本版本不动的部分）

- `AttackData`：字段不变。`activeMomentRatio` 保留，但语义降级为「指示器隐藏时机 / 未来音效触发点」，不再决定伤害。
- `PlayerCombat` / `EnemyCombat` 的 Windup / Active / Recovery 状态机：结构不变，仅替换 Active 阶段内的伤害来源。
- `WeaponPivot + WeaponSprite` 结构：武器矩形的位置、长度、朝向全部可从现有 Transform 实时读出，**不需要新增任何视觉对象**。
- `IDamageable` / `Health` / `PlayerStats`（护甲吸收）/ `EnemyHealth`（受击通知 AI）：结算入口不变。
- `AttackIndicator`：继续作为敌人攻击预警（纯视觉），职责不变。

### 1.4 关键场景事实（实施前必须知道）

| 事实 | 影响 |
|------|------|
| Enemy 根物体上有一个 **radius=5 的 trigger CircleCollider2D**（与实体 BoxCollider2D 共存） | 武器检测**必须跳过 `isTrigger` 碰撞体**，否则武器隔着 5 米就会"命中"敌人的探测圈 |
| Player 在 layer 0 (Default)，Enemy 在 layer 6 (Enemy) | 与两份 AttackData 的 `targetLayer`（Player→64，Enemy→1）一致，沿用即可 |
| Player 的 WeaponSprite 当前错误地挂在 layer 6 (Enemy) | 轮询方案不受影响（从不查询武器自身的层）；顺手修正为 Default，避免未来误用 |
| 武器矩形参数 | 长度 = `AttackData.AttackRange`（Player 1.8 / Enemy 1.5），宽度 = `WeaponController.weaponWidth`（0.15），沿 WeaponPivot 局部 +X 轴伸出，中心在 `pivot.position + pivot.right * (length/2)` |
| Player 根物体 scale = 0.6 | 武器渲染长度实际是 AttackRange × 0.6（Enemy 为 ×1）。WeaponHitbox 的检测盒长宽必须乘 `weaponPivot.lossyScale`（等比缩放假设，与 WeaponController 视觉同一前提），否则判定盒会比看到的武器长，出现"隔空命中" |
| Player 攻击期间仍可 WASD 移动 | 检测盒每帧从 WeaponPivot 世界姿态重新计算，天然跟随，无需特殊处理 |
| Player.prefab 无 HealthBarAnchor 子物体 | 世界空间状态条需要新增锚点 |

## 二、目标架构

```
AttackData（不变）
    │
    ├─► WeaponController   （不变，新增 2 个只读访问器）
    ├─► WeaponAnimator     （不变，纯视觉）
    ├─► AttackIndicator    （不变，纯预警视觉）
    └─► WeaponHitbox  ★新增  由 Combat 状态机驱动，Active 阶段逐帧检测武器矩形 vs 角色碰撞体，
                              命中即 TakeDamage，每次挥击每目标只结算一次

AttackQuery：保留脚本作为 v0.5 瞬时技能/AoE 工具，近战普攻不再经由它。
```

伤害结算路径变化：

```
旧：EnterActive → WeaponAnimator.Play(..., onActiveMoment) → 0.5时刻 → AttackQuery 扇形判定 → TakeDamage
新：EnterActive → WeaponHitbox.BeginSwing() → Active 期间 Combat 每帧驱动 Tick() → 矩形碰到角色 → TakeDamage（去重）
    EnterRecovery（双方）→ WeaponHitbox.EndSwing()
```

## 三、核心设计 A：武器矩形命中检测（WeaponHitbox）

### 3.1 方案选型

| | 方案 A：逐帧 OverlapBox 轮询（**推荐**） | 方案 B：真实 Trigger 碰撞体 |
|---|---|---|
| 做法 | Active 阶段由 Combat 每帧调用 `Tick()`，内部 `Physics2D.OverlapBoxNonAlloc`，盒子姿态取自 WeaponPivot 实时 Transform | WeaponSprite 下挂 BoxCollider2D(isTrigger) + kinematic Rigidbody2D，`OnTriggerEnter2D` 回调 |
| 与视觉一致性 | 与渲染帧完全一致（DOTween 在 Update 改 pivot，同帧检测同姿态） | 物理回调按 FixedUpdate 采样，与 Update 驱动的动画存在采样错位，快挥可能漏帧 |
| 需要改动 | 纯代码，1 个新脚本 + 2 个 Combat 各几行 | 改 Prefab 结构、新增碰撞层、改 ProjectSettings 碰撞矩阵、加 Rigidbody2D |
| 风险 | 极低帧率下可能穿透（0.2s Active，60fps 约 12 次采样，武器长 1.8，实际不会） | Player 的 WeaponSprite 层配错（在 Enemy 层）会直接打自己人；矩阵配置错则全哑火 |
| 与现有风格 | 与 AttackQuery 同款（代码驱动、Overlap 系列、targetLayer 过滤） | 引入第二套判定范式 |

**结论：采用方案 A。** 改动最小、与渲染姿态严格一致、不碰物理设置。方案 B 作为记录备查，本版本不实施。

### 3.2 新脚本 `WeaponHitbox.cs`

**位置**：`Assets/Scripts/v0_4/WeaponHitbox.cs`（与 AttackQuery 同目录）

**职责**：只在挥击激活期间工作，每次 `Tick()` 用武器矩形做碰撞查询并结算伤害。不控制动画、不读输入、不管 AI、**不自跑 Update**。

**生命周期由 Combat 驱动**（与 `WeaponAnimator.Play` 同一模式，攻击节奏只有 Combat 一个主人）：

```csharp
public class WeaponHitbox : MonoBehaviour
{
    // 配置（均有序列化兜底值，Awake 时若存在 WeaponController 则取其宽度/pivot 覆盖）
    [SerializeField] private AttackData attackData;
    [SerializeField] private Transform weaponPivot;              // 武器矩形姿态逐帧取自此 Transform
    [SerializeField] private float weaponWidth = 0.15f;          // 兜底宽度，存在 WeaponController 时被覆盖
    [SerializeField] private bool drawGizmos = false;

    public System.Action<IDamageable, Vector2> OnHit;  // 命中反馈扩展点（特效/音效/未来的击退、HitStop）

    public void BeginSwing();        // Combat 在 EnterActive 调用：清空去重集合，开始挥击
    public void Tick();              // Combat 在 UpdateActive 每帧调用：执行一次矩形检测
    public void EndSwing();          // Combat 在 EnterRecovery 调用：结束挥击
    public void SetAttackData(AttackData data);  // v0.5 换武器/技能，与 Combat 保持同一引用风格
}
```

**为什么 Tick 由 Combat 驱动而非自跑 Update**（评审采纳）：自跑 Update 时脚本执行顺序不受控，`EndSwing()` 当帧若 Hitbox 的 Update 排在 Combat 之后，会多结算一次"挥击已结束后"的命中；由 Combat 驱动后检测窗口严格等于 Active 阶段，不可能越界。

**低耦合设计**（评审采纳，折中版）：运行时只依赖 `weaponPivot` / `weaponWidth` / `attackData` 基础数据，没有 WeaponController 的对象（Boss 肢体、陷阱等）也可独立复用；但 Awake 时若存在 WeaponController 则用其 `WeaponWidth` 覆盖序列化兜底值，**保证视觉宽度与判定宽度单一数据源**，避免两处配置漂移。

**每次 Tick 的检测逻辑**：

1. 计算盒子（乘以 `weaponPivot.lossyScale`，与渲染出的武器矩形严格一致）：
   - `scale = weaponPivot.lossyScale.x`（等比缩放假设，与 WeaponController 视觉同一前提）
   - `length = attackData.AttackRange * scale`，`width = weaponWidth * scale`
   - `center = weaponPivot.position + weaponPivot.right * (length * 0.5f)`
   - `angle = weaponPivot.eulerAngles.z`
2. `Physics2D.OverlapBoxNonAlloc(center, new Vector2(length, width), angle, buffer, attackData.TargetLayer)`，静态缓冲 16 槽位避免 GC。
3. 对每个命中碰撞体过滤：
   - `hit.isTrigger` → 跳过（**关键**：Enemy 的半径 5 探测圈、以及未来任何 trigger 都不可被当作肉体）
   - 属于攻击者自身（`hit.transform.root == transform.root`）→ 跳过
   - 已在本次挥击的 `HashSet<Collider2D>` 去重集合中 → 跳过
4. `hit.TryGetComponent<IDamageable>(out var d)` → `d.TakeDamage(attackData.AttackDamage)`，加入去重集合，触发 `OnHit`。
5. Gizmos 开关：绘制检测盒（挥击中红色高亮），方便 Scene 视图调试。

**伤害结算不事件化**（评审结论，维持原设计）：`TakeDamage` 由本组件直接调用，与 `AttackQuery` 及全项目伤害流风格一致；`OnHit` 仅作命中反馈扩展点。暴击、伤害修正等需要伤害管线的能力属 v0.5 范畴，届时再演进，不在本版本引入无当前需求的间接层。

**配套小改动：`WeaponController` 增加两个只读访问器**（各 1 行，不改任何逻辑）：

```csharp
public float WeaponWidth => weaponWidth;
public Transform WeaponPivot => weaponPivot;
```

### 3.3 Combat 接入（PlayerCombat 与 EnemyCombat 对称修改）

每个文件只有 5 处小改：

1. 字段引用：`attackQuery` 替换为 `weaponHitbox`（Awake 中 `GetComponent<WeaponHitbox>()` 自动补齐）。
2. `EnterActive()`：`weaponHitbox?.BeginSwing();`（WeaponAnimator.Play 调用保持不变）。
3. `UpdateActive()`：计时未到时每帧调用 `weaponHitbox?.Tick();`——检测节奏由状态机统一驱动。
4. `OnActiveMoment()`：删除 `PerformFanAttack()` / `attackQuery.ExecuteAttack(...)`，只保留指示器隐藏（玩家）/ 无操作（敌人指示器已在 Active 切危险色，维持原隐藏时机）。
5. `EnterRecovery()`：**双方**都在此处 `weaponHitbox?.EndSwing();`——武器旋转 Tween 时长 = ActiveDuration，Active 一结束武器就停挥，检测必须同步关闭（Enemy 的 `EndAttack()` 在 Recovery 之后才执行，不能等到那时）。

> 死亡中断说明：当前版本角色死亡时攻击流程本来就靠 `enabled = false` / AI 停转来终止，Tick 不再被调用即停止检测，无需新增中断 API；若 v0.5 加入受击打断，再调 `EndSwing()` 即可。

### 3.4 判定规则明确（写进验收）

- 一次挥击对同一目标**只结算一次**（去重集合在 BeginSwing 时清空）。
- 武器矩形扫过目标即命中，与扇形角度无关；`AttackAngle` 从此只影响**动画幅度与指示器形状**，不再参与近战伤害判定。同步把 `AttackData.attackAngle` 的 Inspector Tooltip 改为注明此语义，防止后续误用（一行注释改动）。
- 目标的死亡、护甲吸收等结算规则完全沿用 `Health` / `PlayerStats` / `EnemyHealth` 现有逻辑，本版本不改。
- 敌人被命中后 `EnemyHealth.OnTakeDamage` 照常触发（AI 仇恨、受伤闪烁），行为不变。

## 四、核心设计 B：Player 世界空间状态条（血条 + 蓝条）

### 4.1 选型

`WorldSpaceHealthBar`（敌人头顶单红条）工作正常，但其结构是"单条 + 二选一数据源"，直接扩展成双条会让敌人用的组件背上 PlayerStats 依赖。**决策：新增独立脚本，模式照抄 WorldSpaceHealthBar 已验证的写法，敌人血条零改动。**

### 4.2 新脚本 `PlayerWorldStatusBar.cs`

**位置**：`Assets/Scripts/v0_3/PlayerWorldStatusBar.cs`（与 WorldSpaceHealthBar、PlayerUI 同目录）

**做法**（与 WorldSpaceHealthBar 同一套已验证模式）：

- 运行时自建 World Space Canvas，挂到全局 `WorldUIRoot` 下（复用同名查找/创建逻辑），`sortingOrder = 10`。
- 两条 `Image (Filled, Horizontal)`：
  - HP 条：红色（沿用 `fillColor` 红），数据源 `Health.OnHealthChanged`
  - 护甲条：蓝色（对齐 PlayerUI 的蓝），数据源 `PlayerStats.OnStatsChanged`
- `LateUpdate` 中 `canvas.position = player.position + 去旋转后的锚点偏移`、`rotation = identity`（与 WorldSpaceHealthBar 相同，只平移不旋转）。
- 订阅发生在 `OnEnable`，订阅后立即主动刷新一次（吸取 v0.4.5.2 敌人血条初始发黑的时序教训）。
- `OnDestroy` 销毁自建 Canvas。

**建议尺寸**：Canvas 84×20 px、scale 0.01；HP 条 80×8 在上，护甲条 80×5 在下，间距 3px。数值进 Inspector 默认值，可调。

### 4.3 Prefab / 场景改动

- `Player.prefab`：
  - 新增子物体 `HealthBarAnchor`（localPosition ≈ (0, 1.1, 0)，对齐敌人锚点的相对高度）
  - 根物体挂 `PlayerWorldStatusBar`（数据源 `GetComponent<Health>()` / `GetComponent<PlayerStats>()` 自动获取，无需手配）
  - 顺手修正：`WeaponSprite` 的 layer 从 6 (Enemy) 改为 0 (Default)
- 屏幕左下角 `PlayerUI` **保留不动**，头顶条与固定条并存（如嫌冗余，届时把 Canvas 里 PlayerStatsPanel 隐藏即可，不在本版本做）。

## 八、框架改进建议（可选，不在本版本实施）

以下为观察到的优化点，**仅作记录，v0.4.6 不执行**：

1. **PlayerCombat / EnemyCombat 约 80% 代码重复**（同一套三阶段状态机）。v0.5 技能系统落地前，可抽一个 `CombatMotor` 基类/组件承载状态机与 WeaponHitbox 驱动，Player/Enemy 只留输入与朝向差异。届时 AttackData 切换也能收拢到一处。
2. **轮询缓冲复用**：WeaponHitbox 已用 NonAlloc + 静态缓冲；若未来同屏攻击者 >20，可再引入 `ContactFilter2D` 复用与分帧检测。
3. **命中反馈管线**：`WeaponHitbox.OnHit` 事件是未来命中停顿（hitstop）、击退、飘字的统一挂点，v0.5 再接。
