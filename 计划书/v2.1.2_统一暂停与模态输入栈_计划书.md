> 补档日期：2026-09-24；本文件依据 v2.1 总计划及已落地代码补齐，记录本版目标与验收合同，不将事后结果伪装成事前计划。

## 1. 目标与范围

把暂停原因、界面焦点和世界输入门禁收敛到同一服务。暂停菜单、设置、叙事/档案、DAG 地图与路线选择、奖励选择、职业角色选择、技能树、死亡与胜利结算均按同一规则打开和关闭。保留准备房开局：玩家先在 `v0_7_PrepRoom` 苏醒/复活，主动交互传送门后从 Start 节点开始新 Run。

本版继续使用 v2.1.1 的临时三选一奖励；正式刻印、贤者石碑美术、物资背包和安全商店属于 v2.1.3～v2.1.6。正式背包创建时直接接入本版模态服务。

## 2. 暂停与输入合同

1. `GameModalService` 为阻塞界面发放并回收令牌，以后进先出顺序确定顶层模态；面板不直接写 `Time.timeScale`。
2. 同时存在多个暂停原因时，关闭一层只释放该层令牌。设置页从暂停菜单打开时，关闭设置回到暂停菜单，不恢复世界。
3. Hit Stop 与 UI 暂停经统一仲裁：重叠 Hit Stop 取最长剩余时间；其到期不得恢复仍被 UI 暂停的世界。
4. Esc 只交给顶层模态。顶层不可取消时消费 Esc；没有模态时 Esc 才打开暂停菜单。关闭最后一层的同一帧继续拦截世界输入，防止确认点击穿透。
5. 阻塞期间屏蔽移动、攻击、Dash、技能、道具与世界交互；界面动画使用非缩放时间。
6. 场景卸载、对象销毁和面板关闭都要配对释放令牌，避免残留暂停。

## 3. 奖励与路线合同

1. 贤者房/物资房先完成房间目标，再出现临时石碑/宝箱及三选一。候选由该节点的 `RewardSeed` 决定。
2. Esc 可暂时关闭奖励选择；暂退不发奖、不置 `RewardResolved` 或 `Completed`。再次与石碑/宝箱交互，重开同一组候选。
3. 未实际确认奖励时，右出口不能打开路线选择，也不能推进到下一节点。确认后只结算一次，保存状态并解锁出口。
4. 路线地图可关闭；再次与右出口交互可重开。候选只来自当前节点的直接后继，不能自动替玩家选择第一个分支。
5. 准备房传送门固定开始新 Run，切换场景前同步结束旧 ActiveRun。未来续局须有独立显式入口；死亡立即返回和暂停菜单重开亦须先结束旧 Run。

## 4. 实施顺序

1. 建立令牌栈、时间仲裁和同帧输入门禁，先覆盖纯规则测试。
2. 接入暂停/设置、叙事、地图/路线、奖励、职业角色、技能树和结算界面，逐一检查关闭与销毁路径。
3. 接入临时石碑/宝箱的暂退重开和出口门禁，固定准备房新局入口。
4. 验证编译、EditMode、准备房 Play 及完整人工路线。核对 Game 视图 Gizmos 状态，避免把编辑器叠加线误判为游戏内容。

## 5. 完成门禁与遗留

- 编译无错；顶层 Esc、嵌套暂停、Hit Stop 与 UI 暂停、同帧输入穿透的测试通过。
- 同 Seed 奖励重开不重抽；未领奖不能选择路线；关闭地图后可再交互打开。
- 准备房进入新 Run 时满状态从 Start 房开始，Start 的三个直接后继均未被自动选中或访问。
- Play 无新增运行时错误；人工检查按钮、键鼠、视觉层级及从 Start 到 Boss 的完整路线。
- 诊断 Gizmos 仅影响编辑器 Game 视图；正常视觉验收应关闭 Game 视图 Gizmos，再判断画面问题。
