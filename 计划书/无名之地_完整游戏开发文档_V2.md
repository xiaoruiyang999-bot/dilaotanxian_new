## 0. 本轮定案摘要

1. 【已定案】游戏为 2D 俯视角、房间制、横向单向宏观推进的 Roguelite；房内上下左右自由移动，不是传统横版。
2. 【已定案】宏观地图使用从左到右的 DAG。上下分支只表示路线选择，不对应物理房间的上门或下门。
3. 【已定案】保留狼人、法师、弓箭手三种职业角色；旧“战士”由“狼人”完整替代。
4. 【已定案】角色功能与职业功能合并。选择一个职业角色，同时确定外观、基础属性、武器池、技能、动画、专属构筑标签和终极能力。
5. 【已定案】刺刀是狼人的基础武器；怒痕充满后按 Q 发动大招，狼爪在大招期间直接替换刺刀，并切换攻击动画、判定与招式组。大招结束后恢复刺刀。
6. 【已定案】狼人保留“怒痕条”，其唯一职责是大招充能：随时间缓慢恢复，造成伤害时加快恢复；充满后按 Q 兽化。首轮用视角左下角黄条占位。
7. 【已定案】角色与武器绘制在同一套 Sprite/序列帧中；身体碰撞、受击 Hurtbox 和攻击 Hitbox 仍独立。
8. 【已定案】后续序列帧统一使用 Unity Animation 与 Animator；停止扩建 FrameAnimator 和 WeaponPivot 旧链。
9. 【已定案】狼人的现有美术素材保留。其余现有美术暂时作为占位资源继续使用，后续按系统逐批替换，不在本轮清理中删除。
10. 【已定案】局外成长以内容解锁为主，不制作永久攻击、生命、移速百分比技能树。
11. 【已定案】统一货币名为“星蓝币”，分为局内随身钱包与守灯厅封存钱包两种状态。
12. 【已定案·测试基线】首轮只实现左右攻击；房内移动仍为二维自由。该方向在完成手感测试后再决定是否长期锁定。
13. 【已定案】空格闪避、F 小技能、Q 大招/兽化；旧 T 变身入口停止使用。
14. 【已定案·测试值】星蓝币按死亡 30%、安全撤离 60%、击败 Boss 100% 进行首轮测试。

## 1. 项目定义

### 1.1 一句话概述

《无名之地》是一款面向 PC、使用 Unity 制作的 2D 俯视角房间制 Roguelite：玩家选择职业角色，在横向长房间中进行二维自由战斗，通过不可回退的 DAG 路线持续向右深入，以局内构筑应对风险节点与 Boss，并在多轮探索中拼合失落世界的真相。

### 1.2 核心体验公式

职业角色差异化战斗 + 俯视角二维走位 + 横向单向推进 + DAG 路线决策 + 局内随机 Build + 风险收益 + Boss 检验 + 多周目叙事揭示。

### 1.3 核心卖点

- “二维自由战斗，一维宏观推进”：保留俯视 ARPG 的走位深度，同时形成持续向右的闯关压迫感。
- 路线与房间解耦：地图负责战略选择，实体房间负责即时战斗，分叉不会制造四向迷宫。
- 职业角色即完整战斗身份：不是换色和基础数值，而是外观、武器、技能、节奏与 Build 一起改变。
- 房间不是统一锁门竞技场：以推进段、战斗段、地形段和奖励段组合成 1～3 屏宽的小型关卡。
- 选择可描述的 Build：玩家结束一局时应能说出“这一局是流血刺刀、兽化狼爪或某种元素/暴击流”。
- 叙事与重复游玩结合：同一地点、角色和文本在后续 Run 中获得新的解释。

### 1.4 目标玩家

- 喜欢《哈迪斯》《死亡细胞》《杀戮尖塔》等战斗、构筑或路线决策体验的玩家。
- 接受失败重开，但希望每局有明确成长、选择与新信息的玩家。
- 偏好中等操作门槛、清晰预警和强反馈，而非极端硬核弹幕或纯数值碾压的玩家。

### 1.5 平台、视角与项目规模

- 首发平台：【建议】Windows PC，键鼠优先，手柄在 Vertical Slice 补齐。
- 视角：2D Top-Down；房内二维自由移动。
- 团队：个人/小团队，优先复用数据结构、房间模板和动画时序。
- 引擎基线：Unity 6、URP 2D、Input System、DOTween。
- 单局时长：【建议】MVP 10～15 分钟；Vertical Slice 20～30 分钟；正式单区域 30～45 分钟。最终值以实测为准。

### 1.6 非目标

- 不做上下左右实体房间迷宫。
- 不做角色与独立武器 Sprite 围绕鼠标持续旋转的攻击表现。
- 不靠大量永久百分比加点代替局内构筑。
- 不在 MVP 同时完成三个职业、五个区域和完整叙事。
- 不为每把同类武器制作完全不同的骨架与攻击逻辑。

## 2. 世界观与叙事框架

### 2.1 开场

主角在没有记忆的状态下醒来，身上只保留一枚标有“VII”的徽章。一个身份不明的女性声音不断引导主角：“去最深处。”玩家最初不知道她的目的，也不知道“VII”代表实验序号、骑士编号、封印层级还是另一种身份。

### 2.2 世界区域顺序

正式版区域按叙事与难度逐步揭示：

1. 荒废边境
2. 旧王国遗迹
3. 月蚀监牢
4. 封印区
5. 钟声之井

首个 Vertical Slice 只制作“荒废边境”，其 Boss 为“失落守门人·格兰”。

### 2.3 叙事投放

- 必得碎片：确保每局至少获得一条关键进展，避免剧情完全依赖随机。
- 随机文本：日志、刻痕、遗物说明和事件对话，用于补充世界细节。
- 玩法事件：敌人、Boss、房间机关和奖励选择本身承担叙事。
- 多局重释：新信息让旧文本产生不同含义，而非单纯重复播片。
- Boss 叙事：Boss 身份、机制和掉落必须与区域主题相互解释。

### 2.4 守灯厅

“守灯厅”是可步行的局外据点，不只是菜单。它承担职业角色选择、内容解锁、图鉴/档案、设置、出发和回收星蓝币等功能。MVP 可先用精简准备空间代替，Vertical Slice 再形成完整据点动线。

## 3. 完整游戏流程

标题界面 → 进入守灯厅 → 选择职业角色 → 确认初始装备/解锁内容 → 开始探索 → 生成本层 DungeonGraph → 查看路线 → 选择下一节点 → 加载对应横向房间 → 战斗/事件/商店 → 获得奖励 → 调整 Build → 完成节点 → 继续选择路线 → Boss → 结算 → 星蓝币封存与内容解锁 → 返回守灯厅。

核心短循环为：战斗 → 选择 → 奖励 → 构筑 → 风险决策。

### 3.1 不可逆规则

- 已完成的 DAG 节点不能回到上层。
- 完成当前节点后，只能从 `NextNodeIds` 中选择一个节点。
- 允许在当前物理房间内有限向左移动，但不得重新进入上一节点。
- 商店购买、事件选项、奖励选择和消耗行为即时生效。
- 【建议】每次完成节点并完成奖励选择后保存，防止通过强退反复刷结果。

## 4. 核心空间：微观二维，宏观一维

### 4.1 两个空间尺度

- 宏观层：DungeonGraph，负责节点类型、分叉、汇聚、风险和不可逆路线。
- 微观层：实际横向房间，负责移动、战斗、地形、奖励和镜头。

DAG 地图上节点的上下位置只是可视化排布，不映射实体世界的门向。任何节点被选中后，玩家仍从房间左侧进入并从右侧离开。

### 4.2 轴向职责

- X 轴：推进、敌我前后距离、镜头移动、入口出口、远近阵型。
- Y 轴：闪避、绕后、拉扯、弹幕规避、突破阵型、利用掩体。

### 4.3 房间尺寸与形状

- 普通房优先长矩形，推荐可玩区域长宽比 2.2:1～4:1。
- 房间长度约 1～3 个屏幕，Vertical Slice 以 1.5～2.5 屏为主。
- Y 轴不能窄到退化成一条直线；至少容纳玩家、近战敌人和一条规避通道。
- Boss 房可更宽，但仍只有左入口和战后右出口。

### 4.4 房间内部节奏

房间可从以下段落中选取 2～4 个组合：

- 入口缓冲段
- 小规模接触战
- 地形/机关段
- 主战斗段
- 强敌或精英段
- 奖励与出口段

不是每个房间都锁门。可使用软锁、击破关键敌人、局部闸门、持续推进、追逐、护送、占点或机关作为推进条件。

### 4.5 房间模板族

- 狭长推进：前排阻挡、后排远程，强调突破。
- 宽阔交战：较大 Y 轴空间，强调包抄和范围规避。
- 掩体走廊：远程火力与移动路径选择。
- 危险地面：安全区随时间或机制变化。
- 上下夹击：敌人从 Y 轴边缘进入，但不生成上下出口。
- 追逐/逃脱：战斗与向右移动同时发生。
- 精英关卡：独立机制与局部镜头锁定。
- Boss 仪式厅：固定结构、清晰登场与阶段空间。

### 4.6 横向特色验收

随机抽取五个普通房，至少四个必须满足：镜头产生明显横移；敌人或目标位于前方；玩家需要跨越空间而非原地等刷；结束位置比开始位置显著靠右。若多数房间仍是“一屏锁门清怪”，空间特色视为失败。

## 5. 操作、移动与攻击

### 5.1 基础操作建议

- WASD：二维移动
- 鼠标左键：普通攻击
- 空格：闪避/冲刺
- F：小技能
- Q：大招/狼人兽化（怒痕充满后可用）
- E：交互/拾取
- Esc：暂停/关闭顶层界面

旧 T 兽化入口在新版停用；狼人变身统一由 Q 触发。R 武器技能与 C 道具键不进入首轮 MVP，是否恢复在相应系统设计时再定。

### 5.2 移动与闪避

- 移动必须支持八方向输入，不限制上下移动。
- 闪避提供短位移和短暂无敌帧；位移、无敌和冷却由数据定义。
- 攻击中的移动减速或踏步由 AttackDefinition 控制，不能散落在角色脚本中。
- 玩家离开房间可走区域时由 Movement Collider 与 Room Bounds 双重限制。

### 5.3 【已定案·测试项 T-01】首轮仅左右攻击

首轮采用仅左右攻击：普通攻击和近战技能只生成左向或右向 AttackDefinition/Hitbox，不生成上、下攻击。

键鼠测试规则：以鼠标世界坐标相对角色的 X 轴正负决定攻击方向；鼠标在角色右侧则向右，左侧则向左。Y 轴只影响移动与走位，不参与攻击方向计算。无有效瞄准输入时沿用角色最后水平朝向。

选择理由：

- 优点：最接近横向闯关，动画量最低，刺刀方向清楚。
- 缺点：与二维自由移动冲突较大，Y 轴敌人可能只能靠对线处理。
- 成本：低。
- 扩展性：较低。

备选方案 B：四方向离散攻击。

- 优点：保留俯视走位价值，不需要鼠标旋转武器；可复用左右镜像，上下各一套。
- 缺点：动画量高于左右攻击，需处理方向锁定与转向窗口。
- 成本：中。
- 扩展性：高。

备选方案 C：八方向或 360° 瞄准。

- 优点：操控最自由，远程职业自然。
- 缺点：极易回到旧元气骑士式视觉与操作，动画/判定复杂度最高。
- 成本：高。
- 扩展性：中。

【测试门禁】v2.0.1 只制作左右攻击灰盒，不同时开发四方向版本。重点记录 Y 轴接敌、攻击落空率、敌人对线时间和横向推进感。如果左右攻击无法充分利用俯视空间，再由用户确认是否开启四方向备选测试；在首轮结论前不量产最终攻击 Sprite。

### 5.4 攻击阶段

每次攻击统一为：输入缓存 → 前摇 → 有效帧 → 后摇 → 可取消窗口。预警、动画事件、Hitbox、伤害、位移和反馈全部读取同一 AttackDefinition。

可见武器像素不是命中判定真源。判定几何必须可在 Scene 视图调试，并和有效帧严格同步。

### 5.5 战斗节奏

- 普通战平均 20～45 秒，主战段不超过 60 秒。
- 玩家需要在攻击距离、前摇和安全位置之间做选择。
- 敌人预警必须先于伤害；强攻击有更长前摇和更强反馈。
- 同屏威胁来自职责组合，而非单纯增加数量和血量。

## 6. 职业角色系统

### 6.1 单一身份模型

新版只存在 `PlayableCharacterId` 和 `PlayableCharacterDefinition`。不再同时维护独立 CharacterId 与 ClassId。

选择职业角色一次性确定：

- 名称、头像、角色 Sprite 与 Animator
- 基础属性和移动参数
- 可用武器类型与初始武器
- 普通攻击模组
- 职业技能与大招
- 专属构筑标签与奖励权重
- 音效、特效、受击与死亡表现

### 6.2 狼人【首个完整职业】

定位：近中距离、持续压制、突进穿刺、兽化爆发。

常态：

- 基础武器：刺刀，直接绘制在狼人常态角色动画中。进入地牢、复活和大招结束时默认恢复刺刀。
- 主要手感：快速突刺、横扫补击、短踏步、弱点/流血联动。
- 优势：贴近目标后连续压制，单体和小范围兼顾。
- 风险：攻击前后存在方向承诺，需要通过 Y 轴走位寻找切入线。

大招：

- 怒痕充满后按 Q 进入兽化，狼爪在大招持续期间直接替换刺刀。
- 狼爪不是独立装备、第二武器槽、掉落武器或可永久替换的基础武器，而是狼人专属大招形态。
- 切换独立攻击招式、Hitbox 几何、伤害标签和反馈。
- 狼爪偏高速、短距、多段与流血；不能只是刺刀数值乘倍。
- 大招结束后完整恢复刺刀 Animator/Attack Set/碰撞状态。
- 怒痕条是大招充能条，充满后按 Q 进入兽化；发动时消耗整条怒痕。
- 怒痕随时间缓慢恢复；玩家造成有效伤害时获得额外恢复。时间恢复速度和伤害转化比例均数据化，首轮灰盒后调参。
- 未满时按 Q 不发动大招，并给予短促的“怒痕不足”UI/音效反馈，不吞掉移动或普通攻击输入。

首批构筑方向：

- 穿刺弱点：刺刀直线命中、背击或破甲后提高单体输出。
- 流血猎杀：多次命中叠流血，对流血目标获得追击收益。
- 兽化爆发：强化狼爪持续时间、攻速、连斩或结束技。
- 残血处决：对低生命敌人触发处决或延长兽化收益。

### 6.3 法师

定位：中远程、元素组合、范围控制和爆发。核心差异必须来自施法节奏与元素联动，而非只把刺刀换成远程弹丸。

【建议】使用有限法术槽与冷却组合，不在 MVP 制作完整法力资源生态。可在 Vertical Slice 只完成定义、选择界面占位和 Build 标签，不进入可玩内容。

### 6.4 弓箭手

定位：远程机动、蓄力弱点、连续命中和暴击。核心机制可围绕专注、完美蓄力或标记目标。

【建议】正式实现晚于狼人；先确保离散方向攻击不会破坏远程瞄准体验。

### 6.5 差异化验收

职业更换后，玩家的安全距离、优先目标、攻击窗口、技能节奏和理想奖励至少有三项明显变化；否则不算完成职业差异化。

### 6.6 怒痕与大招循环【已定案】

- 怒痕范围建议规范化为 0～100，实际 UI 不显示数值文本，只显示填充比例。
- 被动恢复：战斗内随时间缓慢增长，避免低输出 Build 永久无法开大。
- 主动恢复：造成最终有效伤害后按伤害量或攻击定义提供额外怒痕，鼓励持续进攻。
- 防滥用：对无敌目标、场景物件和重复命中同一帧不增加怒痕；需要设置单帧/单次攻击上限。
- 充满反馈：黄条高亮、狼头徽记或边框脉冲，并提供一次提示音。
- 发动：按 Q 消耗整条怒痕并切换狼爪 Attack Set；大招期间是否暂停充能由首轮数值测试决定，默认暂停。
- 结束：恢复刺刀形态；死亡、重生、返回守灯厅和新 Run 必须重置怒痕状态。
- 旧 WerewolfEnergy/WerewolfEnergyBar 可作为迁移起点，但命名、事件来源、UI 位置和 Q 输入必须按本节统一。

【待定参数 T-02】被动每秒恢复量、每点伤害对应恢复量、满怒初始策略、兽化持续时间，以及兽化期间是否允许继续积累怒痕。它们是数值参数，不再影响“使用怒痕条”的系统决策。

## 7. 武器、美术与动画

### 7.1 武器规则

- 每个职业只使用一个或少数指定武器类型。
- 同一武器类型共享攻击节奏、帧数、判定窗口和 Animator 状态结构。
- 同类武器通过基础数值、品质、元素、词条、特效和 Build 联动形成差异。
- 狼人常态武器池只产生刺刀类基础武器；狼爪是怒痕充满后临时替换刺刀的职业大招形态，不作为掉落、商店商品或第二武器槽内容。

### 7.2 一体化 Sprite

武器直接画入角色序列帧。更换刺刀时，可替换同帧结构的 Animator Override Clips 或整套 Sprite；不再运行时挂载独立 WeaponPivot 旋转。

为控制资源膨胀：

- 每职业先固定一套基础动作时序。
- 同类武器优先换色、刀刃局部差异和特效，不无限增加独立动作。
- Vertical Slice 只做 3～5 把刺刀变体，共享完整动画拓扑。
- 狼爪只做一套正式大招形态，变体主要来自 VFX 与构筑。

### 7.3 碰撞职责

- Movement Collider：墙体和实体移动阻挡。
- Body Hurtbox：角色受伤范围。
- Attack Hitbox：只在攻击有效帧启用。
- Interact Trigger：交互检测。

武器像素被画进 Sprite 不得扩大 Body Hurtbox。狼爪形态可改变 Attack Hitbox，但默认不改变身体受击范围；若确需改变，必须在 AttackDefinition/形态定义中显式配置并测试。

### 7.4 Animator 规范

- 新动画统一使用 AnimationClip、Animator Controller 和 Animator Override Controller。
- Animator 参数使用集中常量或哈希，不在 Update 中反复拼接字符串。
- 攻击有效帧通过 Animation Event 或统一状态回调驱动，同一攻击不得存在第二套独立计时真值。
- 形态切换必须原子完成：视觉、攻击定义、状态标签和 VFX 同帧切换。
- FrameAnimator 和旧 WeaponPivot 只允许修复迁移阻断，不添加新功能。

### 7.5 美术保留策略

- 狼人素材：保留，作为正式候选资源逐项清点、统一 PPU/Pivot/切片与命名。
- 其他现有素材：暂时使用，全部标记为占位；有替代品且引用迁移完成后再归档。
- 禁止仅凭“看起来没用”删除 Sprite、AnimationClip、Animator、Prefab 或材质。
- 替换按角色、敌人、房间、UI 四批进行，每批要求引用扫描、场景重载和构建验证。

## 8. 局内 Build

### 8.1 构筑层次

- 职业角色：决定规则边界和奖励权重。
- 武器：决定基础攻击数值、元素和少量核心词条。
- 职业能力升级：改变技能或大招行为。
- 遗物：提供规则联动和跨系统触发。
- 状态效果：连接攻击、敌人和奖励。

### 8.2 首批状态

- 流血：叠层持续伤害，狼人核心标签。
- 破甲：降低护甲或提高后续伤害，服务刺刀穿刺。
- 点燃：法师后续核心标签。
- 冰缓：移动/攻击节奏控制。
- 标记：弓箭手后续弱点目标。

MVP 只实现流血与破甲，避免状态系统过早膨胀。

### 8.3 随机性控制

- 奖励池按职业标签、已有 Build 标签和通用池加权。
- 每次三选一至少保证一个与当前 Build 有关联的选项。
- 连续两次没有关联项时触发保底。
- 重复遗物要么升级，要么不进入池。
- 商店提供一次刷新或锁定选项，价格随刷新次数上涨。

### 8.4 奖励节奏

不是每个战斗段都弹三选一。建议普通节点末尾提供一次主要选择，中间小战斗直接掉落星蓝币、恢复或临时消耗品；精英和 Boss 才提供高价值选择。

---

## 9. 敌人、精英与 Boss

### 9.1 基础生态

- 近战阻挡者：占据 X 轴前线，迫使玩家选择突破位置。
- 后排远程：从前方或斜线施压，迫使玩家使用 Y 轴规避。
- 冲锋敌人：横向封锁并迫使上下闪避。
- 区域控制者：制造危险地面或限制安全区。
- 防御/支援者：保护后排、强化队友或打断玩家连击。

### 9.2 组合原则

一个遭遇由 2～3 种职责组成；同屏高威胁攻击必须有可读的时间错峰。远程敌人不应永远刷在玩家身后，主要压力来自右侧前方阵型。

### 9.3 精英

精英不能只增加生命和攻击。每个精英至少新增一个行为、一个场地交互或一个会改变优先级的规则，并提供明显高于普通节点的奖励。

### 9.4 Boss：失落守门人·格兰

Vertical Slice Boss 负责检验：横向位移、Y 轴规避、攻击窗口识别、Build 伤害闭环和资源管理。

【建议】三段结构：

1. 守门：正面封锁与宽范围挥击，教授绕侧和等待窗口。
2. 追猎：冲锋和地面路径切割，迫使上下走位。
3. 失控：组合前两阶段并缩短安全窗口，但保持预警可读。

Boss 奖励同时提供阶段性叙事碎片和高价值内容解锁。

---

## 10. DAG 地图与节点

### 10.1 数据模型

`DungeonGraph` 与 `DungeonNode` 是纯 C# 数据，不依赖场景 GameObject。节点至少包含：

- NodeId、NodeType、Column、MapPosition
- PreviousNodeIds、NextNodeIds
- Generated、Discovered、Visited、Completed
- RoomArchetypeId、RewardSeed、EncounterSeed

`Generated` 表示数据已生成；`Active` 只属于房间运行实例；`Discovered/Visited/Completed` 不因房间 GameObject 卸载而丢失。

### 10.2 生成约束

- 有且只有一个起点和一个 Boss 终点。
- 所有节点从起点可达，且至少存在一条到 Boss 的路径。
- 只允许从较小列指向较大列，禁止环。
- 支持分叉、汇聚、再次分叉。
- 同一路线避免连续三个纯战斗节点。
- 商店、恢复、精英和宝箱设置最小间距与层数门槛。
- Boss 前至少提供一个可规划的恢复或商店机会，但不保证免费恢复。
- 图生成后先验证，再交给 UI 与房间系统。

### 10.3 节点类型

- 普通战斗
- 精英战斗
- 宝箱/奖励
- 商店
- 随机事件
- 恢复/休息
- Boss

### 10.4 初始权重建议

普通战斗 45%、事件 15%、商店 10%、宝箱 10%、恢复 10%、精英 10%；Boss 由结构固定，不参与随机权重。实际概率需服从层数门槛、最小间距、路径保底和内容池去重。

### 10.5 地图揭示【已定案】

采用“完整连接可见、部分节点类型未知”：玩家能规划分叉和汇聚，但部分事件/奖励节点以未知图标出现。已完成路线、当前节点和可选下一节点必须有明确视觉状态。

### 10.6 地图规模

- MVP：5～7 列，每列 1～2 节点。
- Vertical Slice：10～12 列，每列 1～3 节点。
- 正式版：按单局时长和区域节奏调整，不用单纯增加列数延长游戏。

## 11. 房间生成与管理

### 11.1 节点进入流程

选择节点 → RoomManager 读取节点与 RoomArchetype → 生成或激活 RoomPlan → 验证入口到出口可达 → 设置 Player Spawn 与 Camera Bounds → 开始内容 → 完成条件达成 → 结算奖励 → 标记节点完成 → 开启右出口 → 回到 DAG 选择。

### 11.2 RoomPlan

RoomPlan 必须先生成并验证，再一次性绘制。内容包括：

- 可走区域和实体墙
- 左入口、右出口
- 相机边界
- 障碍岛与危险地面
- 玩家、敌人、奖励与交互物候选点
- 战斗分段和软锁触发区

入口到出口按玩家碰撞体尺寸验证可达；敌人和奖励只能从最终 SpawnCells 取点。任何失败尝试不得污染最终地图。

### 11.3 装载策略【建议】

MVP 同场景只保留一个 Active 房间，节点完成后淡出/过渡并重建。Vertical Slice 再评估对象池或预加载相邻房间。不要在验证玩法前搭建复杂无缝世界流送。

---

## 12. 镜头

首版使用玩家跟随 + 当前 Room Bounds 限制：

- 房间中段平滑跟随玩家。
- 接近左右边缘时不越过房间边界。
- 长房间随玩家向右横移，强化推进感。
- 进入新节点时短暂过渡，切换 Bounds 后恢复跟随。
- 主战/精英可短时锁定局部 Bounds，但不强制所有房间锁屏。

后续扩展：Boss 锁镜、Camera Shake、重击/受击反馈、登场镜头、击杀慢动作。优先保证跟随稳定、不露地图外、不引发晕动。

## 13. 星蓝币、奖励与商店

### 13.1 双钱包

货币统一叫“星蓝币”，但存在两个存储状态：

- 随身钱包：当前 Run 内获得并用于商店；死亡会损失一部分。
- 守灯厅钱包：已封存，不因局内死亡丢失，用于内容解锁。

【已定案·首轮测试值】死亡带回随身余额的 30%；主动安全撤离带回 60%；击败区域 Boss 带回 100%。这些比例仍须数据化，不写死在 UI 文案；测试后可按经济节奏调整。

### 13.2 奖励来源

- 普通战：基础星蓝币、少量恢复、小概率普通强化。
- 精英：高级遗物、职业强化或稀有刺刀。
- 宝箱：稳定提供一次主奖励。
- 商店：武器、遗物、恢复、刷新。
- 事件：明确展示选择、风险和可能收益范围。
- Boss：区域核心奖励、叙事碎片和内容解锁。

### 13.3 商店规则

价格按奖励稀有度和当前层数缩放；禁止同一商店全部商品与当前职业不兼容。Vertical Slice 只做购买和一次刷新，不做复杂议价、出售或商店声望。

---

## 14. 生命、恢复、失败与通关

- 生命跨节点保留，形成路线风险。
- 恢复来源受限：恢复节点、商店、少量事件和特定 Build。
- 普通房不自动回满。
- 死亡结束当前 Run，按规则结算随身星蓝币和解锁进度。
- 击败 Boss 完成本区域，结算全部随身星蓝币并返回守灯厅。
- 不提供无限原地复活；若未来加入复活，必须作为稀有局内效果。

---

## 15. 局外成长、难度与重复游玩

局外成长以内容解锁为主：新职业角色、新刺刀/武器、新遗物、新事件、新敌人、新区域、新 Boss、新难度和新 Build 标签。

不制作永久攻击 +5%、生命 +10% 之类的通用技能树。若需要新手缓冲，可通过首局保护、默认恢复次数或逐步开放内容池解决。

难度系统在 Vertical Slice 后设计，优先使用规则变化：敌人招式、精英词缀、资源压力、路线风险和 Boss 组合，不只做生命与伤害倍率。

---

## 16. UI / UX

### 16.1 HUD

MVP 必需：生命、护甲、怒痕、技能冷却、交互提示、随身星蓝币和当前主要状态效果。

- 怒痕条固定在视角左下角，首轮使用黄色填充占位；它跟随屏幕 UI，不随世界坐标移动。
- 怒痕条只表示狼人 Q 大招充能；满条提供清晰高亮，发动后归零。
- 右下角技能/物品槽不显示技能名称，避免文字拥挤。
- 每个技能槽保留技能图标与按键提示；冷却期间在图标上显示剩余秒数读秒，并配合遮罩。
- 读秒建议大于 1 秒显示向上取整整数，最后 1 秒可显示一位小数；冷却完成后隐藏数字并短暂高亮。
- F 小技能和 Q 大招都遵循上述槽位规则；Q 未满怒时显示不可用状态，而不是伪造固定冷却。

### 16.2 DAG 大地图

显示列、连接、已完成路径、当前节点、可选节点和已揭示类型；不可选节点必须说明原因。路线选择应在 3～8 秒内完成，避免频繁拖慢节奏。

### 16.3 小地图

只显示当前节点、已完成节点与下一层候选。当前房间内部不必制作复杂迷雾地图，因为空间是横向小关卡。

### 16.4 可读性

- 敌我攻击色彩和预警层级一致。
- 交互、选择和战斗输入不争抢焦点。
- 键鼠与手柄提示从 Input System 绑定读取，不写死多份文本。
- 状态、词条和奖励使用统一术语库。

---

## 17. 音效与战斗反馈

命中、受击、破甲、暴击、击杀、刺刀突刺、狼爪连斩、兽化开始/结束需要不同层级反馈。反馈强度遵循：普通命中 < 重击/破甲 < 精英击杀 < Boss 阶段与终结。

Hit Stop、Camera Shake、闪白和音效必须可独立调参，并避免同帧叠加失控。音乐按守灯厅、普通探索、精英、Boss 和结算分层；Vertical Slice 只要求每类一条可用主题。

---

## 18. 基础数值框架

数值目标先定义关系，不提前堆大量表格：

- 普通敌人承受 3～8 次基础攻击死亡。
- 普通敌人有效攻击命中玩家约造成最大生命 8%～15%。
- 精英战 30～75 秒，Boss 3～5 分钟。
- 常态刺刀与狼爪大招的理论输出差需要体现在范围、节奏和风险，不只体现在倍率。
- 高品质武器应改变构筑选择，纯攻击力提升不超过其价值的一半。

所有伤害、状态、冷却、房间权重和经济比例使用数据资产或配置，不散落魔法数字。

## 19. Unity 技术落地

### 19.1 场景建议

- Bootstrap：持久服务、存档、音频和全局初始化。
- Title：标题与存档入口。
- Hub：守灯厅、职业角色选择和内容解锁。
- Run：DAG、房间与战斗运行场景。
- Ending：区域完成与正式结局表现；MVP 可先用结算 UI。

### 19.2 核心模块

- GameSession / SaveService：会话、配置和存档。
- PlayableCharacterService：职业角色选择、定义和实例装配。
- RunManager：Run 生命周期、当前节点、种子和结算。
- DungeonGraphGenerator：纯数据 DAG 生成与验证。
- RoomManager：RoomPlan、房间实例、边界、过渡和完成条件。
- Combat：AttackDefinition、Hitbox、伤害、状态与反馈。
- RewardService / EconomyService：奖励池、星蓝币、商店和封存。
- NarrativeService：必得碎片、随机文本和进度条件。
- Audio / VFX / Camera：表现层服务。

### 19.3 关键数据资产

`PlayableCharacterDefinition`、`WeaponDefinition`、`AttackDefinition`、`SkillDefinition`、`RelicDefinition`、`StatusEffectDefinition`、`EnemyDefinition`、`EncounterDefinition`、`RoomArchetypeDefinition`、`NodeRewardDefinition`、`NarrativeFragmentDefinition`。

运行时纯数据包括 `DungeonGraph`、`DungeonNode`、`RoomPlan`、`RunState`、`WalletState`。ScriptableObject 不直接保存单局可变状态。

### 19.4 通信与生命周期

- 系统通过明确接口或事件通信，事件订阅/退订成对。
- 玩家死亡走受控状态切换或 Respawn，不依赖销毁重建修复状态。
- 协程、Tween 与形态切换互斥并绑定对象生命周期。
- 高频物理查询使用 NonAlloc 和复用缓冲；缓存 GetComponent；Update 中禁止 LINQ 与字符串分配。

### 19.5 存档

存档至少分为：

- Profile：设置、守灯厅星蓝币、内容解锁、叙事进度、统计。
- ActiveRun：种子、职业角色、Build、生命、随身星蓝币、DungeonGraph 状态、当前节点。

【建议】节点完成与奖励确认后保存 ActiveRun；进入战斗后异常退出恢复到该节点入口，但不重新随机奖励。

## 21. 开发阶段

### 21.1 【MVP / 首个可玩版本】

目标：验证“俯视二维战斗 + 横向推进 + 刺刀/狼爪形态切换 + 基础房间奖励”是否好玩。

范围：

- 1 个职业角色：狼人。
- 1 把基础刺刀，1 套狼爪大招，1 套怒痕充能循环。
- 2 种状态：流血、破甲。
- 2～3 种基础敌人，1 种简化精英。
- 3～5 个横向房间模板，5～7 列小 DAG。
- 战斗、奖励二选一/三选一、节点切换、死亡结算。
- Camera Follow + Room Bounds + Transition。
- Animator 攻击、受击、死亡、刺刀/狼爪切换。

最高优先级：仅左右攻击手感、刺刀/狼爪差异、怒痕获取节奏、Y 轴对线与闪避价值、房间横移节奏。

本阶段不做：法师/弓箭手实装、完整守灯厅、复杂商店、事件库、永久解锁树、五区域、无缝流送、正式结局。

### 21.2 【Vertical Slice / 垂直切片】

目标：形成从守灯厅选择职业角色到击败格兰并结算的完整小型游戏。

推荐内容：

- 狼人完整可玩；法师和弓箭手只做后续入口展示或设计定义。
- 3～5 把刺刀变体，共享动作拓扑。
- 12～18 个遗物/强化，至少 3 条可成型狼人 Build。
- 4 种普通敌人、1～2 种精英、1 个 Boss。
- 8～12 个房间模板，10～12 列 DAG。
- 普通、精英、奖励、商店、恢复、事件、Boss 节点。
- 荒废边境完整美术语汇、守灯厅基础功能、星蓝币双钱包。
- 大地图、小地图、存档、设置、音频和必要新手引导。
- 单局 20～30 分钟。

本阶段不做：第二完整区域、三个职业全部成品、大型天赋树、大量武器动画、每日挑战、在线功能、复杂成就平台接入。

### 21.3 【正式版本】

在 MVP 与 Vertical Slice 数据证明核心成立后扩展：

- 狼人、法师、弓箭手三个完整职业角色。
- 五个区域及各自敌人、精英、Boss、事件和叙事。
- 完整武器、遗物、状态与职业 Build 池。
- 内容解锁、难度规则、多周目叙事和图鉴。
- 手柄、可访问性、性能优化、完整音画和平台功能。

正式版内容数量只在生产速度、复用率和单局重复度经过 Vertical Slice 实测后锁定。

## 23. 验收与测试

### 23.1 自动测试

- DungeonGraph：无环、可达、唯一 Boss、路径和节点约束。
- RoomPlan：入口到出口按玩家尺寸可达，SpawnCells 合法。
- AttackDefinition：前摇/有效帧/后摇、Hitbox 窗口和伤害标签一致。
- PlayableCharacter：唯一 ID、武器兼容、Animator Override 完整。
- Save：Profile/ActiveRun 往返、版本迁移、奖励 seed 不重掷。
- Economy：随身/封存钱包与死亡、撤离、Boss 比例。

### 23.2 人工体验测试

- 玩家是否自然向右移动，而非在入口原地等怪。
- Y 轴是否持续产生闪避和选位价值。
- 刺刀与狼爪是否在节奏、范围和风险上明显不同。
- 房间是否避免重复“一屏锁门”。
- 路线选择是否因生命、商店、精英和 Build 产生真实权衡。
- 20～30 分钟内能否形成可描述 Build。

### 23.3 技术门禁

- Unity Console 零编译错误；关键场景零 Missing Script。
- 场景和 Prefab 引用完整；只有一个激活 Player。
- 不通过移动摄像机或瞬移玩家伪造测试结果。
- 外部修改场景后 Reload 再 Play；不保存未授权调试对象。

## 24. 风险登记

- 空间退化：房间过短或总锁屏会失去横向特色。用横移距离与房间模板验收。
- 操作冲突：仅左右攻击可能浪费 Y 轴。首轮只测左右攻击，并记录对线时间、落空率和 Y 轴利用率；数据不达标再决定是否测试四方向。
- 美术膨胀：一体化武器会乘算动画量。限制同类武器动作拓扑和 Vertical Slice 数量。
- 职业膨胀：三个职业同时制作会拖垮垂直切片。先完整狼人，再扩展。
- 系统双轨：旧 Character/Class、Animator/FrameAnimator 共存会持续制造 bug。按版本迁移并设停止扩建红线。
- 随机失控：纯随机奖励可能无法成型。使用标签加权、关联保底和有限刷新。
- 内容稀释：房间和敌人数量多但职责相同。用组合价值与复用测试代替数量指标。
