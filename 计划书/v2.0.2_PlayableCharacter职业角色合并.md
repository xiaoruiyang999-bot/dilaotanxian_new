## 本版目标

把旧的“角色外形 + 职业”两次选择合并为一次职业角色选择。运行时不再同时保存 CharacterId/ClassId，而是只保存 PlayableCharacterId，所有配置由 PlayableCharacterDefinition 派生。

## 已完成

- 新增稳定枚举 PlayableCharacterId 与构建安全的 PlayableCharacterCatalog。
- 扩充 PlayableCharacterDefinition：统一身份、颜色、基础属性、兼容武器池、基础武器、技能、怒痕、普攻和动画目录合同。
- 把旧战士数值迁入狼人：HP 130、护甲 70、法力 100、移速 5、攻击 40、暴击 10%、暴伤 1.5、护甲减伤 0.4、护甲损耗 1。
- 把旧战士两把可用武器迁为狼人“基础刺刀（灰盒）”与“备用短刃（灰盒）”；基础刺刀作为选择、死亡复活后的默认武器。
- 旧战士技能资产保持 GUID 原位迁移为 Werewolf 命名，并接入狼人定义；技能内容本版只迁移，不重新平衡。
- RunStateCarrier、PlayerStats、SkillExecutor、武器拾取、宝箱奖励、准备房、地牢入口和死亡复活全部切到职业角色单一真值。
- CharacterSelectUI 变为唯一选择页；旧 ClassSelectUI、ClassData、ClassCatalog、ClassType 与三份旧职业资产在清除引用并通过回归后删除。
- 准备房选择台由三色职业棱晶改为单一狼人棱晶。

## 关键运行合同

1. RunStateCarrier 只持有 ChosenPlayableCharacterId，不缓存第二份职业或外形身份。
2. 武器兼容性只由 PlayableCharacterDefinition.AvailableWeapons 判断，WeaponData 不再保存 requiredClass。
3. 选择职业角色是一个事务：写入 ID → 应用属性 → 应用外形/能力 → 装备基础武器 → 刷新展台。
4. 死亡保留职业角色，并恢复该定义的基础武器。
5. 当前 Catalog 只发布狼人；法师、弓箭手不得用旧 ClassData 临时接回。

## 追加批次：横向战斗适配（已完成）

### 问题背景

当前敌人仍沿用旧俯视自由朝向风格：移动或追踪目标时会旋转整个身体，远程预警还能在前摇期间持续转向；近战预警、攻击触发距离与实际 `WeaponHitbox` 也存在多套几何入口。玩家 Dash 则把输入向量归一化后统一按同一速度与时长移动，X/Y 位移没有差异。这些行为与“横向长、纵向窄、敌我主要左右攻击”的 V2 空间合同不一致。

本追加批次只修正敌人战斗/移动合同与玩家 Dash，不扩展敌人数量、不制作正式敌人美术、不提前进入 v2.0.3 狼人 Animator 量产。

### 一、敌人攻击方向

1. 有明确方向的敌人攻击默认只允许 `Left`、`Right` 两种离散方向，不再沿任意二维向量旋转攻击。
2. 攻击开始时按目标相对敌人的 X 轴正负确定方向；X 差值进入死区时沿用敌人最后一次有效水平朝向。
3. 方向在进入前摇时锁定，并由预警、动画、位移、Hitbox、伤害和反馈共同消费；前摇期间不再跟随玩家连续转向。
4. 玩家可以在前摇后通过 Y 轴换线离开攻击带；敌人不得在有效帧到来时重新瞄准或把判定吸附到玩家当前位置。
5. 普通近战、远程投射物、冲锋、精英和 Boss 的所有有方向攻击均纳入左右限制；召唤和以自身为中心的无方向效果例外。
6. 个别技能或攻击允许跨 Y 轴影响多个横向攻击带，但必须通过该招式独立的 `laneWidth`/范围形状配置实现，不能恢复任意角度瞄准或旋转敌人身体。

### 二、预警范围与实际打击范围同源

每个敌人招式只允许存在一份攻击几何真值，至少包含：

- 水平朝向 `Left/Right`
- 判定起点/相对敌人的原点偏移
- X 轴攻击距离 `reach`
- Y 轴攻击带宽度 `laneWidth`
- 前摇、有效帧、后摇
- 需要位移时的位移曲线与停止条件

预警必须按这份几何绘制；有效帧 Hitbox 必须按同一原点、方向、距离和宽度检测。禁止使用“圆形预警 + 矩形伤害”“预警角度 + 武器独立宽度”或在显示后再次计算目标方向。

- 预警覆盖区域 = 有效帧可造成伤害的最大区域。
- 玩家留在预警外不得受该次攻击伤害；玩家在有效帧前离开预警区则本次攻击落空。
- AI 的攻击启动判定不得依赖大于真实打击范围的隐藏 `attackRangeBuffer`。接近/停步容差如需保留，只能属于移动决策，不能扩大预警或伤害。
- 冲锋若会沿路径持续造成伤害，预警必须覆盖锁定后的完整冲锋走廊；撞墙提前结束时实际范围可以缩短，但不能超出已显示区域。
- 冲锋使用可配置的 `chargeDistance` 作为无碰撞最大位移；预警 X 长度固定为 `chargeDistance + attackRange`，位移速度由该距离和 Active 时长推导，结束或撞墙时立即停速。
- 远程弹体预警显示锁定的水平弹道走廊；弹体尺寸、可达距离与碰撞层必须来自同一攻击配置。
- 允许跨 Y 轴的招式通过更大的 `laneWidth` 或明确的无方向范围形状扩展；预警仍须完整覆盖其实际伤害区域。

### 三、敌人移动与身体朝向

1. 敌人寻路仍可在房间内进行二维移动，以便追击、换线、绕障和返回巡逻点。
2. 普通移动方向不再写入敌人根节点 `Transform.rotation`；敌人身体始终保持世界 Z 轴旋转为 0，避免移动时斜转或倒转。
3. 攻击朝向只保存为独立的水平状态，不通过旋转整个敌人表达。
4. 视觉保持正立，只按最后水平朝向做左右镜像；“固定正方形”仅表示身体始终正立不旋转，不要求把 Movement Collider 或 Body Hurtbox 改为等宽等高。
5. 世界空间血条、预警和子节点不得继承移动方向旋转。

### 四、玩家八方向差异化 Dash

1. 输入不变：按住一个或两个 WASD 方向时按 Space，得到上、下、左、右及四个斜向，共八种 Dash。
2. Dash 使用离散输入，不按归一化向量乘统一距离；X/Y 两轴分别由数据定义位移。
3. 水平 Dash：`(±dashDistanceX, 0)`，其中 `dashDistanceX` 较长，用于推进、接近和拉开距离。
4. 垂直 Dash：`(0, ±dashDistanceY)`，其中 `dashDistanceY` 较短，用于快速换线和脱离横向攻击带。
5. 斜向 Dash：`(±dashDistanceX, ±dashDistanceY) × diagonalDistanceScale`，同时保留 X 长、Y 短的轴向比例，并用独立缩放避免斜向净位移过长。
6. 同轴反向键同时按下时该轴视为 0；若最终输入为 0，则默认沿最后一次有效水平朝向 Dash，避免 Space 无响应。
7. 位移过程不能穿越实体墙；继续使用连续碰撞或等价的高速移动防隧穿方案。
8. Dash 持续时间、冷却与无敌窗口继续数据化；修改位移比例不能隐式改变这些时间合同。

首轮值：`dashDistanceX = 3.0`、`dashDistanceY = 1.5`、`diagonalDistanceScale = 0.8`，斜向分量为 `(2.4, 1.2)`、净位移约 2.68；持续时间 0.15 秒、冷却 0.9 秒、结束后额外无敌 0.06 秒。以上数值全部集中在 `PlayableCharacterDefinition` 的“移动与闪避”分组，可直接在职业角色资产 Inspector 调整；运行时 Dash 组件只消费配置快照，不另存第二套可编辑真值。

5. 新增左右边界、Y 带宽、原点近界、冲锋走廊及 Dash 轴向/斜向/无输入兜底测试。

### 验收标准

- 任取左、右攻击各一次，预警矩形与实际命中矩形的原点、长度、宽度和方向一致。
- 玩家在前摇期间跨出攻击带后不受伤；敌人不会在有效帧重新转向追踪玩家。
- 敌人向任意二维方向移动时，根节点和身体视觉不发生 Z 轴旋转。
- 左右远离、上下换线和四个斜向 Dash 均可由 WASD + Space 稳定触发。
- X 轴 Dash 明显长于 Y 轴 Dash；斜向结果保持两轴比例并受独立缩放控制，不超过水平 Dash。
- Dash 不穿实体墙，死亡/复活、切换职业角色和离开运行入口后不残留冲刺或无敌状态。
- Unity Console 无新增错误；敌人攻击、Dash 定向测试与 Missing Script 检查通过。

### 审核结论（2026-09-10）

1. 玩家仅左右攻击升级为 V2 最终定案，不再保留四方向/360°作为当前实施备选。
2. 所有有方向的敌人攻击均为左右攻击；召唤和自身中心范围技例外。
3. 敌人身体始终正立、不旋转；不强制把 Movement Collider 或 Body Hurtbox 改成正方形。
4. 个别技能/攻击允许通过独立范围配置跨 Y 轴，但预警与实际范围仍必须严格一致。
5. Dash 数值全部暴露；斜向增加独立缩放，首轮使用 0.8，避免同时吃满两轴造成位移过长。
6. 无方向输入时沿最后水平朝向 Dash，保留 Space 单键兜底。
