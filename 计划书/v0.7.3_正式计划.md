# v0.7.3 正式计划：消耗道具×3（血包/甲包/魔力恢复包）

> 版本线：《v0.7_Demo玩法计划书.md》§4.3 + §九 v0.7.3 执行卡。
> 前置：v0.7.2 已完成（槽位-背包-拾取链路在跑，UseActive 当时只扣数不结算）。本版把三种正式消耗品的数据、效果、投放全部落地。
> 开工前必读《版本实施自检清单.md》§1。用户编辑器可能在运行：**禁改场景/prefab/SO 资产 YAML**，一切新投放走运行时代码。

## 一、目标与范围

1. **三种正式消耗品**：血包（HP+4）/ 甲包（Armor+4）/ 魔力恢复包（Mana+40）——占位数值【待补充·数值，设计 D 定稿】；
2. **使用效果接线**：`ItemInventory.UseActive` 按 effectType 结算 → `Health.Heal` / `PlayerStats.ModifyArmor` / `PlayerStats.AddMana`；
3. **正式数据资产**：`Assets/Data/Item/` 下 Item_HealPack / Item_ArmorPack / Item_ManaPack 三包；删除 v0.7.2 测试资产 Consumable_Test 及准备场景测试投放；
4. **投放三渠道**：准备房间地面投放（出生位前方横排各 1）、宝箱奖励池（三权重 40/30/30）、商店 Row 陈列补充（免费占位，与补给基座同规则，不做货币结算）。

**明确不做（本版）**：击杀掉落（计划书标注【待补充·数值】，设计未定，记为遗留）、货币结算、消耗品正式图标（色块占位沿用）。

### 2.2 脚本改动

| 文件 | 改动 |
|------|------|
| `Item/ItemInventory.cs` | UseActive 前接 `ApplyEffect(data)`：HP → Health.Heal、Armor → PlayerStats.ModifyArmor、Mana → PlayerStats.AddMana；属性已满也照常消耗（简单优先，不拦截） |
| `Class/PrepRoomManager.cs` | SpawnTestItems → SpawnDemoItems()（出生位前方横排三包各 1）；`LoadConsumable(assetName)`（编辑器 AssetDatabase / 构建 Resources.Load，ClassCatalog 同模式）；`ConsumableAssetNames` 内部公开 + `LoadRandomConsumable()` 收口 |
| `Dungeon/Interaction/ChestInteractable.cs` | 奖励二权重扩三权重：武器 0.4 / 法力瓶 0.3 / 消耗包 0.3（序列化可调）；消耗包走 ItemPickup.Spawn + PrepRoomManager.LoadRandomConsumable；资产缺失退回法力瓶不开空箱 |
| `Dungeon/Content/InteractableSpawner.cs` | SpawnRow 收尾处判定 `room.Type == RoomType.Shop` → 基座排下方 2 格追加第二排：三种消耗包各 1 个（ItemPickup.Spawn 运行时投放，间距 1.5，挂 room.ContentRoot）——**单点收口，不散改生成链** |

### 2.3 为什么商店陈列走运行时投放

商店 SpawnTable（InteractableTable_Shop.asset）entries 只持有 prefab 引用，而 ItemPickup 是运行时 Spawn 构建（无序列化 prefab）；且编辑器在运行时改 SO YAML 会被内存覆盖。因此在 SpawnRow（Row 布局唯一消费点）追加运行时投放，风格对齐 ItemPickup.Spawn / PrepRoomManager.SpawnDemoItems 既有模式。

## 三、结算链路（本版落地后）

| 动作 | 链路 |
|------|------|
| 拾取消耗包 | E → ItemPickup → ItemInventory.Add 分流（叠加/入栏/入包/满拒） |
| 使用道具 | C → UseActive → ApplyEffect 按类型结算（Heal/ModifyArmor/AddMana）→ count−1，清零出槽 |
| 宝箱 | 武器 40% / 法力瓶 30% / 消耗包 30%（消耗包资产缺失退回法力瓶） |
| 商店陈列 | 基座 3 件（治疗/护甲/法力球）+ 第二排消耗包 3 件，全部免费占位 |

## 四、验收清单

> 场景：`v0_7_PrepRoom` → `v0_7_ClassWeapon`；Game 1920×1080 或 Free Aspect。

1. `dotnet build Assembly-CSharp.csproj`：0 警告 0 错误（无新脚本文件，csproj 无需补）；
2. **准备房间**：出生位前方横排三种消耗包各 1（非测试药）；E 拾取进背包正常；
3. **使用效果**：血包 HP+4（Health.Heal）、甲包 Armor+4（ModifyArmor）、魔力包 Mana+40（AddMana），数量 −1、清零出槽正确；
4. **满包提示**：栏+3 包容纳 4 种道具 → 捡第 4 种提示"背包已满"且拾取物保留（v0.7.2 遗留项本版可实机触发）；
5. **宝箱**：多次开箱三分支均出现，消耗包 pop-in 弹出可拾取；
6. **商店**：商店房基座排下方有第二排三种消耗包，E 拾取进背包，不与基座重叠；
7. **回归**：补给基座/法力球/换武器入包/准备场景归位照旧。
