## 版本信息
- **版本号**：v0.5.4（v0.5 收官子版本）
- **版本名称**：完整楼层循环 + 交互物美术补充（传送门 / 宝箱开箱动画）
- **前置版本**：v0.5.3（代码完成、自动化验收通过，人工验收随本版本一并覆盖）
- **依据**：《v0.5 Dungeon 系统开发计划书》五-E 节 + 用户需求（2026-07-23：传送门缺美术资源，需「石头中间镶嵌蓝色漩涡门」占位；宝箱需开箱动画——下层 1 矩形盒身 + 上层 2 矩形盖片，走触后盖片上下分开、中间刷新道具，盒/盖同主色调但有明显色差）
- **目标**：
  1. Boss → 奖励结算 → 传送门 → 下一层 → 重新生成 → 难度递增 → 死亡重开，完整 Dungeon Loop 闭环；
  2. 传送门占位美术：灰石块中央嵌蓝色漩涡（持续旋转）；
  3. 宝箱占位美术升级：三段式结构 + 开启动画 + 道具刷新。
- **约束**：
  1. 沿用总计划书约束：不推翻现有架构，对已有模块仅限小口径接入点（全部在第五章列明）；
  2. 交互统一 walk-over，不改输入系统；
  3. 美术为程序员美术：`WhiteSquare/WhiteCircle` 染色 + DOTween 补间，**零外部素材、零 Animator、零 .anim**（沿用美术策略工具箱）；
  4. 一切生成随机走显式 `System.Random`；死亡重开的主 seed 重roll 属运行时一次性事件，不进任何生成流。

### 1.2 关键工程事实（实施前必须知道）

| 事实 | 影响 |
|------|------|
| **敌人 HP 数据源在 `EnemyHealth.maxHealth`（序列化字段，Awake 时 `CurrentHealth = maxHealth`），`EnemyStats.maxHealth` 是另一份手工同步的字段，血条/伤害链路只读 EnemyHealth** | 楼层 HP 缩放必须打在 **EnemyHealth** 上且要同步刷新 CurrentHealth（Awake 在 Instantiate 时已跑完）；EnemyStats 那份顺手同步保持一致 |
| 玩家死亡现状（`PlayerController.OnPlayerDeath`）：`Health.IsDead` 锁移动/攻击 + SpriteRenderer 变灰 (0.3,0.3,0.3) | 死亡重开 = `Health.ResetHealth()`（IsDead 自动解除）+ 回甲 + **恢复初始颜色**；颜色恢复需要 PlayerController 加一个小方法（缓存初始色），这是本版本对现有脚本的唯一改动之一 |
| `Interactable.OnTriggerEnter2D` 是 private 且「立即 ApplyEffect + 压暗」一步到位 | 宝箱要先演动画、演完才结算，需要基类开一个 `protected virtual` 钩子（默认行为不变，Shrine/Supply 零影响） |
| Boss 房 `OnRoomCleared` 触发时房间已 Cleared、敌人全灭 | 奖励宝箱/传送门生成在房中心无遮挡；且它们不受休眠制影响（休眠只作用于战斗内容） |
| 奖励物生成在 Boss 房 contentRoot 下 = dungeonRoot 之下 | 楼层切换 Cleanup 时随根销毁，零残留，无需单独登记 |
| v0.5.3 经验：REST 批量设置私有字段会静默失败、Play 中改 SO 停止后回滚 | prefab 私有字段逐项设置 + 读回 YAML 核验；资产改动在非 Play 状态做 |

### 1.3 随机流设计（沿用 v0.5.3，仅加楼层 seed）

```
主 seed mainSeed（RunManager 持有，第 1 层 = DungeonManager Inspector seed，0=随机）
  └─► 楼层 seed：floorSeed = mainSeed + floorNumber × 104729（质数步长，总计划书五-E）
        ├─► 布局流 / 类型尺寸流 / 房间内容流（派生规则同 v0.5.3，不变）

死亡重开：mainSeed 重roll（运行时随机源，一次性事件，不进生成流）
```

## 二、目标架构

```
Boss 房 OnRoomCleared
  → RunManager.OnBossCleared()：Boss 房中心生成 奖励宝箱 + 传送门
       （奖励 = 治疗 + 占位强化日志，接技能/装备系统前一直是占位）

玩家踩传送门（walk-over，一次性）
  → RunManager.NextFloor()：
       Cleanup()（销毁 dungeonRoot 全部子物体 + 清两块 Tilemap，旧楼层零残留）
       floorNumber++ → floorSeed = mainSeed + floor×104729
       Generate(floorSeed)（生成 + 玩家传送起始房 + 相机 Snap，v0.5.0 已有链路）
       重新订阅新 Boss 房 OnRoomCleared

玩家死亡（Health.OnDeath，只订阅不改逻辑）
  → 2 秒后 RestartRun()：floor=1、mainSeed 重roll、Cleanup → Generate
       → 玩家 HP 回满（ResetHealth）+ 护甲回满（ModifyArmor 差额）+ 颜色恢复（Respawn）

难度注入（Generate 链路内，按当前 floorNumber）：
  敌人数量 += enemyCountBonusPerFloor × (floor-1)（每房封顶 8）
  敌人 HP ×= (1 + hpMultiplierPerFloor × (floor-1))（ApplyFloorScale 注入）
```

## 三、美术补充设计（本版本新增重点）

### 3.1 传送门 `Portal.prefab`：石头镶嵌蓝色漩涡门

结构（根对象 = trigger 碰撞 + `PortalInteractable`，全部白图染色）：

| 子物体 | 底图 | 颜色 | 规格 | sortingOrder |
|--------|------|------|------|--------------|
| StoneBase | WhiteSquare | 石灰 (0.40, 0.40, 0.44) | 竖立石块 scale (1.4, 1.8) | 2 |
| StoneChipA/B | WhiteSquare | 深石灰 (0.32, 0.32, 0.36) | 两小块碎石贴主石下缘，随机感（固定摆位即可） | 2 |
| VortexDisc | WhiteCircle | 蓝 (0.20, 0.50, 0.95) | 嵌在石块中央 scale 1.0 | 3 |
| VortexArm | WhiteSquare（细长条） | 浅蓝白 (0.70, 0.85, 1.00) | 过圆心的短臂 scale (0.8, 0.15)，pivot 居中 | 4 |
| VortexCore | WhiteCircle | 亮蓝 (0.45, 0.75, 1.00) | 中心小圆 scale 0.35 | 5 |

**动效**（`PortalInteractable.Awake` 启动，DOTween，无限循环）：
- VortexArm：`DORotate(z:-360°, 2s, FastBeyond360)` Linear 无限转 —— 漩涡主旋转；
- VortexCore：反向 `DORotate(z:+360°, 3.5s)` 慢转 —— 双层差速形成「涡」感；
- VortexDisc：可选 `DOPunchScale` 待机呼吸（实施时看效果取舍，非验收项）。

**观感**：静止时 = 一块灰石头中间嵌着蓝色圆洞；旋转臂 + 差速亮核让它一眼读出「漩涡门」。tween 挂在 portal 子物体上，Cleanup 销毁根时自动 kill，无泄漏。

**消耗态**：覆盖基类钩子，**不压暗**（踩门即切楼层，对象随旧楼层销毁，无需已消耗表现）。

### 3.2 宝箱 `Chest.prefab` 重构：三段式 + 开启动画

结构（根对象 = trigger 碰撞 + `ChestInteractable`，盒/盖**同主色调（金）但明暗分明**）：

| 子物体 | 颜色 | 规格 | 说明 |
|--------|------|------|------|
| BoxBody（下层盒身） | **暗金棕** (0.70, 0.52, 0.12) | 1 块矩形 1.0 × 0.6，sortingOrder 2 | 盒 |
| LidBottom（下半盖） | **亮金** (0.95, 0.78, 0.20) | 矩形 1.0 × 0.3，闭箱时位于 y ∈ [-0.3, 0]，sortingOrder 4 | 盖（下半） |
| LidTop（上半盖） | **亮金** (0.95, 0.78, 0.20) | 矩形 1.0 × 0.3，闭箱时位于 y ∈ [0, +0.3]，sortingOrder 4 | 盖（上半） |

几何不变量（写进验收）：
- 闭箱：LidTop + LidBottom 合起来 = 1.0 × 0.6，**与 BoxBody 尺寸完全一致**、位置重合，盖片 sortingOrder 高于盒身 → 看到的是亮金盖子包着暗盒的箱子；
- 色差：盒身暗金棕 vs 盖片亮金，同金色调、一眼可辨盒与盖。

**开箱动画**（walk-over 触发，`ChestInteractable` 覆盖基类钩子，DOTween）：

```
玩家触碰 → consumed（一次性）
  → LidTop    DOLocalMoveY(+0.25, 0.35s)
    LidBottom DOLocalMoveY(-0.25, 0.35s)   （两片盖上下分开）
       分开后：上半盖 y∈[0.25,0.55] 与盒身（y∈[-0.3,0.3]）仍有 0.05 重合 ✓
               下半盖 y∈[-0.55,-0.25] 与盒身仍有 0.05 重合 ✓（需求：拉开后仍与盒身有重合区域）
       中间露出 0.5 高的暗盒身缺口
  → 补间完成 → 缺口中央刷新道具占位 Item（scale 0→1，OutBack 弹出，sortingOrder 3：高于盒身、低于盖片，被两片盖框在中间）
  → 结算奖励（+2 HP 治疗 + 日志，现有逻辑不变）
  → 道具停留 0.8s 展示后 0.5s 淡出销毁；箱子保持「开着」的状态留在原地
```

道具占位 `ChestItem_Heal.prefab`：绿圆 (0.30, 0.85, 0.35) scale 0.4（与治疗球同色系，读作「回复道具」）。未来接技能/装备系统时，换 prefab 即换奖励表现。

**奖励宝箱复用**：Boss 结算的奖励宝箱 = 同一个 `Chest.prefab`（奖励内容仍占位：治疗 + 占位强化日志）——自动获得三段式外观与开启动画，Treasure 房宝箱同步升级，零额外工作。

## 四、新增脚本（完整代码）

### 4.1 `Assets/Scripts/v0_5/Core/RunManager.cs`

```csharp
using System.Collections;
using UnityEngine;

/// <summary>
/// 楼层循环总控（计划书五-E）：持有 floorNumber 与主 seed；
/// 监听 Boss 房 OnRoomCleared → 生成奖励宝箱 + 传送门；
/// 传送门 → NextFloor（单场景重建）；玩家死亡 → 2 秒后回第 1 层重开。
/// 对玩家只订阅事件、调用公开方法，不改其逻辑。
/// </summary>
public class RunManager : MonoBehaviour
{
    [Header("引用")]
    [SerializeField] private DungeonManager dungeonManager;
    [SerializeField] private DungeonConfig config;
    [SerializeField] private GameObject rewardChestPrefab;
    [SerializeField] private GameObject portalPrefab;

    [Header("死亡重开")]
    [SerializeField] private float restartDelay = 2f;

    public int FloorNumber { get; private set; } = 1;
    public int MainSeed { get; private set; }

    private PlayerController player;
    private Health playerHealth;
    private PlayerStats playerStats;
    private Room bossRoomSubscribed;

    void Start()
    {
        MainSeed = dungeonManager.ActiveSeed;              // 第 1 层 seed（0=随机 时 Manager 已落定实际值）
        player = FindAnyObjectByType<PlayerController>();
        playerHealth = player.GetHealth();
        playerStats = player.GetStats();
        playerHealth.OnDeath += OnPlayerDeath;
        SubscribeBossRoom();
    }

    void OnDestroy()
    {
        if (playerHealth != null) playerHealth.OnDeath -= OnPlayerDeath;
        UnsubscribeBossRoom();
    }

    // ---------- Boss 结算 ----------

    private void SubscribeBossRoom()
    {
        bossRoomSubscribed = dungeonManager.BossRoom;      // Manager 新增只读访问器（见 5.1）
        if (bossRoomSubscribed != null) bossRoomSubscribed.OnRoomCleared += OnBossCleared;
    }

    private void UnsubscribeBossRoom()
    {
        if (bossRoomSubscribed != null) bossRoomSubscribed.OnRoomCleared -= OnBossCleared;
        bossRoomSubscribed = null;
    }

    private void OnBossCleared(Room room)
    {
        // 奖励宝箱与传送门在房中心左右错开，挂在 contentRoot 下（随 dungeonRoot 一并清理）
        Vector3 c = room.Center;
        Instantiate(rewardChestPrefab, c + new Vector3(-1.5f, 0f, 0f), Quaternion.identity, room.ContentRoot);
        GameObject portal = Instantiate(portalPrefab, c + new Vector3(1.5f, 0f, 0f), Quaternion.identity, room.ContentRoot);
        portal.GetComponent<PortalInteractable>().Init(this);
        Debug.Log($"[Run] 第 {FloorNumber} 层 Boss 已清空：奖励宝箱与传送门已生成");
    }

    // ---------- 楼层切换 ----------

    public void NextFloor()
    {
        UnsubscribeBossRoom();
        dungeonManager.Cleanup();
        FloorNumber++;
        dungeonManager.Generate(FloorSeed());              // 生成 + 传送玩家 + 相机 Snap（v0.5.0 链路）
        SubscribeBossRoom();
        Debug.Log($"[Run] 进入第 {FloorNumber} 层（玩家 HP/护甲保留）");
    }

    private int FloorSeed() => MainSeed + FloorNumber * 104729;   // 质数步长，每层可复现且互不雷同

    // ---------- 死亡重开 ----------

    private void OnPlayerDeath() => StartCoroutine(RestartRun());

    private IEnumerator RestartRun()
    {
        yield return new WaitForSeconds(restartDelay);
        UnsubscribeBossRoom();
        dungeonManager.Cleanup();
        FloorNumber = 1;
        MainSeed = new System.Random().Next();             // 主 seed 重roll（运行时一次性事件，不进生成流）
        dungeonManager.Generate(MainSeed);
        playerHealth.ResetHealth();                        // HP 回满，IsDead 解除
        playerStats.ModifyArmor(playerStats.MaxArmor - playerStats.CurrentArmor);   // 护甲回满
        player.Respawn();                                  // 颜色恢复 + 速度清零（5.4 新增小方法）
        SubscribeBossRoom();
        Debug.Log("[Run] 玩家死亡：回到第 1 层，状态已重置");
    }
}
```

> `dungeonManager.ActiveSeed`：DungeonManager 现有的「实际生效 seed」暴露（Inspector seed=0 时内部已落定随机值）；若当前未暴露，加一个只读属性（属 5.1 小口径）。

### 4.2 `Assets/Scripts/v0_5/Interaction/PortalInteractable.cs`

```csharp
using DG.Tweening;
using UnityEngine;

/// <summary>
/// 传送门（美术：石块镶嵌蓝色漩涡门）：walk-over → RunManager.NextFloor()。
/// 漩涡动效 = 旋转臂 + 差速亮核（DOTween 无限循环，随对象销毁自动 kill）。
/// 消耗态不压暗（覆盖基类钩子）：踩门即切楼层，无需已消耗表现。
/// </summary>
public class PortalInteractable : Interactable
{
    [SerializeField] private Transform vortexArm;
    [SerializeField] private Transform vortexCore;

    private RunManager runManager;

    protected override void Awake()
    {
        base.Awake();
        if (vortexArm != null)
            vortexArm.DORotate(new Vector3(0f, 0f, -360f), 2f, RotateMode.FastBeyond360)
                     .SetEase(Ease.Linear).SetLoops(-1, LoopType.Restart);
        if (vortexCore != null)
            vortexCore.DORotate(new Vector3(0f, 0f, 360f), 3.5f, RotateMode.FastBeyond360)
                      .SetEase(Ease.Linear).SetLoops(-1, LoopType.Restart);
    }

    public void Init(RunManager rm) => runManager = rm;

    protected override void OnConsumed(Collider2D player)
    {
        Debug.Log("[Run] 踏入传送门 → 下一层");
        runManager.NextFloor();
    }
}
```

### 4.3 `Assets/Scripts/v0_5/Interaction/ChestInteractable.cs`（重写）

```csharp
using DG.Tweening;
using UnityEngine;

/// <summary>
/// 宝箱（三段式：暗盒身 + 亮金上下两片盖）：walk-over → 盖片上下分开（仍与盒身保持重合区）
/// → 缺口中央刷新道具占位（pop-in）→ 结算奖励（+2 HP 占位）→ 道具展示后淡出。
/// 奖励从占位变真货的挂点即 ApplyEffect（未来接技能/装备系统）。
/// </summary>
public class ChestInteractable : Interactable
{
    [SerializeField] private float healAmount = 2f;

    [Header("开箱动画")]
    [SerializeField] private Transform lidTop;
    [SerializeField] private Transform lidBottom;
    [SerializeField] private GameObject itemPrefab;
    [SerializeField] private float lidOffset = 0.25f;      // 分开后每片盖仍与盒身重合 0.05
    [SerializeField] private float openDuration = 0.35f;

    protected override void OnConsumed(Collider2D player)
    {
        lidTop.DOLocalMoveY(lidTop.localPosition.y + lidOffset, openDuration);
        lidBottom.DOLocalMoveY(lidBottom.localPosition.y - lidOffset, openDuration)
              .OnComplete(() => SpawnItem(player));
    }

    private void SpawnItem(Collider2D player)
    {
        GameObject item = Instantiate(itemPrefab, transform.position, Quaternion.identity, transform);
        Vector3 targetScale = itemPrefab.transform.localScale;
        item.transform.localScale = Vector3.zero;
        item.transform.DOScale(targetScale, 0.25f).SetEase(Ease.OutBack);   // pop-in 弹出

        ApplyEffect(player);   // 结算：+2 HP（占位奖励）+ 日志

        if (item.TryGetComponent(out SpriteRenderer sr))
            sr.DOFade(0f, 0.5f).SetDelay(0.8f).OnComplete(() => Destroy(item));   // 展示后淡出
    }

    protected override void ApplyEffect(Collider2D player)
    {
        if (player.TryGetComponent(out Health hp)) hp.Heal(healAmount);
        Debug.Log($"[Dungeon] 宝箱开启：HP +{healAmount}（占位奖励）");
    }
}
```

> 注意：盖片动画用 `DOLocalMoveY` 基于当前 localPosition 计算目标值，prefab 内盖片初始位置即闭箱位置，重复开箱由基类 consumed 保证不会二次触发。

### 5.3 `now_use/EnemyStats.cs` + `now_use/EnemyHealth.cs`（难度缩放注入）

```csharp
// EnemyStats.cs 新增（1.3 表已列的 ApplyFloorScale，按工程事实调整落点）：
/// <summary>楼层难度缩放：攻击 ×dmgMul；HP 经 EnemyHealth 缩放（血条/伤害链路只读 EnemyHealth）。</summary>
public void ApplyFloorScale(float hpMul, float dmgMul)
{
    maxHealth *= hpMul;                     // EnemyStats 这份手工同步字段一并缩放，保持一致
    attackDamage *= dmgMul;
    if (TryGetComponent(out EnemyHealth eh)) eh.ScaleMaxHealth(hpMul);
}

// EnemyHealth.cs 新增：
/// <summary>楼层 HP 缩放：上限倍乘并刷新当前血量（Awake 已初始化，必须同步刷新）。</summary>
public void ScaleMaxHealth(float mul)
{
    maxHealth *= mul;
    CurrentHealth = maxHealth;
    OnHealthChanged?.Invoke(CurrentHealth, maxHealth);
}
```

## 九、风险与注意事项

| 风险 | 影响 | 应对 |
|------|------|------|
| HP 缩放打错字段（EnemyStats 与 EnemyHealth 双 maxHealth） | 血条显示与实际血量不一致、缩放不生效 | 已在 1.2/5.3 明确：缩放落点 EnemyHealth + 刷新 CurrentHealth；验收实测敌人血量 |
| ScaleMaxHealth 时序（Awake 已初始化 CurrentHealth） | 缩放后当前血量仍是旧上限 | ScaleMaxHealth 内同步 `CurrentHealth = maxHealth` 并广播血条事件 |
| 死亡重开后玩家保持灰色/锁操作 | 重开假死 | Respawn 缓存初始色恢复；IsDead 由 ResetHealth 解除；验收含移动/攻击项 |
| Boss 房事件重复订阅/旧楼层事件残留 | 奖励重复生成、Missing 引用 | 每次 Generate 后 Unsubscribe→Subscribe 成对执行；旧 Room 随 dungeonRoot 销毁 |
| 传送门 walk-over 瞬间玩家持续站立导致多次触发 | 连跳楼层 | 基类 consumed 一次性 + 触发后对象即随楼层销毁 |
| DOTween 无限旋转 tween 泄漏 | 长局内存缓增 | tween 挂在 portal 子物体上，Cleanup 销毁即自动 kill；验收含 3 层无泄漏 |
| Cleanup 漏挂对象（dungeonRoot 之外的生成物） | 旧楼层残留 | 任务2 含挂载审计：所有生成物（房/门/内容/奖励物）必须在 dungeonRoot 下；奖励物挂 contentRoot 天然满足 |
| 盖片动画期间玩家离开/再次触碰 | 动画重复或卡住 | consumed 先行，二次触发被基类拦截；动画仅 0.35s 无中断需求 |
| 奖励物与门洞/玩家出生位冲突 | 遮挡通行 | 固定在 Boss 房中心 ±1.5，Boss 房 62×38 空间充足 |
