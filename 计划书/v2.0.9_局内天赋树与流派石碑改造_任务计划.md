## 1. 产品方案

### 1.1 一棵通用树，三个使用界面

| 场景 | 界面职责 | 是否改变本局战力 |
|---|---|---|
| 守灯厅流派石碑 | 查看完整流派树；选择一个兼容的一阶起始天赋 | 是，只写入当前 Run |
| 地牢奖励三选一 | 从三个合法天赋石板中选择一个 | 是，只写入当前 Run |
| 暂停页本局构筑 | 查看本局已激活节点、合法后继和成型流派 | 否，只读 |

三处界面共用当前 Run 的天赋 ID 集合，不分别保存状态。

### 1.2 通用的准确含义

通用树包含全部 19 个流派和 76 个小天赋，不再为狼人、法师、弓箭手复制三棵结构相似的树。

通用不代表任何职业都无条件获得所有节点。每个节点通过明确兼容标签决定能否进入当前职业的奖励池：

- 攻击标签：普攻、技能、近战、远程、重击、蓄力、反击、DOT。
- 状态标签：破甲、持续伤害、虚弱、冻结、腐化。
- 防御标签：生命、护甲、治疗、闪避。
- 行为标签：贴身、远距、受击、完美闪避、蓄力。
- 职业接口：强化状态、职业资源回流、职业终结技。

不兼容节点仍可在石碑总览中看到，但显示不兼容原因，不会进入当局三选一。

涉及职业差异时，节点名称保持通用，效果说明按当前职业显示实际结果：

| 通用规则 | 狼人显示 | 法师显示 | 弓箭手显示 |
|---|---|---|---|
| 恢复一次职业循环收益 | 恢复指定点数怒痕 | 恢复指定点数法力 | 缩短下一次蓄力或闪避冷却 |
| 进入职业强化状态 | 兽化 | 法术强化状态 | 精准/速射状态 |
| 强化职业终结技 | 狼爪结束技 | 法术终结技 | 满蓄力终结箭 |

效果说明中禁止出现“主资源”这类未落地词。

### 1.3 石碑职责

现有 SkillTreeBeacon 改造为“流派石碑”，继续位于守灯厅传送门附近并保留 E 交互。

新职责：

1. 读取当前 PlayableCharacterId 与其兼容标签。
2. 展示六个玩法主枝、19 个流派分枝及每枝四个天赋节点。
3. 展示每个节点的名称、触发条件、收益、代价、数值与前置。
4. 玩家从兼容的一阶节点中免费选择一个作为本局起始天赋。
5. 选择后写入 RunTalentState，并提高前两次奖励中该流派合法后继的出现权重。
6. 进入地牢后起始天赋锁定；死亡或通关清空，下局重新选择。

石碑不再消耗魂晶，不再提供永久攻击、移速、攻速、生命、护甲或暴击数值。

## 2. 通用天赋树结构

### 2.1 六条主枝与十九个流派分枝

| 主枝 | 流派分枝 |
|---|---|
| 伤害输出 | F01 直伤爆发、F02 持续普攻、F03 穿透破甲、F04 暴击倍率 |
| 生存防御 | F05 护甲屏障、F06 反伤荆棘、F07 闪避规避、F08 回血续航 |
| 持续异常 | F09 持续伤害、F10 状态引爆、F11 腐化诅咒 |
| 控制削弱 | F12 硬控封锁、F13 软控虚弱 |
| 机动位移 | F14 贴脸近战、F15 拉扯风筝、F16 反击时序 |
| 代价博弈 | F17 自残献祭、F18 蓄力延迟、F19 代价契约 |

树形视觉不同时铺开 76 块大卡片：

1. 中央为古树主干。
2. 主干伸出六条玩法主枝。
3. 六条主枝上分出 19 个流派芽点。
4. 选中一个流派芽点后，右侧展开该流派四块连续天赋石板。
5. 已激活节点点亮分枝；合法后继呼吸描边；不兼容节点显示断枝和原因。

### 2.2 节点顺序

每条流派固定四阶：

1. 起手：建立最小触发能力。
2. 循环：让触发能够持续积累。
3. 转化：把积累转换成伤害、生存或控制收益。
4. 成型：加入高价值兑现与明确代价，构成完整流派。

第四阶不是额外第五个终极技能。四个节点同时激活时，完整效果等于十九流派数值表中的最终效果。

### 2.3 解锁和选择规则

- 第一阶无树内前置，可以作为起始天赋或在局内开启新流派。
- 第二至第四阶必须拥有同流派上一阶。
- 同一节点每局只能激活一次，不做重复升级。
- 一次奖励只能选择一个节点。
- 一局允许多流派混搭，不要求点满一条后才能开启另一条。
- 已成型流派后，其节点不再占奖励候选；奖励权重转向联动流派。
- 不兼容节点不进入候选，也不能通过随机补位绕过。

### 3.2 其余六十个节点的命名审查

保留已经通用且清楚的名称，例如“偏锋赌注、战中修补、擦身而过、催化印记、借力时机、以血换势、预备架势、签订誓约”。

必须改名的情况：

- 名称直接包含狼人、狼爪、兽化、怒痕、刺刀。
- 名称直接包含尚未确定的法师或弓箭手专属技能名。
- 名称只描述数值，没有体现玩法动作。
- 同一个词在两个系统里代表不同资源。

每个节点的说明固定为四段信息：

触发条件 → 数值收益 → 层数/冷却/持续时间 → 代价或不触发范围。

### 3.3 兼容类型

每个节点必须归入以下一种类型：

| 类型 | 说明 | 示例 |
|---|---|---|
| 完全通用 | 所有职业都拥有所需基础行为 | 暴击、生命、护甲、闪避 |
| 标签通用 | 具有指定攻击或状态标签的职业可用 | 近战、远程、DOT、破甲、蓄力 |
| 职业适配 | 名称与结构通用，实际回报按职业映射 | 怒痕、法力、蓄力冷却 |
| 内容未就绪 | 规则已定，但当前工程尚无所需运行状态 | 腐化、冻结、契约 |

“内容未就绪”节点在石碑中可预览，但在对应运行状态完成前不进入奖励池。

## 4. 天赋石板与美术计划

### 4.1 必须新增的可见对象

每个可投放天赋必须具备：

- 树上节点石板：用于流派石碑和暂停构筑树。
- 奖励选择石板：用于房间结算三选一。
- 流派图标：用于树上芽点、奖励卡和 HUD。
- 状态图标：仅用于需要显示层数或倒计时的天赋。

TalentDefinition 没有关联展示信息时，Catalog 校验必须报错并禁止投放，避免“逻辑存在但前端看不到”。

### 4.2 石碑界面美术

美术主题：石碑内生长出发光古树，分枝随本局选择逐步点亮。

资产清单：

- 一张石碑内嵌古树主背景。
- 六条玩法主枝的颜色与符号。
- 十九个流派图标。
- 天赋石板普通、悬停、按下、已激活、合法后继、不兼容六种状态。
- 分枝未激活、可延伸、已点亮、断枝四种连线状态。
- 起始天赋确认、获得天赋、流派成型三类短反馈。
- 右侧效果详情面板与通用词条图标。

首轮允许节点图标使用统一风格的简化符号，但不再以无文字色块作为最终交付。

### 4.3 世界石碑美术

- 保留碑体尺寸、碰撞范围和传送门旁动线。
- 旧三色符文改为六条主枝符号围绕中央树纹。
- 未选择起始天赋时，六个符号依次微亮。
- 选择后，对应主枝与流派图标持续亮起。
- 进入地牢后石碑表现锁定，不允许改变当前 Run。

## 5. 局内奖励规则

### 5.1 奖励职责拆分

| 奖励类型 | 推荐来源 | 是否占用天赋三选一 |
|---|---|---|
| 天赋 | 主要战斗房、精英房 | 是 |
| 星蓝币 | 清房掉落、宝箱、事件 | 否 |
| 治疗 | 药剂、恢复节点、商店 | 否 |
| 武器变体 | 武器架、精英、商店 | 否 |
| 遗物 | 精英、Boss、商店 | 否 |
| 纯攻击 +12% / +25% | 从主要构筑池移除 | 否 |

主要战斗奖励优先保证天赋树推进。经济、治疗、武器和遗物的取舍由路线、商店、事件与独立掉落承担。

### 5.2 三类候选不是固定槽位名称

“关联、联动、开拓”是候选分类，不在玩家 UI 上显示为一号位、二号位、三号位，也不固定卡片位置。

| 分类 | 判定条件 | 权重目标 |
|---|---|---|
| 后继天赋 | 已拥有同流派上一阶 | 保证主流派可以成型 |
| 联动天赋 | 与已有攻击、状态、防御或行为标签至少命中一项 | 形成跨流派组合 |
| 开枝天赋 | 兼容且尚未开启的流派一阶节点 | 保留转型机会 |
| 代价天赋 | 高收益且带明确负面规则 | 低权重，只在风险构筑池出现 |

一次三选一的生成顺序：

1. 收集所有职业兼容且前置合法的未获得节点。
2. 按后继、联动、开枝、代价分类。
3. 优先抽一个后继节点。
4. 从联动与开枝中抽取其余节点。
5. 打乱展示顺序，玩家看不到内部槽位。

保底：

- 前两次主要奖励至少出现一个起始流派合法后继。
- 连续两次没有任何已开流派后继时，下一次强制提供。
- 不展示前置未满足节点、已获得节点和不兼容节点。
- 候选不足三个时，使用兼容的通用一阶节点补齐；仍不足才使用遗物或恢复，不用纯攻击百分比占位。
- 结果由 Run seed、房间 ID 和奖励序号决定，退出重进不得刷新。

### 5.3 奖励节奏

- 开局石碑：1 个兼容的一阶起始天赋。
- 普通主要战斗房：1 次天赋三选一。
- 精英房：1 次高关联天赋三选一，遗物独立结算。
- Boss 战前不再发新天赋；Boss 后进入通关结算。
- 单局目标获得 6～10 个天赋，通常形成一条四阶主流派与一至两条副流派。

实测若 8～12 房全部奖励导致成长过快，再调整房间奖励频率；首次实现不同时修改天赋数值和房间节奏。

## 6. 数据与模块职责

### 6.1 推荐模块

| 模块 | 单一职责 | 形态 |
|---|---|---|
| TalentDefinition | 静态 ID、分类、阶位、前置、兼容标签、名称、说明与数值 | ScriptableObject |
| TalentCatalog | 校验并提供 76 个静态定义 | 只读目录 |
| RunTalentState | 起始天赋、已获得 ID、奖励序号、保底计数 | 纯 C# 数据 |
| TalentEligibility | 判断职业与节点是否兼容，并生成明确原因 | 纯 C# 规则 |
| TalentOfferService | 根据 seed、分类、权重和保底生成候选 | 纯 C# 规则 |
| TalentRuntime | 接收获得、恢复、清空命令并协调效果模块 | 薄运行门面 |
| TalentTreeView | 石碑可选模式与暂停只读模式 | 表现层 |
| RewardChoiceUI | 展示天赋石板并回调选择 | 表现层 |

### 6.2 数据所有权

- TalentDefinition 保存策划配置，不保存当前 Run 状态。
- RunTalentState 归 RunStateCarrier 与 ActiveRun 保存链，不依赖场景对象 Active。
- PlayerStats 继续持有角色最终属性，不保存天赋树结构。
- DamageContext 只保存一次伤害结算信息，不保存层数。
- EnemyStatus 保存敌方 DOT、破甲、虚弱等目标状态。
- 连击、暴击节奏、贴身压制等玩家运行计数由对应小型效果模块持有。
- UI 只读取 Definition 与 RunTalentState，不直接写 PlayerStats。

### 6.3 通信规则

- 选择天赋：UI 发出 TalentId 选择命令，运行层校验后写入状态。
- 获得天赋：TalentRuntime 发布低频“天赋已获得”事件，UI 刷新。
- 战斗触发：效果模块订阅明确的命中、受击、闪避、状态和强化状态事件。
- 不通过 GameObject.Find、字符串名称或每帧扫描判断天赋。
- 不依赖多个 MonoBehaviour 的偶然 Awake 顺序；由 RunManager/角色初始化入口显式恢复天赋状态。

### 6.4 性能边界

- 命中、DOT tick、距离判定属于高频路径，不使用 LINQ。
- 复用集合与物理查询缓冲。
- 距离流派读取已有攻击目标和命中位置，不额外全场搜索。
- UI 仅在打开、获得天赋或职业改变时重建，不在 Update 中重建树。

## 8. 测试与验收矩阵

| 类别 | 必测内容 |
|---|---|
| 可见性 | 每个可投放天赋同时存在树节点石板与奖励石板 |
| 前置 | 未拥有上一阶时不出现二至四阶 |
| 去重 | 已获得节点不再次进入候选 |
| 兼容 | 不兼容节点只在总览预览，不进入奖励池 |
| 保底 | 前两次奖励至少一个起始流派合法后继 |
| 确定性 | 同 seed、房间 ID、奖励序号得到相同候选 |
| 生命周期 | 新 Run 初始化，断点恢复，死亡与通关清空 |
| 效果组合 | 单节点、四阶成型、跨流派组合 |
| 伤害标签 | 直伤、DOT、真伤、普攻、技能、重击、反击不串线 |
| 状态规则 | 流血上限、破甲非叠层及后续状态各守合同 |
| UI 模式 | 石碑可选、奖励可选、暂停只读 |
| 输入 | Esc、E、鼠标、键盘与手柄焦点不冲突 |
| 存档迁移 | 旧魂晶与旧解锁不再增加永久属性 |
| 性能 | 命中、DOT tick、距离检查无明显 GC 分配 |

## 9. 明确不做

- 不保留旧力量、迅捷、坚韧永久百分比树。
- 不将魂晶转换为星蓝币。
- 不增加新的长期货币。
- 不让天赋在一局内无限升级。
- 不把三个候选分类显示成固定卡槽名称。
- 不为每个职业复制一份 76 节点树。
- 不让尚无底层能力的天赋以空效果进入奖励池。
- 不在数据、运行层和 UI 各复制一份天赋数值。

## 10. 执行顺序与入口保护

推荐依赖链：

T0 通用规则冻结 → T1 数据与兼容 → T2 石板和树形美术 → T3 石碑替换 → T4 奖励池 → T5 效果运行层 → T6 构筑 UI → T7 旧树退役 → T8 平衡。

入口保护：

- 新石碑未能选择并写入 RunTalentState 前，不删除旧石碑入口。
- 新奖励链未能稳定生成可见候选前，不移除现有奖励回退。
- 新天赋效果未接入时，节点标为内容未就绪且不进入奖励池。
- 每个批次完成后仍须能进入地牢、完成战斗、死亡或通关返回守灯厅。

## 11. 计划完成定义

本计划完成不等于 19 个流派全部数值平衡完成，而是满足：

1. 76 个节点拥有通用名称、完整说明、稳定 ID 与兼容类型。
2. 所有可用节点在石碑和奖励界面都能被看到。
3. 守灯厅旧石碑已经完整替换为树干分枝式通用天赋树。
4. 起始选择、局内三选一、暂停查看共用同一份 Run 状态。
5. 旧魂晶永久数值树已经安全退役。
6. 当前可玩角色能通过通用树形成至少六种可描述 Build。
