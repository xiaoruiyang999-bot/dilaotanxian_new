> 文档状态：玩法新基线 / 可进入原型验证

## 1. 项目定义

### 1.1 一句话概述

一款 2D 俯视角房间制 Roguelite：玩家以职业化角色在房间内进行二维自由战斗，在宏观上沿 DAG 路线持续向右推进，通过不可逆路线选择、局内构筑和风险收益决策，最终挑战 Boss。

### 1.2 核心体验公式

职业战斗差异 × 俯视角二维走位 × 横向单向推进 × DAG 路线决策 × 可读的局内 Build × Boss 检验。

### 1.3 核心卖点

1. **微观二维、宏观一维**：单房间中可上下左右自由移动；整层只从左向右推进。
2. **房间本身也在推进**：房间可跨 1～3 屏，并包含接敌、地形、主战、奖励等节奏，而非全都退化成一屏锁门清怪。
3. **路线选择改变构筑条件**：DAG 节点承担治疗、经济、精英收益与事件风险，选择不可逆。
4. **职业改变思考方式**：狼人、法师、弓箭手采用不同资源循环、站位需求和 Build 方向，不以换色和基础属性差异充数。
5. **小团队可持续制作**：职业限制武器类型，角色与武器视觉一体化；用统一动画模组、判定时序和数据资产复用控制成本。

### 1.4 目标玩家

- 喜欢俯视角动作、走位和清晰打击反馈的玩家。
- 喜欢《杀戮尖塔》式路线取舍和 Roguelite 局内构筑的玩家。
- 能接受一局失败重来，但希望每局形成可描述流派的中度玩家。
- 不以复杂装备管理、长篇剧情或高强度永久数值碾压为主要诉求。

### 1.5 项目级别与制作判断

本项目按“长期维护的小团队游戏”设计，而不是一次性原型。架构必须能支撑新增职业、节点、房间和 Build，但当前只保留少量稳定模块，不提前建设大型通用框架。

## 2. 设计支柱与非目标

### 2.1 设计支柱

- **战斗先于内容数量**：动作时序、受击反馈、敌人组合优先于敌人总数。
- **选择必须有机会成本**：路线、金币、治疗、奖励选择都要有放弃项。
- **Build 必须可识别**：玩家应能说出“这一局是流血变身流”而非“攻击力高了一些”。
- **空间服务节奏**：Y 轴服务战斗变化，X 轴服务推进感，镜头和刷怪方向共同强化此关系。
- **复用不等于重复**：同一房间模板通过障碍布局、遭遇组合、进入条件和事件目标产生变化。

### 2.2 非目标

- 不制作传统平台跳跃式横版游戏。
- 不制作四方向房门迷宫；DAG 的上下分叉不映射为场景中的上门、下门。
- 不让全部职业自由使用全部武器。
- 不以数百件微小数值差异装备作为内容主体。
- 不在 MVP 阶段制作联机、复杂锻造、随机词条生成器、开放世界或多层永久天赋树。

## 3. 完整游戏循环

### 3.1 局外到局内

职业角色选择 → 初始武器或起始特性确认 → 生成本层 DungeonGraph → 查看路线 → 选择可达节点 → 加载横向房间 → 战斗/事件/商店 → 奖励与 Build 调整 → 完成节点 → 选择下一节点 → Boss → 通关或死亡结算 → 内容解锁 → 下一局。

### 3.2 不可逆规则

- 已完成节点不能返回。
- 当前节点只可选择图中明确连出的下一层节点。
- 离开商店、事件或奖励界面后，未选项目默认放弃。
- 房间内原则上不能向左返回上一节点；是否允许在当前房间内短距离回走见待定项 T-06。

### 3.3 建议单局时长

- MVP 验证局：10～15 分钟。
- Vertical Slice 完整局：30～40 分钟。
- 正式版单区域：35～50 分钟；多区域长局需在后续验证存档与疲劳后再决定。

建议以 8～12 个普通层级节点加 1 个 Boss 节点构成垂直切片，而不是先追求三大区域长流程。

## 4. 空间模型：二维战斗，一维推进

### 4.1 两个空间尺度

| 尺度 | 表现 | 作用 |
|---|---|---|
| 宏观 | DAG 路线地图 | 路线规划、风险收益、节点选择 |
| 微观 | 横向长矩形俯视房间 | 即时战斗、走位、地形利用 |

DAG 地图中的纵向位置只是为了画出分支关系。玩家选择上方“精英”节点后，仍从该房间左侧进入，从右侧完成并离开。

### 4.2 轴向职责

- X 轴：推进、敌我距离、前后排、镜头移动、追逐与增援来源。
- Y 轴：闪避、绕后、包抄、弹幕规避、队形突破和危险区避让。

### 4.3 横向推进感验收

一个房间至少满足下列五项中的三项，才可称为“横向推进房”：

1. 摄像机在房间内发生明显的水平位移。
2. 玩家至少进行一次位置推进，而非站在入口清完全部敌人。
3. 敌人或目标按前、中、后层次布置。
4. 障碍、危险区或奖励引导玩家继续向右。
5. 出口或阶段目标始终位于玩家前方。

### 4.4 房间尺寸

- 标准宽度：约 1.5～2 屏。
- 短房：约 1 屏，用于休息、商店、宝箱和部分事件。
- 长房：约 2.5～3 屏，用于追逐、分段遭遇和精英战。
- 高度不统一压成窄走廊；战斗房需保留足够 Y 轴走位空间。
- 尺寸以摄像机可视世界范围与玩家碰撞直径为基准，不以素材像素直接定值。

## 5. 操作、移动与闪避

### 5.1 建议基础操作

| 操作 | 键鼠建议 | 说明 |
|---|---|---|
| 移动 | WASD | 俯视角八向输入，速度归一化 |
| 普通攻击 | 鼠标左键 | 方向方案待定 |
| 闪避 | Space | 短位移、短无敌、不可连续滥用 |
| 职业技能 | F | 职业核心循环的重要按钮 |
| 终极/变身 | Q 或 T | 狼人为兽化；全职业统一键位待定 |
| 武器技能 | R | 由当前武器提供 |
| 交互 | E | 商店、宝箱、出口、事件 |
| 使用道具 | C | 单激活道具位 |
| 地图 | Tab | 按住或切换显示 DAG |
| 暂停/关闭界面 | Esc | 界面栈统一处理 |

手柄映射在 Vertical Slice 后半段补齐，不在 MVP 前置。

### 5.2 移动目标

- 角色可在攻击间隙精确调整 Y 轴。
- 不使用惯性过强的滑行，确保危险区规避可控。
- 普通攻击可有轻微减速，但不默认完全定身。
- 近战重击允许短暂方向锁定，以换取可读性和承诺感。

### 5.3 闪避初始框架

- 冷却制优先于体力条，降低首版 UI 和数值复杂度。
- 建议位移 2.0～2.8 个玩家直径，无敌 0.12～0.20 秒，冷却 0.9～1.4 秒。
- 闪避不能穿越实体墙；能否穿过敌人由职业特性决定。
- 受击、攻击后摇和技能是否可被闪避取消，应逐技能数据化。

## 6. 攻击方向方案【已定案 T-01：A 仅左右】

> **定案（2026-09-09，用户灰盒试玩对比后拍板）**：采用 **A. 仅左右攻击，移动仍八向**。
> 灰盒实现与方向离散合同见《v1.2.1_攻击方向灰盒.md》；实现真源 `AttackDirectionResolver`
>（`AttackDirectionPrototypeMode.Horizontal` 为正式模式，FourWay 代码保留作回归对照）。
> 斜向移动攻击取水平主轴、对角精确相等优先水平——由 `AttackDirectionResolverTests` 锁定。

新方向确认了俯视角二维自由战斗，但没有确认攻击瞄准方式。此项会直接影响动画量、手感、敌人设计和输入方案，必须原型对比后定案。

| 方案 | 优点 | 缺点 | 成本 | 扩展性 |
|---|---|---|---|---|
| A. 仅左右攻击，移动仍八向 | 横向感最强；动画和一体化武器资源最省 | Y 轴接敌容易产生“对不上线”；远程与近战瞄准受限 | 低 | 中 |
| B. 四方向离散攻击 | 保留俯视角空间价值；动画量可控；手柄友好 | 斜向敌人会吸附或落空；需清晰方向判定 | 中 | 高 |
| C. 八方向/鼠标 360°瞄准 | 精确、熟悉、远程职业舒适 | 一体化武器动画量急剧上升；横向推进辨识度减弱 | 高 | 高但昂贵 |

**推荐：先制作 B 的灰盒原型，同时用 A 作低成本对照。** 四方向攻击最能兼顾二维走位与一体化 Sprite 的制作约束。正式定案前，不删除现有鼠标瞄准代码，也不继续扩建 WeaponPivot 表现链。

## 7. 战斗节奏与攻击系统

### 7.1 标准攻击阶段

攻击统一由前摇、有效判定、后摇组成。动画只是表现消费者，伤害窗口由攻击数据和动画事件/状态机行为共同驱动，不能从当前 Sprite 帧号临时推断。

### 7.2 同源规则

一次攻击的预警、伤害判定、位移、命中特效与动画窗口消费同一份 AttackDefinition。身体碰撞与攻击判定始终分离：

- Body Hurtbox：承受碰撞和受击。
- Attack Hitbox：只在有效帧开启。
- Movement Collider：阻挡墙体和环境。

武器画在角色 Sprite 中，不代表伤害范围等于可见像素；每个共享动画模组仍需一份标准判定几何。

### 7.3 连击与输入缓存

- 普攻可采用 2～3 段固定模组。
- 在当前攻击后半段接受一次输入缓存。
- 连击重置时间初值 0.45～0.70 秒。
- 每段位移、转向锁定和取消窗口数据化。
- MVP 只做一种完整模组，不建设任意连招编辑器。

### 7.4 反馈层级

- 普通命中：短音效、轻微停帧、微弱震屏、受击闪白。
- 重击/处决：更长停帧、明显音调和震屏、击退或慢动作。
- 玩家受击：优先保证危险来源、伤害量和无敌窗口可读。
- Camera Shake 必须按强度通道合成，避免多次命中无限叠加。

## 8. 职业系统

### 8.1 职业名单

战士职业正式退役。新版目标职业为：

1. 狼人
2. 法师
3. 弓箭手

新版将原有“角色选择”和“职业选择”合并为单一的**职业角色选择**。职业角色同时定义身份与外观、基础属性倾向、可用武器类型、职业资源、技能、动画集合与专属 Build 池。玩家不会再先选外观角色、再套一层职业。MVP 与 Vertical Slice 只实装狼人。

技术数据以 PlayableCharacterDefinition 作为统一入口；原 CharacterDefinition/ClassData 中仍有价值的字段逐步迁入。皮肤若在正式版加入，只能替换视觉与音效表现，不改变职业规则。

### 8.2 狼人：侵略节奏与兽化

定位：近距离、高生存、持续压迫、以受伤风险换取爆发。

核心资源建议为“兽性”：

- 近距离命中、连击和处决积累兽性。
- 脱战或被远程压制时缓慢衰减。
- 兽性达到条件后主动兽化，或消费兽性强化技能。
- 兽化提供攻击模组变化，而不只是属性翻倍。

推荐 Build：

- 流血撕裂：叠层、刷新、爆层。
- 狂怒连击：持续贴身提高攻速和吸血上限。
- 残血处决：低生命换取收益，但必须保留恢复决策压力。
- 兽化爆发：缩短人形积累期，强化变身窗口。

### 8.3 法师：元素编织与资源规划

定位：中远程、区域控制、爆发、站位脆弱。

核心机制建议为“三元素印记”：

- 普攻或技能施加火、冰、雷印记。
- 不同顺序触发燃烧、冻结、连锁等反应。
- 魔力不是单纯蓝条，而是爆发与安全距离之间的节奏限制。

### 8.4 弓箭手：专注、弱点与机动

定位：远程持续输出、精确站位、连击与暴击。

核心机制建议为“专注”：

- 连续命中、保持安全距离或命中弱点提高专注。
- 受击或空射会损失专注。
- 高专注改变蓄力速度、穿透或技能效果。

### 8.5 差异化验收

更换职业后，至少改变三项：安全距离、资源循环、移动/取消规则、目标优先级、奖励偏好。只改变生命和攻击数值不算新职业。

## 9. 武器与一体化美术

### 9.1 规则

- 每个职业只使用一个或少数指定武器类型。
- 同武器类型共享基础攻击模组、帧数、判定时机和逻辑。
- 不同武器以数值、品质、词条、元素、命中特效和 Build 联动形成差异。
- 武器视觉直接绘入角色动画；装备切换可替换整套“角色 + 武器”动画资源。

### 9.2 推荐首批

- 狼人：爪刃/巨爪作为唯一基础模组。
- Vertical Slice：3～5 把武器变体，其中最多 2 套显著不同的特效主题，不新增第二套基础动作。
- 正式版单职业首发建议 6～10 把武器；超过此范围前必须验证资源复用收益。

### 9.3 品质

建议四档：普通、精良、稀有、传奇。品质主要控制可拥有的固定效果强度与槽位，不随机生成大量不可读小数词条。

### 9.4 词条结构

- 基础特性：定义武器身份，固定且总是存在。
- 强化词条：从受控池中抽取 0～2 条。
- 传奇效果：改变规则或与职业机制强联动。

词条优先使用明确条件，如“对流血 3 层敌人重击爆层”，少用“伤害 +4.7%”。

### 9.5 资源膨胀估算与控制

若每把武器都复制待机、移动、攻击、受击、技能全套 Sprite，资源量会按“职业 × 武器 × 方向 × 动作 × 帧数”相乘。控制方案：

1. 同类型武器严格共享帧数与事件时刻。
2. 优先换色、局部轮廓和特效层，不为每把武器新增动作。
3. 只对当前职业的当前武器加载动画集合。
4. 用统一命名和 Animator Override Controller 替换 Clip。
5. 技能中与武器无关的帧尽量共享。
6. 传奇武器可用命中特效和拖尾创造差异，不强制整套重画。

## 10. 技能、遗物与 Build

### 10.1 构筑层次

- 武器：基础攻击方式和一个身份效果。
- 职业技能：职业资源循环和主动决策。
- 遗物：跨系统联动和规则变化。
- 状态效果：为组合提供共同语言。
- 少量词条：补足方向，不替代遗物身份。

### 10.2 遗物池结构

建议垂直切片 12～16 件：

- 6～8 件狼人专属。
- 4～6 件全职业通用。
- 2 件高风险诅咒/契约。

正式版再扩展至每职业 20～30 件专属、20～30 件通用；在掉落筛选算法稳定前不追求数量。

### 10.3 控制随机性

- 奖励池按职业、已有标签和缺失环节加权。
- 连续两次主要奖励至少出现一个与已有 Build 标签相关的选项。
- 三选一中避免三个选项功能完全同质。
- 允许有限次数重掷，但重掷消耗稀缺资源。
- 商店至少提供一个当前职业可用项目和一个恢复/通用项目。
- 不保证强制凑齐套装，保留路线与经济选择的风险。

### 10.4 状态效果首批

| 状态 | 作用 | 设计用途 |
|---|---|---|
| 流血 | 可叠层的持续伤害，部分技能可爆层 | 狼人主 Build |
| 易伤 | 短时间提高承伤 | 爆发窗口 |
| 减速 | 降低移动速度，不默认影响攻击速度 | 控场与拉扯 |
| 燃烧 | 持续伤害，可与火系联动 | 法师后续 |
| 冻结/冰缓 | 控制积累或短控 | 法师后续 |
| 标记 | 弓箭手弱点与追踪条件 | 弓箭手后续 |

MVP 只实现流血与一个通用增益，避免先造通用状态编辑器。

## 11. 敌人生态、精英与 Boss

### 11.1 基础职能

- 前排近战：建立接触压力，保护后排。
- 后排远程：迫使玩家推进或改变 Y 轴。
- 冲锋敌人：通过水平预警后冲刺，迫使上下闪避。
- 区域控制敌人：制造危险区，压缩安全空间。
- 防御/辅助敌人：保护后排、增益或改变优先击杀顺序。

### 11.2 组合原则

每场遭遇最多突出两个主要问题。例如“盾兵 + 弓手”考验突破前排，“冲锋 + 地面危险”考验 Y 轴预判。不要用五种机制同时制造不可读混乱。

### 11.3 精英

精英不是普通怪数值放大版。每种精英至少增加：

- 一个改变站位的主动机制；
- 一个可被玩家识别并反制的窗口；
- 一个与房间空间联动的特性。

Vertical Slice 建议 1～2 种精英，复用基础骨架但新增行为阶段。

### 11.4 Boss

首个 Boss 建议三阶段：

1. 教学阶段：前排压迫 + 明确横向攻击。
2. 组合阶段：加入上下方向区域压制或召唤。
3. 检验阶段：更短安全窗口，要求玩家利用 Build 爆发。

Boss 不应只检验单体 DPS，也要检验生存、目标切换和危险区处理。首版只做 1 个高完成度 Boss。

## 12. 房间结构与遭遇节奏

### 12.1 房间内部阶段

一个 DungeonNode 对应一个实际房间，但房间内部可包含：

入口缓冲 → 小规模接敌 → 地形/机关 → 主战或精英 → 奖励缓冲 → 右侧出口。

房间不必都拥有三段战斗。系统提供“阶段点”，模板选择是否使用。

### 12.2 房间模板族

1. 横向狭长：强调推进和远近阵型。
2. 宽阔战区：保留充足 Y 轴包抄空间。
3. 掩体走廊：远程交火和侧向绕行。
4. 危险地面：压缩安全区并改变移动路线。
5. 夹击房：敌人从上下侧区进入，但出口仍在右侧。
6. 追逐房：软性迫使玩家持续向右。
7. 防守/护送事件房：短时改变推进目标。

### 12.3 避免“一屏锁门清怪”

- 只有主战区允许硬锁；接敌段和收尾段使用软锁或目标门槛。
- 远处敌人不在入口即全部激活，按阶段或镜头触发。
- 奖励不总在原地弹窗，可放置于右侧收尾区。
- 部分普通房允许边战边推进；精英/Boss 才频繁使用完整镜头锁定。
- 统计“进入到首次前进”“静止战斗时长”“镜头水平位移”，作为原型验收数据。

### 12.4 生成安全规则

- 先生成纯数据 RoomPlan，再一次性绘制。
- 障碍候选在临时集合中完成可达性与评分验证后提交。
- SpawnCells 必须满足以玩家尺寸计的通行、距门和无墙净空。
- 敌人、奖励、装饰从最终 SpawnCells 取点，再做 NonAlloc 物理检查。
- 所有模板必须保证入口到出口存在玩家碰撞体口径的路径。

## 13. DAG 地图

### 13.1 数据职责

DungeonNode 至少保存：

- NodeId
- NodeType
- LayerIndex
- MapPosition
- PreviousNodeIds
- NextNodeIds
- Generated
- Discovered
- Visited
- Completed
- RewardSeed / EncounterSeed
- RoomTemplateTag

Active 属于当前运行时上下文，不应作为持久节点 GameObject 的激活状态替代逻辑真值。

### 13.2 生成约束

- 节点按 LayerIndex 从左向右排列，边只能指向更大的层级。
- 起点唯一，Boss 为唯一汇点。
- 每个非 Boss 节点至少有一条到 Boss 的路径。
- 每层建议 2～4 个节点；首尾层可更少。
- 相邻层允许分叉与汇聚，禁止交叉边过多影响可读性。
- 不连续出现三个同类功能节点。
- 首层不出现精英；Boss 前 1～2 层至少可达一个恢复或商店。
- 高收益路径应付出生命、金币、未知事件或更强战斗中的至少一种成本。
- 同一 Seed 必须生成同一图、节点类型和奖励入口。

### 13.3 Vertical Slice 建议图规模

- 8～10 个可选择层级 + Boss。
- 每层 2～3 个候选节点。
- 一局实际访问 9～11 个节点。
- 至少出现两次真实分叉和一次汇聚。

### 13.4 节点基础权重

以下只用于首轮调参，生成器还需应用层级与邻接约束：

| 节点 | 初始权重 |
|---|---:|
| 普通战斗 | 48% |
| 精英 | 12% |
| 奖励/宝箱 | 10% |
| 商店 | 10% |
| 事件 | 10% |
| 恢复 | 10% |

Boss 固定，不参与权重。前两层提高普通战斗权重，Boss 前层提高恢复/商店可达性。

### 13.5 【待定项 T-02】地图揭示方式

| 方案 | 优点 | 缺点 | 成本 | 体验 |
|---|---|---|---|---|
| A. 全结构与类型公开 | 战略清晰，路线决策最强 | 惊喜较少，可能形成固定最优路线 | 低 | 规划型 |
| B. 连接公开、部分类型隐藏 | 保留规划骨架与探索 | 需要清晰的未知节点规则 | 中 | 平衡 |
| C. 只显示附近节点 | 神秘感强 | DAG 长期规划价值下降，选择可能像盲猜 | 中 | 探索型 |

**推荐 B 的渐进公开版本**：全图连接可见；当前层及未来两层显示类型；Boss、固定商店/休息可作为地标提前公开；更深节点显示轮廓。它最符合“路线选择 + Build 构筑”，又保留适度未知。

## 14. 节点与房间运行时分离

### 14.1 五种状态

| 状态 | 含义 |
|---|---|
| Generated | 逻辑数据、种子与模板选择已确定 |
| Active | 当前房间运行时正在执行 |
| Discovered | 地图 UI 允许显示该节点信息 |
| Visited | 玩家已进入 |
| Completed | 节点目标已完成并可选择后续 |

状态不可互相替代。地图显示不能通过“对应 GameObject 是否 Active”推断。

### 14.2 加载流程

选中节点 → 校验可达性 → 标记 Visited → RoomManager 根据节点种子生成/加载房间 → 绑定 RoomBounds 与节点目标 → Active → 完成目标 → 写回奖励和 Completed → 卸载运行时房间 → 返回路线选择。

### 14.3 【待定项 T-03】房间装载策略

| 方案 | 优点 | 缺点 | 成本 |
|---|---|---|---|
| A. 整层所有房间预建 | 切换快 | 内存高，浪费未选择路线内容 | 中 |
| B. 选中后生成，离开后卸载 | 数据清晰，最符合 DAG | 切换需加载遮罩，恢复房间较难 | 低～中 |
| C. 模板池 + 运行时复用 | 性能稳定 | 生命周期复杂，容易残留状态 | 高 |

**推荐 Vertical Slice 使用 B。** 本作原则上不可返回，无需为未访问房间维持 GameObject。正式版出现跨节点回访玩法后再评估 C。

## 15. 镜头

### 15.1 首版规则

- 平滑跟随玩家。
- 最终位置限制在当前 RoomBounds。
- 房间宽度大于一屏时，镜头随玩家向右移动。
- 切换节点时先短暂 Transition，再替换 Bounds 和出生点。
- 主战区可临时锁定更小边界，完成后解除。

### 15.2 后续能力

Boss 登场、Boss 锁镜、命中震屏、特殊事件镜头、击杀慢动作均由独立表现服务提供，不把逻辑写进 CameraFollow。

### 15.3 验收

- 任意房间边缘看不到地图外。
- 改变 Bounds 后无瞬间跳动或露黑边。
- 震屏不会突破视觉安全边界。
- 角色位于屏幕中心偏左区域时，右侧前进视野略多于左侧。

## 16. 奖励、商店与经济

### 16.1 货币

- 局内金币：用于商店、重掷和部分事件，死亡/通关后清空。
- 永久货币：用于内容解锁，不直接提供大幅永久攻击/生命成长。

### 16.2 奖励节奏

- 普通战斗：金币 + 小概率消耗品，不必每场弹三选一。
- 每 2～3 个战斗节点提供一次主要 Build 选择。
- 精英：高品质遗物或三选一。
- 宝箱：明确的免费收益，但路线本身占用一个节点。
- Boss：阶段性高品质奖励和通关结算。

这样避免每个房间都暂停选择，保持横向推进节奏。

### 16.3 商店

Vertical Slice 商店建议 5 个槽：

- 1 个当前职业武器；
- 2 个遗物/强化；
- 1 个恢复；
- 1 个重掷或随机槽。

价格应让玩家通常只能买 1～2 件，形成真实取舍。

### 16.4 事件

事件必须至少包含两个有信息差或机会成本的选择。首批事件优先复用现有系统：生命换遗物、金币赌品质、移除负面、下一战增益换风险。Vertical Slice 只做 4～6 个事件。

---

## 17. 生命、恢复、死亡与通关

- 房间间不自动回满。
- 普通战斗掉落恢复必须受控，避免路线中的恢复节点失去意义。
- 恢复房可提供“治疗 / 升级技能 / 清除负面”二选一。
- 死亡结束当前 Run，展示路线、Build、关键伤害来源和解锁进度。
- 通关展示 Build 标签、Boss 用时、选择路线和新增解锁。
- 首版不加入中途复活；降低挫败通过前期难度和永久内容解锁解决。

---

## 18. 局外成长、难度与重复游玩

### 18.1 局外成长

以内容解锁为主：

- 新武器、遗物、事件、职业；
- 新敌人、区域、Boss；
- 新难度规则和 Build 可能性。

少量便利升级可存在，但不让老玩家仅靠永久数值碾压。

### 18.2 难度

Vertical Slice 只提供标准难度。正式版使用逐级“契约/威胁”规则，例如更强精英词缀、更少恢复、Boss 新招式，而非仅增加生命倍率。

### 18.3 重复游玩来源

DAG 路线、房间模板组合、敌人组合、职业 Build、事件选择、解锁池变化和难度规则共同提供重玩性。Seed 只用于复现和测试，不默认允许玩家反复刷同一奖励。

## 19. UI / UX

### 19.1 HUD

首版保留：

- 生命/护甲；
- 职业资源（狼人兽性）；
- 技能和闪避冷却；
- 金币；
- 当前武器与关键状态；
- 当前房间目标。

不在 HUD 同时展示所有遗物文字，提供暂停页查看 Build。

### 19.2 大地图

- 节点类型、连接、当前节点、已完成路径和可选后续。
- 不可达分支明确变暗。
- 选择前显示节点类型与已知奖励级别；未知信息使用统一问号语义。
- 确认节点后不可反悔，需二次确认只用于高风险/退出式选择，避免每步多一次点击。

### 19.3 小地图

小地图只显示当前节点、已完成路径与下一层可选节点；房间内部不需要传统方格迷宫小地图。长房可用轻量水平进度条代替复杂平面图。

## 20. 音效与战斗反馈

- 关键动作各有唯一高辨识音色：攻击、命中、受击、闪避、兽化、奖励。
- 同帧多目标命中限制音效并发，避免爆音。
- 敌人强攻击必须有视觉和声音双预警。
- UI 选择、路线锁定和节点完成形成一致的听觉闭环。
- 音频事件通过 AudioManager 或后续封装服务触发，玩法数据只保存事件 ID。

## 21. 基础数值框架

以下为灰盒起点，不是最终平衡：

| 项目 | 初始目标 |
|---|---|
| 普通战斗时长 | 35～70 秒 |
| 精英战时长 | 90～150 秒 |
| Boss 战时长 | 4～7 分钟 |
| 普通敌人承受普攻次数 | 3～7 次 |
| 玩家承受同层普通重击次数 | 5～8 次 |
| 单次主要奖励体感提升 | 约 8%～20% 或规则变化 |
| 每局主要 Build 选择 | 6～10 次 |

建议伤害管线：

最终伤害 = 基础攻击 × 动作倍率 × 加法增益组 × 独立乘区 × 暴击 × 目标状态修正 × 防御结算。

规则：

- 同类小增益进入加法组，防止乘区无限膨胀。
- 规则改变型遗物尽量不用纯倍率。
- 真伤、处决、百分比伤害设置 Boss 上限。
- 所有公式由纯 C# 计算服务测试，UI 只显示结果。

## 22. Unity 落地架构

### 22.1 推荐模块

1. **Bootstrap / GameFlow**：持久服务、场景流、Run 生命周期。
2. **DungeonGraph**：纯 C# DAG 数据、生成、可达校验、Seed。
3. **RoomRuntime**：RoomPlan、生成、阶段、边界、加载/卸载。
4. **Combat**：输入意图、攻击状态、Hitbox、伤害、状态效果、敌人行为。
5. **Build / Economy**：职业、武器、遗物、奖励池、商店和 Run 状态。
6. **Presentation / UI**：Animator、特效、音频、镜头、HUD 与地图。

不新增“万能 Manager”。跨模块依赖指向稳定接口或事件。

### 22.2 场景与启动

- 一个 Bootstrap 入口负责初始化持久服务并防止重复实例。
- 职业角色选择场景只写入 Run 配置。
- 实际地牢使用一个运行壳场景；房间模板按选择生成或附加加载。
- GameFlow 拥有流程状态，具体 UI 和房间对象不负责跳场景。
- 初始化失败应明确报错，不能静默出现半初始化玩家。

### 22.3 数据归属

| 数据 | 归属 |
|---|---|
| 职业、武器、遗物、敌人、房间模板静态配置 | ScriptableObject |
| DungeonGraph、RunBuild、奖励种子、节点状态 | 纯 C# 运行时数据，可序列化 |
| 房间碰撞、出生点、Bounds、表现引用 | Scene/Prefab |
| 攻击状态、当前房间活动对象 | 运行时组件 |
| 存档 | 版本化 DTO，不直接序列化 MonoBehaviour |

### 22.4 通信规则

- MonoBehaviour 尽量薄，只处理 Unity 生命周期和表现绑定。
- 生成、数值、路线可达性使用纯 C#，可在 EditMode 测试。
- 高频同对象通信使用缓存引用；跨模块低频通知使用显式事件。
- 事件订阅和退订必须配对。
- 不用全局 Find 驱动每帧逻辑。

### 22.5 性能热区

- 敌人感知、攻击判定与生成检测使用 NonAlloc 查询和静态/复用缓冲。
- 不在 Update 中创建 LINQ 集合、字符串或反复 GetComponent。
- 只激活当前房间敌人与特效。
- Sprite/AnimationClip 按职业和当前武器加载，避免整库常驻。

### 22.6 Animator 方案

- 后续序列帧统一使用 Unity Animation Clip + Animator。
- 每职业一个基础 Animator Controller；同武器模组通过 Animator Override Controller 替换 Clip。
- 参数保持少量稳定：MoveX、MoveY、Speed、AttackIndex、IsAttacking、IsDodging、IsTransformed、IsDead。
- 攻击有效帧用 Animation Event 或 StateMachineBehaviour 调用统一 Hitbox 窗口接口；事件只发“开/关判定”，不计算伤害。
- FrameAnimator 停止扩建，迁移完成后再删除；在此之前作为旧场景兼容层。

### 22.7 现在做 / 暂不做

现在做：DAG 纯数据、狼人灰盒战斗、横向房间、Bounds 相机、Animator 单模组、奖励闭环。  
暂不做：通用技能可视化编辑器、复杂对象池框架、多区域流式世界、全职业 Animator、联机同步。

## 23. 主要风险与缓解

| 风险 | 表现 | 缓解 |
|---|---|---|
| 横向特色退化 | 每房都站桩锁门清怪 | 房间推进验收指标、分段激活、长房模板 |
| DAG 只是装饰 | 总选收益最高路线 | 生命、金币、Build 需求和未知信息形成代价 |
| 一体化 Sprite 爆量 | 每把武器重画全动作 | 共享模组、Override Controller、限制首发数量 |
| 方向与动画冲突 | Y 轴自由但攻击难对线 | T-01 先做 A/B 对照原型 |
| 敌人 AI 成本失控 | 每怪独立复杂逻辑 | 复用职能骨架，以组合创造差异 |
| 奖励随机无法成型 | Build 标签断裂 | 职业池、标签加权、有限重掷 |
| 动画事件脆弱 | Clip 替换后漏判定 | 导入验证、标准事件名、无事件时失败保护 |
| 旧系统迁移牵连 | Class/Weapon/Room 强耦合 | 先建立数据边界，再逐链替换，不一次全删 |

## 24. 已定案与待定项登记

### T-01 攻击方向方案【已定案】

采用 A：仅左右攻击，移动仍八向。灰盒对照于 v1.2.1 完成并经用户试玩定案；
四方向实现保留为回归对照，不删除。攻击方向由 `AttackDirectionResolver` 唯一解析，
预览、踏步与 Hitbox 同源消费。

### T-04 职业选择与角色选择关系【已定案】

采用“职业就是角色”的合并方案。狼人、法师、弓箭手分别是独立的职业角色；一次选择同时决定外观、属性、武器限制、技能、职业资源、动画和专属构筑池。选择界面、RunState 和存档只保存一个 PlayableCharacterId。

正式版若增加皮肤，皮肤作为职业角色下的纯表现变体，不产生新属性、技能或奖励池，防止重新形成两套交叉选择系统。

### T-05 武器视觉替换粒度

- A：每把武器替换完整动画集。辨识度高，资源最贵。
- B：每个武器类型共享主体帧，只换色与特效。最省资源，差异较弱。
- C：普通/精良走 B，传奇走 A。资源集中在高价值内容。

**推荐 C。**

### T-06 当前房间内能否向左回走

- A：只要未离开当前房间即可自由回走。
- B：越过阶段门后永久封闭左侧。
- C：危险追逐房封闭，普通房自由回走。

**推荐 C。** 普通房保留俯视移动自由；特殊房通过规则强化推进，不让全局显得僵硬。

### T-07 终极/兽化按键

- A：全职业 Q 为终极，狼人 Q 兽化。
- B：狼人保留 T，其他职业 Q。
- C：Q 为职业技能，T 为形态技能。

**推荐 A。** 统一输入与 HUD，降低教学和手柄映射成本。

### T-08 保存粒度

- A：只保存局外，退出当前 Run 视为失败。
- B：节点完成时保存当前 Run。
- C：房间内实时存档。

**推荐 Vertical Slice 使用 B。** 只在节点边界保存，兼顾单局时长与实现可靠性；房间内不保存瞬时对象。

### T-09 单局目标时长

- A：20～30 分钟。重开压力小，但完整 Build 与 DAG 路线层次较浅。
- B：30～40 分钟。能形成 6～10 次主要构筑选择，内容成本与疲劳较平衡。
- C：45～60 分钟。Build 和路线更完整，但失败挫败、节点存档与内容重复风险更高。

**推荐 Vertical Slice 使用 B。** 正式版在完成率和中途退出数据稳定后，再决定是否向 C 扩展。

## 25. 阶段规划

### 25.1 【MVP / 首个可玩版本】

目标：验证“二维战斗 + 横向推进 + 基础奖励”是否好玩。

范围：

- 狼人 1 个职业、1 套灰盒视觉。
- 1 种武器模组、1 把基础武器。
- 普攻、闪避、兽性/兽化的最小闭环。
- 2 种普通敌人。
- 3 个横向房间模板：标准、宽阔、掩体。
- 4～5 节点固定小 DAG，仅普通战斗、奖励、Boss 占位。
- Bounds 镜头与节点切换。
- 5～8 个测试强化。
- 基础死亡/重开。

优先级：攻击手感 P0；空间/镜头 P0；房间循环 P0；DAG 可选路线 P1；UI 美化 P2。

不应该制作：

- 法师、弓箭手；
- 商店完整经济、事件库；
- 随机词条生成器；
- 多区域、多 Boss；
- 局外天赋树；
- 最终美术与全量音频。

退出条件：

- A/B 攻击方向原型完成并定案。
- 三种房间都能形成不同移动轨迹。
- 玩家可完成一条不可返回的路线并打败 Boss 占位。

### 25.2 【Vertical Slice / 垂直切片】

目标：从职业角色选择到 Boss 结算形成可公开试玩的完整小型体验。

范围：

- 狼人 1 个完整职业。
- 1 种武器类型、3～5 把效果明显不同的武器。
- 1 套完整基础攻击、闪避、职业技能、兽化、武器技能。
- 10～20 个遗物/局内强化。
- 3～5 种普通敌人、1～2 种精英、1 个完整 Boss。
- 普通、精英、奖励、商店、事件、恢复、Boss 节点。
- 1 套 8～10 层 DAG，含分叉与汇聚。
- 6～10 个可复用横向房间模板。
- 完整 Follow + Bounds + Transition。
- 大地图、轻量小地图/HUD。
- 基础经济、奖励、死亡/通关结算。
- 4～6 个事件和少量内容解锁。
- 节点边界存档。

不应该制作：

- 第二、第三职业；
- 第二游戏区域；
- 大量传奇武器；
- 复杂装备打造/洗词条；
- 多结局剧情；
- 高阶难度阶梯；
- 联机与排行榜。

退出条件：

- 30～40 分钟完整 Run 可重复完成。
- 至少三种狼人 Build 能通过受控奖励形成。
- DAG 选择会因生命、金币或 Build 状态发生变化。
- 至少半数战斗房不是“一屏锁门清怪”。

### 25.3 【正式版本】

在前两阶段数据确认核心成立后扩展：

- 狼人、法师、弓箭手 3 个职业。
- 每职业 1～2 种武器类型、每类型 6～10 把武器。
- 每职业 20～30 件专属遗物，20～30 件通用遗物。
- 2～3 个区域，每区 6～10 种普通敌人、2～3 种精英、1～2 个 Boss。
- 完整事件、商店、解锁和难度契约。
- 辅助设置、手柄、数据统计与存档迁移。

正式版仍不默认承诺：联机、无限模式、地图编辑器、UGC、程序生成动画、大型剧情分支。它们必须另立验证版本。

## 26. 现有项目迁移方案

### 26.1 保留的资产与经验

- 现有伤害管线、命中反馈、音频、死亡结算可作为迁移参考。
- 现有 RoomPlan、Seed、SpawnCells、玩家口径可达性原则继续使用。
- 现有狼人素材和变身逻辑可拆分复用，但狼人从“战士外观/附加变身”升级为完整职业。
- Trigger、NonAlloc、Prefab/YAML、Respawn 重置等工程红线继续有效。

### 26.2 退役或替换

- Warrior/战士职业数据、专属选择入口与文档退役。
- 四方向网格房间连接生成器替换为 DAG 路线 + 单个横向房间运行时。
- 独立 WeaponPivot 武器视觉停止扩建；判定层不随视觉一起删除。
- FrameAnimator 主链迁移至 Animation/Animator。
- 旧 Class 与独立 Character 选择合并为 PlayableCharacterDefinition；选择界面、RunState、存档与奖励过滤只消费一个 PlayableCharacterId。
- 旧存档格式在 v1.2 引入 SchemaVersion；不保证旧 Run 存档兼容，局外解锁尽量迁移。

### 26.3 安全迁移顺序

1. 锁定 T-01 攻击方向。
2. 建立 PlayableCharacterDefinition、RunState 和 AttackDefinition 新数据边界。
3. 用新 Animator 完成狼人单武器灰盒。
4. 建立横向 RoomPlan 与 Bounds 镜头。
5. 建立纯 C# DungeonGraph 与地图 UI。
6. 串联节点选择、房间加载、完成写回。
7. 迁移奖励、商店、Build。
8. 最后移除旧场景引用与兼容代码。

任何阶段都保持一个可运行入口，不一次性删除全部旧链路。

## 28. 验收与测试

### 28.1 自动测试

- 同 Seed 生成相同 DAG。
- 图无环、Boss 可达、所有节点存在到 Boss 的路径。
- 节点状态转换合法。
- 入口到出口按玩家碰撞体口径可达。
- AttackDefinition 伤害公式与状态叠层。
- 奖励池不生成职业不可用武器。
- Save SchemaVersion 与节点边界恢复。

### 28.2 人工体验测试

- 5 分钟内能否理解向右推进目标。
- Y 轴移动是否真正解决攻击，而非只用于绕路。
- 路线选择是否会随当前生命/金币/Build 改变。
- 玩家能否描述本局 Build。
- 房间之间是否存在节奏差异。
- Boss 是否检验构筑而非只检验基础操作。

### 28.3 关键观测指标

- 房间平均完成时长。
- 镜头水平移动距离。
- 玩家在 X/Y 轴的移动占比。
- 各节点选择率与跳过率。
- Build 标签成型率。
- 死亡来源与阶段。
- 奖励界面停留时间。
