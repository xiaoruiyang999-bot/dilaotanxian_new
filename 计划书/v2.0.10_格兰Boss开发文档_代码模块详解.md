代码层面不需要先制作一个很庞大的 Boss 框架。针对目前这版“双阶段格兰”，建议完成下面 7 个核心功能模块。

## 一、Boss 总状态机

需要有一个专门控制格兰的 Boss 行为状态机，不能只靠现有随机攻击池。

建议状态：

```text
Idle
Approach
BasicCombo
Retreat
TripleLeap
PhaseWarning
FourHitCombo
PhaseTransition
QuadrupedChase
ChargeAttack
MoonHunt
Stunned
Dead
```

它需要负责：

- 当前是一阶段还是二阶段。
- 当前动作是否可以被打断。
- 一个动作结束后进入什么动作。
- 普攻、特殊招式之间的间隔。
- 禁止同时启动两个攻击。
- 受控、死亡、阶段转换时取消旧动作和旧预警。
- 格兰眩晕期间禁止移动、转向和攻击。
- 同一招不能连续无限释放。

现有 `BossPhaseController` 可以继续负责监听生命变化，但需要从“更换攻击池”升级为向 Boss 状态机发送阶段转换命令。

## 二、一阶段普通攻击循环

### 1. 右爪—左爪—后退

需要实现固定顺序：

```text
接近攻击距离
→ 右爪前摇
→ 右爪判定
→ 间隔约 1 秒
→ 左爪前摇
→ 左爪判定
→ 收招
→ 后退一定距离
→ 重新选择行为
```

功能要求：

- 右爪和左爪使用独立攻击定义。
- 每一爪都有独立的前摇、有效帧和后摇。
- 第一爪结束后才能开始第二爪。
- 第二爪允许有限角度转向，不能瞬间转身追踪玩家。
- 两爪结束后，格兰主动向玩家反方向后退。
- 后退过程中不能攻击。
- 被打断时必须清理攻击判定。
- 已经命中过的目标不能在同一爪中重复受伤。

建议把连击顺序交给 `GrandBossBrain`，每一爪的预警、Hitbox、伤害和时序仍读取 `AttackDefinition`。

## 三、一阶段“三重跃击”

这是代码量最大的招式，需要单独的招式执行器。

### 1. 单次跃击流程

```text
起跳前摇
→ 记录玩家当前位置
→ 生成落点预警
→ 锁定落点
→ 格兰进入空中状态
→ 移动至落点
→ 落地中心判定
→ 生成外围震荡波
→ 等待下一跳
```

需要的功能：

- 起跳时记录目标位置。
- 预警锁定后不再追踪玩家。
- 空中阶段关闭格兰的普通移动和普通攻击。
- 明确空中时是否可以受到伤害。
- 落地时分别结算：

  - 中心坠落判定；
  - 外围震荡判定。

- 每次落地记录是否命中玩家。
- 连续执行三次，每次之间间隔约 2 秒。
- 中途死亡或阶段变化时安全停止整套动作。

### 2. 三次结束后的条件分支

Boss 需要保存一个布尔值：

```csharp
bool tripleLeapHitPlayer;
```

处理逻辑：

```text
任意一次跃击命中玩家
→ 第三次落地
→ 转入右爪—左爪连击

三次全部没有命中
→ 第三次落地
→ 进入眩晕
→ 持续 6～7 秒
→ 恢复后回到普通循环
```

这里必须判断“坠落中心是否命中玩家”，不能把震荡波擦到玩家也算作跃击命中，除非你明确想让外围震荡也触发追击。

## 四、临界狼嚎与阶段转换

假设二阶段在 50% 生命触发，那么临界狼嚎大约在 55% 生命触发。

建议单独保存两个状态：

```csharp
bool phaseWarningTriggered;
bool phaseTwoEntered;
```

### 临界狼嚎需要完成

- 只触发一次。
- 中断当前普通行为。
- 如果正在三重跃击，建议等本次跃击整套结束后再触发，避免空中强制切换。
- 狼嚎期间暂时禁止普通攻击。
- 添加短时间抗性：

  - 降低受到的硬控时间；
  - 或暂时免疫新的硬控；
  - 不建议直接进入完全无敌。

- 狼嚎结束后：

  - 三重跃击永久退出一阶段招式池；
  - 双爪连击替换为四段连击；
  - 接近玩家的等待时间缩短；
  - 不再执行两爪后的主动后退。

### 四段攻击流程

```text
右爪横扫
→ 左爪横扫
→ 右爪上挑
→ 双爪下砸
→ 收招
→ 继续接近玩家
```

四段分别使用独立攻击定义，不能只把一个 Hitbox 连续开关四次，否则攻击方向、范围和预警会难以区分。

### 正式进入二阶段

生命达到二阶段阈值后：

- 停止一阶段行为。
- 清理现有攻击判定和预警。
- 进入阶段转换状态。
- 切换成四足移动参数。
- 切换碰撞体尺寸或偏移，但不能在玩家体内直接扩大碰撞体。
- 切换二阶段行为与招式列表。
- 重置当前连击序号和攻击冷却。
- 阶段转换完成后再允许二阶段行动。

## 五、二阶段四足移动系统

二阶段不能只是把一阶段移速调快，需要有不同的移动逻辑。

需要实现：

- 四足追踪移动。
- 围绕玩家侧向移动。
- 主动拉开距离，为奔袭准备起跑空间。
- 转向速度限制，不能原地瞬间掉头。
- 根据玩家、石柱和房间边界选择合法起跑位置。
- 接近玩家时不自动触发站立爪击。
- 不满足招式条件时，只做侧跳、绕行和拉距。
- 移动时跳过 Trigger，只让实体墙、石柱和房间边界阻挡。

建议二阶段行为循环：

```text
调整位置
→ 检查奔袭条件
→ 检查围猎条件
→ 选择一种招式
→ 执行
→ 恢复
→ 重新调整位置
```

## 六、二阶段两个招式

### 招式一：裂柱奔袭

现有 `AttackData.IsCharge` 可以复用基础冲锋位移，但当前通用冲锋还不足以完成整招，需要增加 Boss 专属逻辑。

必须支持：

- 蓄力阶段持续朝向玩家。
- 锁定时保存固定方向。
- 锁定后不再追踪玩家。
- 沿直线高速移动。
- 冲锋期间开启身体攻击判定。
- 检测撞到：

  - 玩家；
  - 完整石柱；
  - 开裂石柱；
  - 碎石带；
  - 外墙。

- 根据撞击对象进入不同收招状态。
- 最多连续奔袭三次。
- 撞到玩家或石柱后立即结束连续奔袭。
- 每次重新奔袭必须重新显示预警，不能暗中锁定下一次方向。

建议结果枚举：

```csharp
public enum ChargeEndReason
{
    Missed,
    HitPlayer,
    HitIntactPillar,
    HitCrackedPillar,
    HitWall,
    Interrupted
}
```

状态结果：

- `HitPlayer`：停止连冲，进入短恢复。
- `HitIntactPillar`：石柱开裂，格兰短失衡。
- `HitCrackedPillar`：石柱倒塌，格兰长眩晕。
- `HitWall`：短恢复。
- `Missed`：如果未满三次，重新锁定；第三次后进入喘息。
- `Interrupted`：清理判定并返回安全状态。

### 招式二：残月围猎

这个招式需要“路径记录 + 延迟危险区”。

流程：

```text
选择绕场方向
→ 生成合法绕场路径
→ 格兰沿路径奔跑
→ 按固定距离留下月痕
→ 中途选择扑击起点
→ 锁定玩家
→ 侧向扑击
→ 月痕依生成顺序爆发
→ 恢复
```

必须支持：

- 顺时针或逆时针绕行选择。
- 路径必须处于房间可走区域内。
- 月痕按距离生成，不能每帧生成一个。
- 对月痕数量设置上限。
- 每块月痕保存：

  - 生成序号；
  - 位置；
  - 预警时间；
  - 爆发时间；
  - 是否被石柱截断。

- 月痕按照顺序逐个激活。
- 站立石柱可以中断后续月痕生成。
- 碎石带降低格兰的奔跑速度。
- 扑击方向锁定后不追踪玩家。
- 月痕全部结束后回收对象，不残留判定。

建议使用对象池管理月痕，避免每次围猎都频繁实例化和销毁大量对象。

## 七、石柱和碎石状态

如果要保留地形联动，代码必须有一个独立的场地状态系统。

### 石柱状态

```csharp
public enum PillarState
{
    Intact,
    Cracked,
    Collapsed
}
```

每根柱需要支持：

- 查询当前状态。
- 接收 Boss 撞击。
- 完整变开裂。
- 开裂变倒塌。
- 倒塌后关闭高柱碰撞。
- 开启对应碎石区。
- 通知 Boss 招式和月痕系统状态已改变。
- Boss 战重开时恢复完整状态。

不要直接复用现在“受到几刀就销毁”的 `ObstacleHealth` 作为石柱真值，因为玩家不应该通过普通攻击拆柱。石柱应使用 Boss 撞击命令改变状态。

### 碎石区

碎石区需要：

- 对玩家：决定是否减速；如果不想惩罚玩家，可以只影响 Boss。
- 对格兰：降低奔袭或四足移动速度。
- 对震荡波/月痕：提供明确的阻挡或非阻挡规则。
- 使用独立 Layer，避免同时被当作实体墙。

## 八、预警系统

至少需要支持三种预警：

1. **圆形落点预警**：三重跃击。
2. **直线锁定预警**：裂柱奔袭和二阶段扑击。
3. **序列地面预警**：残月围猎的月痕。

关键规则：

- 预警和实际攻击读取同一份攻击数据。
- 预警锁定时的位置就是实际落点。
- 预警结束后再开启伤害判定。
- 动画只负责表现，不作为伤害唯一计时来源。
- 攻击取消、Boss 死亡或阶段转换时，立即清除相关预警。

现有 `AttackIndicator` 可以复用圆形和直线基础形状，但三重跃击锁定落点、连续预警和月痕队列需要扩展。

## 九、建议的数据配置

静态参数放在 ScriptableObject，不写死在 Boss 脚本中。Unity 官方也把 ScriptableObject 定位为独立于 GameObject 的共享数据容器。[Unity ScriptableObject 文档](https://docs.unity3d.com/6000.1/Documentation/Manual/class-ScriptableObject.html)

建议数据分为：

### 单次攻击定义

- 前摇时间。
- 有效时间。
- 恢复时间。
- 攻击范围与形状。
- 转向限制。
- 预警类型。
- 是否锁定落点。
- 是否属于重型地形攻击。

### 招式流程配置

- 跃击次数。
- 跃击间隔。
- 全部落空后的眩晕时间。
- 普攻连击顺序。
- 奔袭最大次数。
- 月痕间距、数量和爆发间隔。

### 阶段配置

- 临界狼嚎阈值。
- 二阶段阈值。
- 抗性持续时间。
- 一、二阶段移动参数。
- 各阶段允许的招式。

运行时状态不要写回 ScriptableObject。

## 十、推荐代码模块

不需要为每一爪创建一个大型 MonoBehaviour。建议控制在这些模块内：

| 模块 | 职责 |
|---|---|
| `GrandBossBrain` | 总状态、阶段、动作选择、动作切换 |
| `GrandBasicCombo` | 两段与四段爪击流程 |
| `GrandTripleLeap` | 三重跃击、命中记录和眩晕分支 |
| `GrandChargeAttack` | 二阶段连续奔袭和撞击结果 |
| `GrandMoonHunt` | 绕场路径、扑击和月痕序列 |
| `BossArenaState` | 四根石柱与碎石状态 |
| `BossTelegraphController` | 圆形、直线与月痕预警 |
| `BossPhaseController` | 监听生命阈值并发送狼嚎/二阶段命令 |

其中 `GrandBossBrain` 是唯一允许启动招式的对象。其他模块只执行命令并报告“完成、命中、撞柱、被中断”等结果，避免多个脚本同时争夺 Boss。

## 十一、实现顺序

建议严格按这个顺序做：

1. Boss 总状态机。
2. 右爪—左爪—后退。
3. 四段临界连击。
4. 单次跃击和圆形预警。
5. 三次跃击及命中/落空分支。
6. 眩晕与恢复。
7. 临界狼嚎和阶段转换。
8. 四足移动。
9. 单次直线奔袭。
10. 连续三次奔袭与撞击结果。
11. 石柱三态和碎石区。
12. 残月围猎路径。
13. 月痕序列。
14. 全流程测试和数值调整。

不要一开始就同时制作两阶段全部内容。先让“一阶段普通攻击 + 三重跃击 + 眩晕”形成完整闭环，再进入二阶段。

完成后的代码验收标准是：

- 格兰始终只有一个行为在运行。
- 每次攻击都能分辨前摇、有效和收招。
- 三重跃击条件分支准确。
- 狼嚎和二阶段都只触发一次。
- 二阶段不会继续使用一阶段招式。
- 冲锋锁定后不追踪。
- 石柱状态能正确复位。
- Boss 死亡、重开和阶段切换不会残留 Hitbox、协程、Tween 或月痕。
- 暂时没有美术资源时，使用纯色形状也能完整玩通两阶段。
