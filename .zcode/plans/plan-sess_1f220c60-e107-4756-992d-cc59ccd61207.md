# 修复计划：致命+高危问题修复（v0.5.4.4.4）

## 背景诊断结论

你在游玩中遇到的三类症状，经全量代码审查已定位到根因：

| 症状 | 根因 |
|---|---|
| 楼层循环失效 | 场景 `v0_5_Dungeon.unity` 在 Unity 崩溃恢复时丢失了 **RunManager 组件**（HEAD 有、工作区没有，已验证）→ Boss 清房无宝箱/传送门、死亡即软锁 |
| 敌人行为异常 | `EnemyPerception.IsDirectionClear` 不跳过 Trigger → RoomTrigger/敌人探测圈挡住后撤探测射线，远程敌人被近身后站桩（v0.5.4.4.3 只修了 LOS 那一半） |
| 战斗判定怪异 | ① 投射物命中 Trigger（宝箱/补给/传送门/另一颗子弹）时无 IDamageable 仍自毁 → 子弹"打空气"消失；② 召唤物纯随机落点可嵌墙 → 房间永不清、门永锁 |

另发现：场景中 3 个 Debug_ 调试对象 + 5+ 个 DamagePopup 运行时泄漏被序列化（违反你的《开发调试规范》），且 Debug_RealPlayer 与正式 Player 实例**同时存在且都 tag=Player**。

## 修复项（按执行顺序）

### 1. 代码：`EnemyPerception.IsDirectionClear` 跳过 Trigger（EnemyPerception.cs:82-88）
在遍历 hits 时加 `if (hit.collider.isTrigger) continue;`（与 62 行 QueryLineOfSight 的 v0.5.4.4.3 修复同款，补齐另一半）。

### 2. 代码：召唤物落点合法性校验（EnemyCombat.cs:633-638 SummonMinions）
随机取点后用 `Physics2D.OverlapCircle(pos, 0.4f, ContactFilter2D{layerMask=Default|Enemy|Obstacle, useTriggers=false})` 校验（沿用 SpawnPositionHelper.cs:26-35 的既有模式），不合法则重摇角度，最多 8 次；全失败则跳过该只不生成——宁可少一只，不可卡死清房条件。

### 3. 代码：AttackIndicator 孤儿泄漏修复（两处配合）
- **AttackIndicator.cs:249-268 RestoreParent**：拆分 `originalParent == null` 分支——`isDetached=true` 但父引用为 fake-null（父已被销毁）时 `Destroy(gameObject)` 自毁，不再常驻场景根。
- **AttackIndicator 新增 `DestroyIndicator()` 公共方法**；**EnemyCombat.cs:587 OnDisable**：仅 `attackIndicator?.Hide()` 改为判断敌人 `EnemyHealth.IsDead`（死亡停用 → 销毁指示器；未进房休眠/场景卸载 → 只 Hide，保证休眠敌人复活后指示器仍可用）。玩家的 PlayerCombat.OnDisable 路径不动（玩家对象不被销毁）。

### 4. 代码：投射物不再被 Trigger 吞掉（Projectile.cs:154-164 ResolveHit）
命中 targetLayer 但 `FindDamageableInParents` 返回 null 时：`other.isTrigger` 为真（宝箱/传送门/投射物互射）→ `return false` 穿透继续飞；非 Trigger（墙 TilemapCollider）→ 保持原销毁挡弹行为。obstacleLayer 分支不动。

### 5. 场景手术：`v0_5_Dungeon.unity`（先备份到项目根 `_backup/`，纯 YAML 编辑，保留工作区全部未提交改动）
1. **恢复 RunManager**：DungeonSystem（&1357356017）的 m_Component 列表补回 `- component: {fileID: 1357356021}`，并从 HEAD 版本原样复制 RunManager 组件块（四个字段 dungeonManager/rewardChestPrefab/portalPrefab/restartDelay 与当前 RunManager.cs 序列化字段完全一致；Chest.prefab 与 Portal.prefab 的 GUID 已验证存在）。
2. **清理调试残留**：删除 Debug_Player、Debug_RealPlayer、Debug_EnemyRanged 三个对象及其子物体/组件块；删除全部泄漏的 DamagePopup 实例块。保留正式 Player prefab 实例（PrefabInstance &2002241262，已确认 tag=Player）。
3. **引用完整性检查**：逐一 grep 被删块 fileID，确认无存活对象引用（重点：CameraFollow.target、PlayerWorldStatusBar.anchor 若指向被删对象则重接到正式 Player 实例）。`DungeonManager.player` 保持 `{fileID: 0}`，依赖已有的运行时 tag 兜底（DungeonManager.cs:63-73），避免手写 stripped 引用风险。
4. **验证**：RunManager guid 场景内出现 1 次、fileID 1357356021 出现 2 次、无悬空引用。
